## 摘要
大型语言模型（LLMs）为长时程机器人规划提供了灵活接口，但生成的规划往往无法遵守具身约束、从规划错误中恢复，或在部分可观测条件下有效推理。我们提出 GAVEL，一个围绕显式图世界模型构建的长时程 LLM 规划验证与修复框架。该图表示相关物体关系、动作前置条件和效果，以及未观测物体位置上的概率信念。该模型可在执行前预测 LLM 生成动作的后果，检测违规，并修复那些可直接从世界模型推导出修正的违规。该方法还将 LLM 重新规划仅保留给需要语义推理的错误。对于多任务指令，GAVEL 基于可能物体位置分布进行推理，以重排剩余子任务并最小化期望搜索代价。我们在 BEHAVIOR-1K 上评估 GAVEL，涵盖 100 个单一长时程任务和 500 个多任务指令。使用 Qwen3-8B 时，GAVEL 将单任务成功率从 41.2% 提升到 91.8%，多任务成功率从 19.9% 提升到 92.6%。与静态变体相比，分布信念推理还将移动距离减少约 5.4%。这些改进表明，显式图世界模型框架能够显著提高跨紧凑型和前沿托管 LLM 能力的具身长时程规划的可靠性和效率。

## Abstract
Large language models (LLMs) provide a flexible interface for long-horizon robot planning, but generated plans often fail to respect embodiment constraints, recover from planning errors, or reason effectively under partial observability. We present GAVEL, a framework for verifying and repairing long-horizon LLM planning built around an explicit graph world model. The graph represents relevant object-relations, action pre-conditions and effects, and probabilistic beliefs over unobserved object locations. This model can predict the consequences of LLM-generated actions before execution, detect violations, and repair those whose corrections follow directly from the world model. This method also reserves LLM replanning solely for errors requiring semantic reasoning. For multi-task instructions, GAVEL reasons over distributions of possible object locations to reorder remaining subtasks and minimize expected search cost. We evaluate GAVEL on BEHAVIOR-1K across 100 single long-horizon tasks and 500 multi-task instructions. With Qwen3-8B, GAVEL improves single-task success from 41.2% to 91.8% and multi-task success from 19.9% to 92.6%. Distributional belief reasoning also reduces travel distance by approximately 5.4% compared with a static variant. These improvements show that an explicit graph world model harness can substantially improve the reliability and efficiency of long-horizon embodied planning across compact and frontier hosted LLM capabilities.

## 1. 论文的核心问题与整体含义

- **核心问题**：LLM 用于长时程机器人任务规划时，生成的计划经常不可执行，主要表现为：
  - 忽略前提条件或具身约束；
  - 出现规划错误后难以可靠恢复；
  - 在部分可观测环境中不能有效进行不确定性推理。
- **现有方法的不足**：
  - 像 SayPlan 这类“验证—反馈”方法，会把每一个失败都返回给 LLM 重新规划；但很多失败其实可以直接从动作语义中推导出修正，重复调用 LLM 既昂贵又可能引入新错误。
  - 像 EPoG 这类图编辑规划方法速度快、适合空间重排，但只能表达 pick/place 类的图状态变化，无法表达“洗盘子”这类需要完整动作序列的语义目标。
- **整体含义**：论文提出 GAVEL，把场景图从被动的“验证器”升级为显式的 **图世界模型**：
  - 在执行前预测 LLM 计划的结果；
  - 直接修复那些可由动作模型推导出的失败；
  - 只把真正需要语义推理的错误交给 LLM；
  - 同时利用概率信念对多任务执行顺序进行在线优化。
- 这一思路的目标是显著提升长时程具身规划在紧凑本地模型和前沿托管模型上的可靠性与效率。

## 2. 论文提出的方法论

### 2.1 图世界模型
- 论文将环境表示为带类型的场景图：
  - 顶点：房间、任务相关物体、机器人；
  - 边关系：`near`、`under`、`room connect`、`room inside`、`object inside`、`on top`、`next to`、`holding`；
  - 一元状态：`open`、`toggled`、`cooked`、`washed`、`dried`。
- 模型区分隐藏的物理状态和机器人当前“相信”的图状态，并在后者上执行符号推理。
- 动作原语共 9 个：`NAVIGATE TO`、`GRASP`、`RELEASE`、`PLACE ONTOP`、`PLACE INSIDE`、`OPEN`、`CLOSE`、`TOGGLE ON`、`TOGGLE OFF`。
- 每个动作都有前置条件和效应：
  - 前置条件包括接近性、可操作性、手爪状态、可达性（例如目标物体不能位于关闭容器内）；
  - 效应更新图中的关系与状态；
  - 如果前置条件不满足，转移结果为无效。
- 图世界模型还额外跟踪恢复性约束：计划中打开的容器必须关闭，安全关键设备开启后必须关闭。

### 2.2 计划验证与修复
- 给定 LLM 生成的候选计划，图世界模型逐步向前推演：
  - 每一步检查动作前置条件；
  - 推演结束后检查目标是否全部满足；
  - 同时检查整条轨迹的安全约束。
- 验证器返回结构化违规信息，包括：
  - 适用性失败；
  - 未满足的目标；
  - 安全违规。
- 修复算法 `REPAIR` 的核心思想是：许多失败可直接从动作语义推导修正。
  - 例如，因为距离不足导致抓取失败，就插入 `NAVIGATE TO`；
  - 物体在关闭容器内，就先生成导航到容器，再插入 `OPEN`；
  - 安全违规则插入恢复动作。
- 修复过程会保留历史候选，用排序函数选择最佳计划，避免循环修复导致死循环。
- 如果失败无法由模型语义直接修复，则将结构化错误反馈给 LLM，要求重新规划；LLM 重新调用的次数受预算约束。

### 2.3 任务理解与信念初始化
- 对多任务指令，先分解为子任务。
- 使用轻量 LoRA 适配器（基于 Qwen3-1.7B）完成：
  - 提取任务相关物体和显式关系；
  - 提取目标状态。
- 对位置仍不确定的物体，使用 Relational Semantic Network（RSN）初始化房间位置信念：
  - 冻结文本编码器编码物体类别；
  - MLP 预测物体属于各房间类型的得分；
  - 将房间类型得分均匀分配到该类型的可达房间实例上；
  - 归一化后作为初始概率分布。

### 2.4 信念感知的多任务排序
- 对每个未定位物体，按信念概率从高到低对候选房间排序。
- 计算第 k 个房间找到物体时的搜索代价，包括：
  - 从当前位置到第一个房间的导航距离；
  - 前 k−1 个房间的完整搜索代价与房间间转移距离；
  - 第 k 个房间中预期搜索距离。
- 根据信念分布加权得到未定位物体的期望搜索代价。
- 对剩余任务，构造：
  - 每个任务作为第一个任务执行时的期望代价 h；
  - 任务两两之间的转移代价矩阵 A；
  - 整个排序的近似总代价 J。
- 由于任务数 N≤5，论文直接枚举所有排列，选择代价最小且通过验证的排序。
- 实际只执行排序中的第一个任务；执行后的观测更新信念，再对剩余任务重新优化排序，从而实现在线重规划。

### 2.5 系统流程
整体流程可概括为：
1. 分解指令，提取对象、关系、目标；
2. 用 RSN 初始化不确定物体的位置信念；
3. LLM 一次生成所有子任务的动作序列；
4. 图世界模型对每个子任务计划进行验证和修复；
5. 未解决的语义错误返回 LLM 重规划；
6. 根据当前信念选择最优任务顺序；
7. 执行第一个任务，观测并更新信念；
8. 重复直到所有任务完成。

## 3. 实验设计

### 3.1 数据集与场景
- 主要基准：**BEHAVIOR-1K**。
- 实验在符号动作层面进行，使用 2D 轻量执行器模拟 BEHAVIOR-1K 动作转移，保留原始平面图、物体属性、任务谓词和导航几何。
- 导航采用 A* 算法；搜索未观测物体采用基于前沿的探索和楔形摄像头模型。
- 验证了符号执行器与 OmniGibson 在 100 个单任务指令上的结果完全一致，说明抽象合理。
- 基准规模：
  - 单任务基准：100 个长时程任务，跨 10 个场景；参考计划平均 12.2 个动作原语，目标谓词 240 个。
  - 多任务基准：500 个指令，每个指令包含 2 到 5 个独立任务，平均 18.8 个动作原语，跨 4.66 个房间；其中 199 个需要设备操作产生语义状态。

### 3.2 评估指标
- **Success**：计划执行后是否成功完成目标；
- **Distance**：机器人实际移动距离；
- **Planning time**：包括任务分解、LLM 调用、修复和排序在内的规划时间。

### 3.3 对比方法
- `llm-only`：LLM 只生成一次计划并直接执行。
- `sayplan`：复制 SayPlan 的验证—反馈循环，失败时反馈给 LLM 最多 T 次重新规划，但不做图修复。
- `epog`：基于相信图和目标图的差异生成动作，按旅行代价排序，不使用 LLM 生成完整语义流程。
- `gavel-basic`：只使用一次 LLM 提案，之后完全依赖图修复，不进行 LLM 反馈重调用。
- `gavel-map`：把每个不确定物体固定为最可能房间，并提前固定任务顺序。
- `gavel-static`：保留完整分布，但仍然提前固定任务顺序。
- `gavel`：完整 GAVEL，保留分布并在线重排剩余任务。
- `oracle`：使用真值物体位置和参考子计划，作为代价上界参考。

### 3.4 实验组
- **实验 1**：100 个单任务，测试 Qwen3-4B 和 Qwen3-8B，比较 llm-only、sayplan、gavel-basic、gavel。
- **实验 2**：500 个多任务指令，使用 Qwen3-8B，比较 llm-only、sayplan、epog、gavel-map、gavel-static、gavel、oracle。
- **实验 3**：100 条指令子集，测试本地模型 Qwen3-4B、Qwen3-8B 和托管模型 GPT-5.6 Sol、Claude Sonnet 5，比较带 GAVEL 和不带 GAVEL 的效果。
- 另外对 RSN 信念质量、成本模型拟合优度进行了单独评估。
