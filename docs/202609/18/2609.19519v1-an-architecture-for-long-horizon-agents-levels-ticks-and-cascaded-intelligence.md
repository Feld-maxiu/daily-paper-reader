## 摘要
语言模型智能体越来越多地被要求执行持续数天或数周的工作，例如运维修复或研究项目。此类任务的持续时间超过任何上下文窗口、任何进程以及人员能够关注的时间间隔。本文认为，长时程智能体若要持续学习，首先必须能够持续运行而不遗忘。这种能力存在于模型外部的控制框架中，而非模型本身。我们从长时程设定中推导出七个瓶颈，并通过一种由三部分构成的层级架构加以解决：（i）按时间尺度索引的层级，每一层维护一个用于概括其下一层的有界文件；（ii）作为自主行动单位的时钟节拍；以及（iii）级联智能，即工作仅在审查未通过时才升级到能力更强的模型。我们报告了一场为期十天的活动，在该活动中，基于该架构构建的智能体在人类每天仅关注一次的情况下复现了一项已发表的强化学习结果，并展示：（1）该智能体在活动的每次上下文重置和会话边界之间保持了任务连贯性；（2）早期写入的操作知识在模型权重未改变的情况下改变了后续行为；以及（3）学习组件将在何处接入此类系统。总体而言，我们的经验表明，这些智能体的持续学习需要一种比所有上下文和进程都存续更久的基底，而框架已经在运行的检查环节正是学习器应当所在之处。

## Abstract
Language-model agents are increasingly asked to carry out work spanning days or weeks, such as an operations remediation or a research programme. Such a task outlives any context window, any process and any interval at which a person can attend. In this paper, we argue that a long-horizon agent must run continually without forgetting before it can learn continually. This ability lies in the harness around the model rather than in the model itself. We derive seven bottlenecks from the long-horizon setting and answer them with a hierarchical architecture of three parts: (i) levels indexed by time scale, each keeping a bounded file summarising the level below; (ii) a clocked tick as the unit of autonomous action; and (iii) cascaded intelligence, where work is escalated to a more capable model only after failing review. We report on a ten-day campaign in which an agent built on this architecture reproduced a published reinforcement-learning result with a human attending once a day, and show (1) the agent kept the thread across every context reset and session boundary of the campaign, (2) operating knowledge written early changed later behaviour with no change to model weights, and (3) where learned components would enter such a system. Overall, our experience suggests continual learning for these agents needs a substrate outliving every context and process, and the checks the harness already runs are where a learner belongs.

- **整体含义**：论文不是提出新的模型训练方法，而是提出一种架构立场：在引入可学习组件之前，必须先有一个能跨越上下文、进程和人类注意力边界的“基底”。学习器最终应嵌入框架已有的检查环节中。

## 2. 方法论

### 2.1 长时程设定与七个瓶颈

论文将智能体的工作置于两个轴上：

- **自主性（autonomy）**：智能体在无人干预下自行决策的份额。
- **时程（horizon）**：智能体完成任务所需维持的轨迹长度，可按动作数、token 或墙钟时间衡量。

在长时程设定中，以下量都远小于总时程 H：

- C：单次模型调用的上下文窗口；
- P：单个进程或会话的生命周期；
- A：人类关注间隔；
- F：任一依赖组件的故障间隔；
- B：最高能力层级的预算上限。

由此推导出七个瓶颈：

| 瓶颈 | 来源 | 含义 |
|---|---|---|
| Autonomy 自主性 | A ≪ H | 无人提示、无人决定何时继续 |
| Horizon 时程 | C ≪ H | 任何上下文都无法容纳完整轨迹 |
| State 状态 | P ≪ H | 每个进程都会先结束，状态不能只活在上下文中 |
| Delegation 委派 | 工作超过单一进程 | 需要合约、任务下发、决策上送 |
| Correctness 正确性 | 自主性 × 时程 | 错误无人检查、误差累积、压缩会隐藏证据 |
| Resilience 韧性 | F ≪ H | 每个组件在长时间内都会至少失败一次 |
| Cost 成本 | 自主性 × 时程 | 最高能力层级的支出随时程线性增长，受预算约束 |

### 2.2 四个核心抽象

- **层级（level）**：按时间尺度索引的系统层，每层维护一个有界状态，用于概括其下一层，并向其下一层发出稀疏指令。
- **节拍（tick）**：判断层中自主行动的单位，即驱动会话从读取状态到写回状态的一次完整循环。
- **协议（protocol）**：一个有名称的文件，具有指定的写入者、读取者、节奏和检查；所有信道和持久状态都是协议。
- **层级智力（tier）**：三类智能，分别是判断层（judgment）、劳动层（labor，分为 routine / strong）和确定性进程（deterministic processes）。层级越高，使用的智能能力越强。

### 2.3 时间层级结构

论文以一次实际活动为例，给出七层时间层级：

- L0：工具调用，秒级，保存原始日志、轨迹、指标；
- L1：劳动回合，分钟级，保存会话日志、每次试验进展；
- L2：指导层，30–60 分钟，保存评估与下一步试验指令；
- L3：节拍层，约 1 小时，保存有界检查点（≤8k 字符）和日志；
- L4：门审层，每 5 个 tick 一次，保存审阅备忘录和门审结论；
- L5：人类层，每天一次，保存 ≤1,500 字符的日报；
- L6：目标层，一周，保存目标、规格和预算。

向下信道传递**指令**（directives），向上信道传递**反压信息**（back-pressure），包括压缩状态、升级线、监视器标记的注意项，以及**终止判决**（kill verdicts）——终止判决是唯一不压缩跨层传递的消息，因为正是这类消息最容易被压缩隐藏。

### 2.4 七个机制族

- **自主性**：由时钟制造主动性；驱动会读取所有预先注册的规则，做出决策并执行动作，再把状态写回。人类回答被保存为“常设决策”（standing decisions），每次唤醒时读取。
- **时程**：强制要求任何日志或源代码最多读取 40 行；其余内容被委派并摘要。
- **状态**：所有状态必须落在文件里，每个数字都指向其来源文件。每次会话开始和上下文压缩后都运行恢复协议：检查点 → 常设决策 → 计划 → 未决问题 → 活动实验卡。若追加日志比检查点更新，则以日志为准。
- **委派**：工作以合约形式向下传递，以证据形式返回；决策向上传递，最终到达人类负责人。一个 brief 是一个文件，包含任务、目标、层级、可读文件、约束和返回内容。面向开放式工作时，劳动者写 `PROGRESS`，驱动写 `DIRECTIVE`。
- **正确性**：所有实验必须预注册假设、成功标准、提前停止规则、资源上限和随机种子；驱动在每个 tick 检查停止规则，终止判决成为摘要中的一个比特。只有在可比较条件下（如实际陈旧度而非请求陈旧度被测量）运行才有意义。对抗性审阅者在每个门审处阅读计划与证据。
- **韧性**：每个层级都有上一层的检测器和无需判断的恢复机制；挂起的 worker 会被重新下达 brief，失效的驱动从检查点恢复，探针作为所观察作业的步骤运行，而不是作为登录运行。
- **成本**：采用**审阅-升级（review-and-escalate）**机制：工作在可能的最低能力层级完成，由上一层审阅；失败则反馈重试；再次失败才提升一个层级，最高到人类负责人。强层级一旦找到配方，后续运行就由常规层级按配方执行。会话每几个 tick 轮换，预 tick 摘要可在无事可做时跳过唤醒。

### 2.5 无遗忘与积累

- **无遗忘**：智能体不做参数意义上的学习；所有需要的信息都存在文件中，不依赖上下文。驱动在活动中被重置数十次（压缩、轮换、看门狗），每次都能从文件恢复。
- **积累**：某一层早期写入的操作知识会改变下层后续行为，例如人类回答成为常设决策、审阅发现成为后续实验卡的规则、强层级发现的配方被写入常规 brief。论文强调这是“积累”，不是“学习”，但它标定了学习组件应插入的位置：即一个持续存在的门审环节内部。

## 3. 实验设计

- **任务场景**：复现一项已发表的异步强化学习研究结果（Hou et al., 2026）：在智能体任务中，使用陈旧 rollout 训练的策略会在陈旧度超过阈值后崩溃，而去耦的重要性采样校正能保持稳定；实验在两个模型规模上进行。
- **任务特点**：具有可验证结果、共享基础设施、固定预算、人类每天只关注一次，以及不会自我暴露的失败模式。
- **活动设计**：为期十天的活动，经历五个受门审控制的阶段：
  1. 环境启动；
  2. 小规模下“未校正 vs 校正”的稳定性对比（跨种子）；
  3. 在指导性劳动下找到大模型的单节点训练配方，并完成该规模的稳定性对比；
  4. 移植到第二个训练框架，按“实际陈旧度”而非“请求陈旧度”进行验证，并在训练硬件减半的情况下优化到与原运行相当；
  5. 在经四次门审重设计的校准环境中进行“完整方法 vs 对照”的有效性比较。
- **实验结果**：复现了发表结果：未校正策略在两个规模下均跨过陈旧度阈值后崩溃，校正策略保持稳定；完整方法在更短时间内达到校准环境的上限。
- **方法对比**：论文并未与传统基准或多种现成智能体方法进行对照，实验本质上是单一部署的存在性证明，而不是标准 benchmark。

## 6. 主要结论与发现

- **结论一：持续学习之前必须先持续运行不遗忘**。无遗忘是一种框架属性，而不是模型属性；活动的驱动被重置数十次，仍能保持任务连贯性。
- **结论二：早期写入的操作知识在模型权重不变的情况下改变了后续行为**。这就是“积累”现象，表明记录本身可以作为未来学习器的数据来源。
- **结论三：学习器应插入框架已有的检查环节**。例如，决定 brief 层级或唤醒间隔的学习策略，应替代书面规则，但保留在框架的验证检查内部。
- **结论四：记录即数据集，门审即插入点，积累而不学习是基线**。任何更新权重的方法都必须比会写文件的层级架构在多次重置后保留更多活动信息，才能证明其优势。
