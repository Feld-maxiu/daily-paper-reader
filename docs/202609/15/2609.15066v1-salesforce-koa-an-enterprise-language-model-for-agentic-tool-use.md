## 摘要
我们提出了 Salesforce Koa，一个企业语言模型，通过对开放权重的 Nemotron-3-Super-120B 基础模型使用群体相对策略优化（GRPO）进行强化学习后训练而构建。Salesforce Koa 在公开数据和合成生成的数据上进行训练，不使用客户数据，以改进工具使用和智能体能力，同时保持强大的通用性能。其独特组成部分是一个从仿真到奖励的流水线，该流水线将工作流规范扩展为以人物角色为条件的多轮任务，并为数据依赖型请求赋予基于成功工具使用的任务解决奖励。对于企业领域，这些规范用 Agent Script（Salesforce 用于构建 Agentforce 智能体的声明式语言）编写；对于公开工具使用领域，我们直接合成工作流结构。相同的仿真和基于事实的奖励机制在两者上驱动 GRPO。在公开工具使用、智能体推理和企业客户关系管理（CRM）基准测试中，Salesforce Koa 相比其开放权重基础模型有所提升，在多轮工具使用上提升最明显，并超越了一个强大的专有基线，但仍低于最强的前沿模型。这些结果表明，规范驱动的强化学习是将开放权重基础模型专门化用于企业智能体任务的一条实用途径。

## Abstract
We present Salesforce Koa, an enterprise language model built by post-training the open-weight Nemotron-3-Super-120B foundation model with reinforcement learning using Group Relative Policy Optimization (GRPO). Salesforce Koa is trained on public and synthetically generated data, with no customer data, to improve tool use and agentic capabilities while preserving strong general-purpose performance. Its distinctive component is a simulation-to-reward pipeline that expands workflow specifications into persona-conditioned multi-turn tasks with task-resolution rewards grounded in successful tool use for data-dependent requests. For enterprise domains, these specifications are written in Agent Script, Salesforce's declarative language for building Agentforce agents; for public tool-use domains, we synthesize the workflow structure directly. The same simulation and grounded-reward machinery drives GRPO across both. Across public tool-use, agentic-reasoning, and enterprise Customer Relationship Management (CRM) benchmarks, Salesforce Koa improves over its open-weight base, with the clearest gains on multi-turn tool use, and surpasses a strong proprietary baseline while remaining below the strongest frontier models. These results show that specification-driven reinforcement learning is a practical path to specializing open-weight foundation models for enterprise agentic tasks.

## 2. 方法论

### 2.1 整体训练路线

- 基础模型：开放权重的 **Nemotron-3-Super-120B**（推理模型，训练时使用 thinking mode）。
- 训练方法：直接对基础模型应用 **GRPO（Group Relative Policy Optimization）** 强化学习，而不先做 SFT checkpoint。
- 数据原则：仅使用公开数据和合成生成的数据，不使用任何客户数据。
- 目标函数：最大化期望轨迹奖励 \(J(\theta) = \mathbb{E}_{x\sim D} \mathbb{E}_{\tau\sim\pi_\theta(\cdot|x,\text{env})} [R(\tau)]\)。

### 2.2 规范驱动的环境与任务构建

- 对于企业领域，工作流结构用 **Agent Script** 编写。Agent Script 是 Salesforce 的声明式语言，用于配置 Agentforce 智能体。
- 一个规范（specification）包含：路由器、专门子智能体、类型化动作、工具范围、工作流指令等。
- 静态提取阶段将规范编译为**类型化工作流图**，其中包括：
  - 每个工具的参数 schema；
  - 声明的状态效果；
  - 路由条件；
  - 循环/终止配置。
- 对于没有 Agent Script 的公开工具使用领域，则直接合成等价的工作流结构，产生同样的工作流图。
- 模拟流水线把每个规范扩展为**场景条件和人物角色（persona）条件**的多轮会话：
  - 场景决定需要练习的工作流和用户需求；
  - 人物角色控制模拟客户的行为方式。
- RL 示例可以从最初用户请求开始，也可以从生成的对话前缀开始，以便模型学习多轮交互中不同深度的决策。
- 每个示例采用统一 schema，其中 `agent_ref` 选择环境，其余字段提供初始 rollout 上下文，例如任务意图、角色、对话状态、可用工具等。
- 多个环境联合训练时，通过 `agent_ref` 分发实现差异化暴露；必要时对环境样本进行重复后再 shuffle，以控制不同环境的训练比例。

### 2.3 在线 rollout 与基于事实的奖励

- 每个示例在 **NeMo Gym** 环境中作为在线 rollout 执行。
- 对于模拟对话环境，使用一个**冻结的辅助模型**同时扮演三种角色：
  1. 客户模拟器：根据采样角色生成下一用户轮次；
  2. 工具/函数模拟器：在无真实后端时生成工具输出；
  3. 覆盖度评判器：对任务解决程度打分并形成奖励。
- 该辅助模型是独立的推理服务，训练期间不会被更新。
- **任务意图**在建任务时被表示为编号的子问题列表。
- 覆盖度定义为：

  \[
  \text{cov} = \frac{\#\text{被判定为已解决的子问题}}{\#\text{子问题总数}} \in [0,1]
  \]

  缺失或格式错误的判定默认视为未解决。
- 最终奖励加入**重复调用门控**：

  \[
  R =
  \begin{cases}
  0, & \text{出现连续重复工具调用（名称和参数相同）} \\
  \text{cov}, & \text{否则}
  \end{cases}
  \]

- 评判器提示要求：任何需要客户或系统特定数据的子问题，只有在回答基于成功的相关工具调用时才可判为已解决；一般常识性问题可以不使用工具解决。
- 确定性工具沙箱环境不依赖覆盖度评判器，而是使用二值状态等价奖励：预测动作复现参考终态时 \(R=1\)，否则 \(R=0\)。
- 环境的关键性质：
  - 工具列表是 **per rollout** 的，不是全局的；路由环境中只暴露当前子智能体范围内的工具。
  - 人物角色在单个对话中保持固定，影响模拟用户如何反应、升级或声明问题解决。
  - 路由环境中每次子智能体切换都会追加新的 focus/procedure 系统消息，使策略在话题变化时被重新聚焦。
  - 三种环境拓扑：
    - 扁平客户支持：单一智能体，所有工具直接可用；
    - 路由客户服务：路由器加专门子智能体，通过 `go_to_*` 切换，并插入 focus 消息；
    - 确定性工具沙箱：有状态工具，无模拟客户和辅助模型，使用状态等价验证。

### 2.4 GRPO 优化细节

- 每个 prompt 由策略采样一组完整轨迹；动态采样丢弃奖励方差为零的组，并补充采样直到凑齐完整训练 batch。
- 不使用价值网络，采用 **leave-one-out 基线**：
  - \(b_i\) 是组内除轨迹 \(i\) 以外其他轨迹奖励的均值；
  - \(s_i\) 是其他轨迹奖励的标准差；
  - 优势 \(A_i = \text{clip}\left(\frac{R_i - b_i}{s_i + \epsilon}, -c, c\right)\)。
- 每个 batch 只做一次 on-policy 更新，策略比率被强制为 1，因此 clipped PPO 项和参考 KL 惩罚不生效。
- 使用 token 级截断重要性采样权重修正训练/生成 log-prob 不一致：

  \[
  w_{i,t} = \min\left(\tau, \exp[\log \pi_{\text{train}}(y_{i,t}) - \log \pi_{\text{gen}}(y_{i,t})]\right)
  \]

- 损失函数先对每条轨迹的 token 平均，再对 batch 平均，防止长失败轨迹仅因长度主导梯度。
- 有效性约束：对格式错误的工具调用或 thinking token，将对应 assistant message 的 token 优势设为固定负值；超长或 log-prob 不一致轨迹被 mask 掉。
- 另有**单步训练模式**用于“约束决策回合”：在这些回合中，智能体不能仅靠调用工具完成任务，而必须与用户沟通，例如说明限制、请求缺失信息或澄清意图。奖励由程序性门控 \(G(a_k)\) 和后续恢复回合的工具调用匹配分 \(f_{\text{match}}\) 相乘得到。
