## 摘要
语言智能体在交互环境中仍然脆弱，成功需要长时程状态跟踪、有效动作执行以及从失败步骤中恢复。我们通过两个模块化认知扩展对 SwiftSage（一种将快速动作提议器与较慢规划器相结合的双过程智能体）进行扩展：自适应记忆模块（AMM）用于显著性门控的情景存储和触发驱动检索，以及自我反思模块（SRM）用于有界执行时验证和纠正干预。两个模块均作为基于同一执行基底的特征开关扩展实现，从而支持在 ScienceWorld 上进行受控消融。在四种配置——基线、基线+AMM、基线+SRM 和完整系统——中，完整系统取得了最佳平均最终得分（64.62）、成功率（43.17%）和成功步骤效率（19.33 步），而 SRM 是最强的独立贡献模块。结果表明，在该设置中执行时控制是主要瓶颈，而情景记忆在运行时循环稳定后最为有用。

## Abstract
Language agents remain brittle in interactive environments, where success requires long-horizon state tracking, valid action execution, and recovery from failed steps. We extend SwiftSage, a dual-process agent that combines a fast action proposer with a slower planner, using two modular cognitive extensions: an Adaptive Memory Module (AMM) for salience-gated episodic storage and trigger-driven retrieval, and a Self-Reflection Module (SRM) for bounded execution-time validation and corrective intervention. Both modules are implemented as feature-flagged extensions over the same execution substrate, enabling controlled ablations on ScienceWorld. Across four configurations---baseline, baseline+AMM, baseline+SRM, and the full system---the full system achieves the best mean final score (64.62), success rate (43.17%), and successful-step efficiency (19.33 steps), while SRM is the strongest standalone contributor. The results suggest that execution-time control is the dominant bottleneck in this setting, while episodic memory becomes most useful once the runtime loop is stabilized.

## 论文核心问题与整体含义

- **研究动机**：语言智能体在交互式环境中仍然脆弱，成功执行任务需要长时程状态跟踪、有效动作执行以及从失败步骤中恢复。大型语言模型虽能生成流畅文本并解决许多短时推理问题，但这些能力并不能自动转化为可靠的智能体行为。
- **核心问题定位**：中心问题不仅是智能体“知道什么”，还在于它如何协调快速动作提议、较慢的深思熟虑、记忆以及执行时监控。常见失败模式包括：合理的顶层计划在执行时退化，例如重复过时动作、提出当前状态下不可用的动作、或尽管没有可测量进展仍继续导航。
- **研究背景**：这些失败难以仅靠扩大提示词解决，因为它们发生在语言生成与环境转换的接口处。本研究通过双过程语言智能体架构来探究这一问题，选定 SwiftSage 作为基线，因为它天然分离了快速 System 1 风格的动作提议器 Swift 和较慢的 System 2 风格规划器 Sage。
- **整体含义**：论文主张认知启发的智能体扩展只有在插入到正确的因果接口时才最有用；执行时控制是当前设置下的主要瓶颈，而情景记忆在运行时循环稳定之后才发挥最大价值。

## 论文提出的方法论

- **总体架构**：保留 SwiftSage 控制循环，将两个模块化扩展——自适应记忆模块（AMM）和自我反思模块（SRM）——作为特征开关插入到精确的运行时接口。
- **AMM（自适应记忆模块）**：
  - **写入钩子**：在环境返回观察和得分变化后运行，构建候选情景记录；仅当显著性门控检测到信息性转换时才存储，例如终端成功、正得分变化、近失误进展、明确的无效动作反馈或应避免的失败。
  - **存储表示**：紧凑的半结构化记录，包含任务、局部状态、近期上下文、执行动作、结果观察、得分转换和类型标签（成功、近失误、避免导向）。
  - **检索触发**：T1 对应 Swift 失败时检索相关情节并重试；T4 对应基线调用 Sage 且内存规划启用时检索成功和近失误情节；T2、T3 虽实现为停滞和重复无效动作的检索/缓存钩子，但在 AMM-only 配置中不直接修改模型输入。
  - **提示注入有界**：Swift 仅在恢复模式接收少量内存块，Sage 可接收稍大块；提示明确指示模型将记忆视为提示而非权威，当前观察、库存、可允许动作和运行时约束始终优先。检索到的记忆经过去重、按操作类型过滤和截断；若检索、格式化或提示结构检查失败，则回退到未修改的基线提示。
- **SRM（自我反思模块）**：
  - **Gate–1 验证**：在动作到达环境前立即执行，接收提议动作、当前有效动作集、最近状态描述符和运行时约束；规范化动作、检查可接受性、在轻微且安全的不匹配时应用确定性修复，若仍无效或违反约束则丢弃动作。Gate–1 对 Swift 动作、Sage 缓冲动作和 Critic 生成动作均统一应用。
  - **执行后停滞检测**：更新确定性诊断，跟踪重复观察、无效果重复动作、无效动作循环、无状态多样性过度导航、动词级循环等。当信号超过阈值时，发出结构化停滞报告，总结失败模式、应避免的动作和相关运行时约束。
  - **有界 Critic 干预**：仅在检测到停滞且保障措施允许调用时触发；Critic 输出短执行动作列表，解析、过滤后插入与 Sage 相同的 FIFO 缓冲区，而非直接执行。Critic 动作仍经过 Gate–1。调用受预算和冷却时间约束（默认每集最多三次 Critic 调用），使其成为受控修复机制而非始终开启的第二规划器。
- **完整系统组合**：AMM 写记忆并在触发条件下检索有界证据；SRM 在执行前应用 Gate–1，执行后监控停滞。两者主要交互发生在反思性纠正期间，当 SRM 调用 Critic 时，AMM 可提供检索到的情景证据作为支持上下文。设计保持明确层级：当前有效动作和约束占主导，停滞诊断识别局部失败模式，检索到的记忆提供可选证据，Gate–1 作为最终保障。

## 实验设计

- **数据集与环境**：使用 ScienceWorld，一个交互式文本基准，要求智能体通过有根基的顺序动作执行基础科学任务。评估使用任务 0–29，每个任务最多 10 个自然语言变体，每个配置最多 271 个评估 episode。
- **基准与对比方法**：以 SwiftSage 为基线，比较四种配置——基线、基线+AMM、基线+SRM、完整系统。所有配置共享同一环境接口、有效动作接地、每个时间步一次 `env.step`、Swift/Sage 仲裁和 FIFO 动作缓冲执行。
- **评估指标**：
  - **最终得分**：任务级宏观平均的最终得分。
  - **成功率**：宏观平均的任务成功率。
  - **Steps@Succ**：仅在成功 episode 上计算的平均步数。
  - 按 oracle 轨迹长度分组：Short（0 < Len ≤ 20）、Medium（20 < Len ≤ 50）、Long（Len > 50）。
- **机制级日志**：跟踪 AMM 写入和注入、SRM 丢弃和 Critic 调用，以及控制器使用代理（如 Swift 执行步数、缓冲区执行步数、System 2 调用率），用于解释最终得分来源。
- **运行设置**：Swift 使用 SwiftSage 风格的 Flan-T5-large 行为克隆组件，Sage 和 SRM Critic 使用本地通过 vLLM 服务的 Qwen2.5-7B-Instruct-1M；AMM 将显著情节存储在 Letta 档案记忆中。记忆消费上限：Swift T1 恢复最多 3 条检索情节，Sage T4 规划最多 5 条。

## 主要结论与发现

- **完整系统表现最佳**：平均最终得分 64.62，成功率 43.17%，Steps@Succ 19.33 步，优于基线、基线+AMM 和基线+SRM。
- **SRM 是最强独立贡献**：基线+SRM 得分 64.33，成功率和效率提升大部分来自 SRM；而基线+AMM 仅从 51.67 提升至 53.83，增益较小。
- **执行时控制是主导瓶颈**：SRM 的主要贡献不是频繁的反思性重规划，而是持续过滤无效或陈旧动作，防止其消耗环境步骤。Gate–1 丢弃频繁，Critic 调用接近每集一次左右。
- **记忆有条件的有效性**：AMM 单独增益有限，但在 SRM 稳定执行后，完整系统写更多记忆但使用更少记忆条件恢复，说明记忆在难任务中更有用。
- **反思必须受限**：将 Critic 预算从 3 增至 6 导致性能下降（从 64.33 降至 52.95），支持有界反思的设计选择。
- **系统使用趋势**：更强的配置用更少的 System 2 调用和更少的缓冲区执行步骤，更多直接 Swift 执行步骤，说明性能提升来自让快速路径更安全、慢速路径更有针对性，而非更多深思熟虑。

## 优点

- **模块化与可解释性**：AMM 和 SRM 作为独立特征开关实现，明确分离“信息提供”和“执行控制”两类因果接口，使消融研究可解释为证据与控制的协作而非不透明的重新设计。
- **有界设计**：检索触发驱动、记忆注入有界、Gate–1 始终开启的廉价保障以及 Critic 仅在停滞时调用，避免了无约束自我纠正带来的成本与性能风险。
- **机制级分析**：通过详细日志分解分数来源，能够识别 Gate–1 过滤、记忆检索、控制器使用等具体贡献，而非仅报告最终分数。
- **敏感性分析**：额外测试关键实现选择（记忆初始化、Critic 预算、T1 注入），增强了结论稳健性。
- **对话于认知理论**：将双过程理论、互补学习系统等概念与工程实现结合，提供了合理的架构定位。

## 不足与局限

- **记忆表示较简单**：AMM 依赖紧凑半结构化记录和外部记忆代理，检索排名和转换为具体动作改进的能力有限；缺乏成熟的语义整合层，主要覆盖快速情景侧而非较慢的语义侧。
- **SRM 规则手工设计**：停滞阈值、动作过滤规则、约束、Critic 预算和确定性修复策略均由人工设定，可能难以泛化；Gate–1 的修复在动作无法干净规范化时较浅。
- **评估范围有限**：仅在 ScienceWorld 文本模拟环境中测试，未覆盖多模态、机器人动作空间或其他模型后端；结果可能无法直接迁移到其他交互环境。
- **AMM 依赖初始化记忆**：评估使用填充记忆智能体，不能完全刻画冷启动学习、记忆老化、压缩或遗忘动态。
- **因果分析不完整**：机制级日志能展示记忆写入检索和 SRM 动作丢弃，但未完全隔离个体成功或失败背后的每个因果提示级因素，需要更细粒度的因果追踪和反事实重放。
- **部分结论相关性**：控制器使用与性能之间的关系主要是相关性证据，未来需要更严格的因果验证。
