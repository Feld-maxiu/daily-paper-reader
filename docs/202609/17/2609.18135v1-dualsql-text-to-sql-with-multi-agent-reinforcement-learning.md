## 摘要
最先进的文本到SQL系统通常是围绕两个基本任务（模式链接和SQL生成）的多智能体流水线。然而，现有工作为每个任务训练单独的模型，未能利用这些相互关联任务之间的协同效应。在本工作中，我们提出 DualSQL，一个由单一模型骨干驱动的两个智能体组成的新型文本到SQL系统。这些智能体共享相同的模型权重和智能体脚手架，通过稳健的多智能体强化学习（RL）框架实现联合优化。我们设计了三个数据库访问工具，以促进基于与数据库交互的有效多步推理。为了改进训练并避免模型崩溃，我们引入了一组 rollout 护栏机制，稳定多智能体RL训练，支持 DualSQL 在训练过程中持续改进。我们还引入了一种新的SQL正确性指标——鲁棒执行匹配（REX），以更准确地判断SQL正确性并分配奖励信号。仅在3755个示例上训练，DualSQL-4B 在 BIRD 开发集上实现了令人印象深刻的 68.0% 执行准确率，与之前的 7B 模型相当。DualSQL-8B 进一步提高到 71.1%，优于之前最先进的 32B 参数单模型解决方案。这些结果证明了联合多智能体强化学习在构建高性能文本到SQL流水线方面的优势。

## Abstract
State-of-the-art Text-to-SQL systems are typically multi-agent pipelines centered around two fundamental tasks: schema linking and SQL generation. However, existing work trains separate models for each task, failing to leverage the synergy between these interrelated tasks. In this work, we propose DualSQL, a new Text-to-SQL system consisting of two agents powered by a single model backbone. The agents share the same model weights and agentic scaffold, enabling joint optimization through a robust multi-agent reinforcement learning (RL) framework. We design three database access tools to facilitate effective multi-step reasoning grounded to interactions with the databases. To improve training and avoid model collapse, we introduce a set of rollout guardrail mechanisms that stabilizes multi-agent RL training, supporting DualSQL to keep improving during training. We also introduce a new SQL correctness metric, robust execution match (REX), to more accurately judge SQL correctness and assign reward signals. Being trained on only 3755 examples, DualSQL-4B achieves an impressive 68.0% execution accuracy on the BIRD development set, matching previous 7B models. DualSQL-8B further improves to 71.1%, outperforming previous state-of-the-art single-model solutions with 32B parameters. These results demonstrate the strength of joint multi-agent reinforcement learning for building high performance Text-to-SQL pipelines.

- **核心问题**：能否将模式链接与 SQL 生成视为统一智能体的两个侧面，通过共享模型权重和联合多智能体强化学习，实现对 Text-to-SQL 流水线的端到端联合优化？

## 2. 论文提出的方法论

### 2.1 统一智能体框架

- 将模式链接与 SQL 生成建模为 **同一随机过程**，两个智能体共享同一个 LLM 骨干与智能体脚手架。
- **模式链接智能体**：给定问题 Q 与完整数据库 schema S，识别相关 schema 子集 S'，减少大数据库干扰并为后续生成提供聚焦上下文。
- **SQL 生成智能体**：基于问题 Q 与链接 schema S' 生成 SQL 查询 y'。
- 通过共享权重，鼓励 SQL 生成结果与正确的 schema 元素对齐，减少幻觉。

### 2.2 三个数据库访问工具

- **SQL 执行器（SQL Executor）**：提供执行反馈验证语法/语义正确性、实体 grounding、以及通过 `sqlite_master` 或 `PRAGMA` 进行临时 schema 探索；对普通查询实施内容感知截断（最多 10 行，超长单元格截断），对 schema 查询保留完整结果。
- **全文搜索（Full Text Search）**：基于 SQLite FTS5 倒排索引，对 schema 名称和单元格值进行模糊匹配，返回匹配的 schema 元素及每个列最多五个匹配值，用于桥接用户查询中的模糊/缩写与数据库内容。
- **数据库分析器（Database Profiler）**：离线预计算表/列描述（由 LLM 生成）、外键关系以及列级统计（不同值数量、类型、空值比例），帮助智能体关注查询逻辑而非 schema 解释。

### 2.3 多智能体强化学习框架

- **异步 rollout 系统**：将 schema linking 与 SQL generation 作为完整随机过程，避免阶段间同步，提高多智能体 rollout 吞吐。每个训练批次 B 个 prompt，每个 prompt 由 pipeline actor 执行；每组大小 G，每个优化步采样 2B·G 条轨迹（sl 与 sql 各 B·G 条），按任务分组用于联合策略更新。

- **Rollout 护栏机制**（稳定多智能体 RL 训练）：
  - **严格格式检查**：每轮必须生成非空 `<think>` 块；每轮必须生成 `<tool_call>` 或最终答案代码块；工具调用须为合法 JSON 且同一工具不能以相同参数重复调用；最终代码块后内容不能超过本轮总长度的一半。
  - **Rollout 截断（Rollout Cutoff）**：检测到格式违规立即停止 rollout，防止格式错误被奖励为“可接受”，避免奖励黑客与不可恢复的模式崩溃。
  - **Loss Masking**：当轨迹以格式错误轮结束时，仅对该错误轮施加损失，屏蔽之前轮次的损失，以集中学习信号、避免惩罚有效推理步骤。

### 2.4 奖励设计

- **模式链接奖励** \(R_{sl}\)（分段函数）：
  - 完全匹配：\(R_{sl}=1\)；
  - 若 \(S^* \subseteq S'\)：\(R_{sl}=0.9 - \max(0.2 - \frac{|S^*\cap S'|}{|S'|}, 0)\)；
  - 若 \(T^* \subseteq T'\)（表级召回）：\(R_{sl}=0.7 - \max(0.2 - \frac{|S^*\cap S'|}{|S'|}, 0)\)；
  - 否则基于 F1 分数给予部分奖励：\(0.5 \cdot \frac{2|S^*\cap S'|}{|S^*|+|S'|}\)。
- **SQL 生成奖励** \(R_{sql}\)：若预测 SQL 与真实 SQL 结果一致（按 REX 等价判断），\(R_{sql}=1+0.1\cdot R_{tool}\)；否则为 0。\(R_{tool}\) 对使用工具且正确的轨迹给予奖励，鼓励多轮推理。
- **长度惩罚** \(R_l\)：对格式正确轨迹，长度在 \(L_{max}-L_{cache}\) 内为 0，超出部分线性衰减至 -1，超出 \(L_{max}\) 为 -1。
- **最终奖励**：\(R = \max(R_{task}, 0.1 R_f) + \lambda_l R_l \cdot R_f\)，其中 \(\lambda_l=0.2\)，负奖励截断为 0。

### 2.5 鲁棒执行匹配（REX）

- 传统的执行准确率（EX）对重复行、行顺序不敏感，且对列顺序排列过于敏感，容易产生假阳性/假阴性。
- **REX 指标**：基于数据相似性，对两个 SQL 查询结果集寻找最大匹配；若问题不要求行顺序（根据真实 SQL 是否含 `ORDER BY` 判断），先按高基数列排序；再尝试寻找列置换使匹配最大化；若存在完美匹配则认为结果集等价。
- REX 可确定性地计算，避免训练中强化假阳性信号。

### 2.6 训练目标

- 使用 GRPO（Group Relative Policy Optimization），结合 token-mean loss、clip-higher、以及序列级 masked importance sampling 以增强稳定性。
- 对每个 prompt，采样 \(2G\) 条轨迹，计算任务特定的组相对优势进行策略更新。

## 6. 论文的主要结论与发现

- **主结果**：DualSQL-4B 在 BIRD-Dev 达到 **68.0% EX**，与之前的 7B 模型相当；DualSQL-8B 达到 **71.1% EX**，超过此前 32B 参数的单模型 SOTA。
- **联合优化有效性**：多智能体 RL 相比单智能体 RL 在 BIRD-Dev 上提升 1.5% EX 和 1.9% REX；相比单轮 RL 提升 2.3% EX 和 5.4% REX。
- **REX 奖励的优势**：使用 REX 作为奖励信号比 EX 训练出的模型在 EX 和 REX 上均更高，尤其改善需要 `DISTINCT` 和 `ORDER BY` 的场景。
- **Guardrails 的作用**：有 guardrails 的训练能持续提升并避免模式崩溃；无 guardrails 时模型会强化错误格式行为并最终退化。
- **工具贡献**：所有三个工具均有正向贡献，SQL 执行工具影响最大（移除后 EX 下降 2.5%，REX 下降 6.8%）。
- **推理策略涌现**：模型学会交互式 schema linking（主动验证数据格式、表连接）和基于执行反馈的错误纠正（如类型转换、避免整数除法截断）。

## 7. 优点

- **单模型多智能体联合优化**：打破传统分阶段独立训练，通过共享权重实现跨任务知识迁移，显著提升小模型性能。
- **REX 指标设计**：更精确地判断 SQL 执行等价性，减少假阳性/假阴性，可作为更干净的奖励信号。
- **稳定的多智能体 RL 训练方案**：guardrails 组合（格式检查、截断、loss masking）有效抑制模式崩溃，使训练能够持续改进。
- **丰富的数据库工具**：SQL 执行、全文搜索、数据库分析器覆盖了查询验证、内容匹配和元数据理解，赋予智能体更强的 grounding 能力。
- **实验分析详实**：包含多组消融

- **分段奖励与长度控制设计细致**：模式链接奖励采用分段函数兼顾精确匹配与部分召回，SQL 奖励结合执行成功与工具使用，长度惩罚抑制冗余推理，使训练信号更细粒度。  
- **开放权重小模型的强性能**：仅用 4B/8B 参数即在 BIRD-Dev 上达到或超过更大模型，验证了在有限参数下通过联合智能体设计与强化学习可显著提升推理能力，降低部署门槛。  
- **可复现性与工程实现**：基于 VeRL 框架实现，给出详细超参数与工具设计，数据库工具基于 SQLite 等通用组件，有利于后续工作复现与扩展。

## 8. 缺点与局限性

- **训练数据经过过滤与修正**：作者从官方训练集中剔除了大量“平凡”和“不可解”样本，并手动修正标注错误。这虽然提升了训练质量，但可能导致模型对某些边缘问题或真实世界噪声的适应能力不足，削弱结论向原始分布的泛化性。
- **对比公平性受限**：在 BIRD-Dev 上，与已有方法（如 SQL-R1、Reasoning-SQL 等）的对比主要依赖原论文报告的结果，训练数据、基座模型、prompt 模板和评估细节可能存在差异，难以完全公平。在 Spider 上则仅与自身 RL 变体比较，缺乏与已发布 SOTA 系统的直接对比。
- **未在 BIRD 官方测试集上评估**：由于测试集未公开或不可访问，论文主要报告开发集性能，无法验证模型在官方隐藏测试集上的真实表现，这在一定程度上限制了结论的外部有效性。
- **计算资源需求较高**：DualSQL-8B 训练需要 32 块 H100 80GB GPU 约 4.5 天，整体算力门槛仍然较高，可能不利于资源受限的研究团队快速复现或扩展。
- **REX 指标的通用性**：鲁棒执行匹配虽然比传统 EX 更合理，但其列置换搜索和行排序策略引入了额外计算复杂度和设计选择；对于含聚合、嵌套子查询或 NULL 语义复杂的结果集，REX 的等价性判断仍可能存在边界情况，尚未形成广泛共识。
- **工具依赖性**：全文搜索依赖 SQLite FTS5，数据库分析器依赖离线 LLM 生成描述，SQL 执行器假设可无限制执行 SQL。这在不同数据库引擎（如 PostgreSQL、MySQL）或只读生产环境中可能需要额外适配，影响方法迁移性。
- **多智能体 RL 的稳定性边界**：尽管 guardrails 有效抑制了模式崩溃，但奖励函数中的分段阈值、长度惩罚系数和截断策略均较为主观，其对不同任务分布、不同基座模型和更长训练的适应性尚不清楚。
- **模式链接奖励的粒度有限**：当前奖励主要基于 schema 集合的重叠与 F1，未显式建模列间连接关系或虚假相关性，可能仍有奖励黑客空间，例如链接了正确表但错误列却获得较高部分奖励。

## 9. 总体评价与展望

- 论文的核心贡献在于将 Text-to-SQL 的模式链接与 SQL 生成两个关键子任务纳入统一的多智能体强化学习框架，并通过共享权重、鲁棒执行匹配奖励和严格的 rollout 护栏，显著提升了开放权重小模型在 BIRD-Dev 上的执行准确率。该工作证明了联合优化可以打破分阶段训练的性能上限，为后续端到端 Text-to-SQL 系统提供了可参考的训练范式。
- 相比单纯堆叠模型参数，DualSQL 在 4B/8B 规模下取得与更大模型相当甚至更优的性能，对降低推理与部署成本具有实际意义；同时其工具设计和奖励机制也为构建具备自我纠错和 schema 探索能力的智能体提供了具体实现路径。
- 未来工作可以在更广泛数据库引擎、更大规模未过滤数据、官方测试集以及更多公开 SOTA 系统上验证方法，进一步简化 REX 计算或寻找替代的语义等价奖励，并探索更细粒度的模式链接奖励以提升泛化性和训练稳定性。
