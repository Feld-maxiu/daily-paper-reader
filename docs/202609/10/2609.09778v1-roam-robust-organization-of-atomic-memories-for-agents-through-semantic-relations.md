## 摘要
长期语言模型智能体依赖跨交互的外部记忆。原子记忆尤为有用：其细粒度语义边界支持精确检索，并便于观察之间直接比较。然而不断累积的原子不可避免会变得冗余、重叠或冲突。现有方法通常让 LLM 管理器直接添加、更新、删除或改写记忆，将语义解释、存储决策和内容生成耦合在容易出错的单一操作中。我们提出 ROAM，一种关系引导框架，在管理时利用原子性，同时允许在回答时使用更丰富的表示。ROAM 将传入—已存储的原子对分类为独立、等价、方向性包含或冲突，然后将观察组织为活跃的主（Primary）角色和支持性证据（Evidence）角色。随后融合将互补细节和时间变化合并为紧凑、可能非原子的视图。回答时仅检索主视图，防止冗余或过时原子独立竞争。在多种模型和评估设置下，ROAM 将答案准确率最多提高 29.8 个百分点。消融实验显示不同关系带来互补收益，并且在角色组织之外融合持续带来提升。机制分析进一步发现，答案关键来源召回率提高 15.6 个百分点，混淆 token 占比降低 11.5 个百分点。ROAM 在不同管理器规模下保持稳健。

## Abstract
Long-term language-model agents rely on external memory across interactions. Atomic memories are particularly useful: their fine-grained semantic boundaries enable precise retrieval and direct comparison between observations. Yet accumulating atoms inevitably become redundant, overlapping, or conflicting. Existing methods often ask an LLM manager to add, update, delete, or rewrite memories directly, coupling semantic interpretation, storage decisions, and content generation in one error-prone operation. We introduce ROAM, a relation-guided framework that uses atomicity for management while allowing richer answer-time representations. ROAM classifies incoming--stored atom pairs as independent, equivalent, directionally subsuming, or conflicting, then organizes observations into active Primary and supporting Evidence roles. Fusion subsequently combines complementary details and temporal changes into compact, potentially non-atomic views. Only Primary views are retrieved for answering, preventing redundant or outdated atoms from competing independently. Across models and evaluation settings, ROAM improves answer accuracy by up to 29.8 percentage points. Ablations show complementary benefits from different relations and consistent gains from fusion beyond role organization. Mechanism analysis further finds 15.6-point higher answer-critical source recall and an 11.5-point lower confounder-token share. ROAM remains robust across manager scales.

## 1. 论文的核心问题与整体含义

- **研究背景**：长期语言模型智能体需要跨会话累计用户偏好、状态与经历，但原始对话历史会迅速超出工作上下文限制，因此业界普遍使用外部记忆系统，在查询时检索相关历史子集。
- **原子记忆的优势与挑战**：细粒度的原子事实（atomic facts）语义边界清晰，有利于精确检索、直接比较和定点更新；但持续的原子观察会自然产生语义重复、属性细化、时间状态变迁等，造成**冗余、重叠、冲突**。
- **现有方法的痛点**：许多系统让 LLM 管理器直接执行 `ADD / UPDATE / DELETE / REWRITE`。这种端到端做法把**语义解释、存储决策、内容生成**耦合在一个复合操作中，既难以控制又可能破坏历史溯源。
- **论文核心思想**：将复合管理决策**解耦为显式语义关系推断 + 确定性状态控制**，提出 ROAM（Robust Organization of Atomic Memories through Semantic Relations）。它利用原子性进行管理，同时允许回答时使用更丰富、融合后的表示，最终提高有限检索预算下答案质量。

## 2. 论文提出的方法论

ROAM 将记忆系统建模为 `Extraction → Management → Retrieval` 三段流水线，重点优化中间的 Management 阶段。

### 2.1 原子观察与角色结构

- 每个传入事实为原子观察：  
  `O_t = (a_t, τ_t, c_t)`，其中 `a_t` 是自包含事实陈述，`τ_t` 是时间戳，`c_t` 是来源上下文。
- 每条记忆记录为：  
  `M_i = (a_i, v_i, τ_i, c_i, z_i)`，其中：
  - `a_i`：不可变原子文本，用于后续关系推断与溯源；
  - `v_i`：当前回答期读视图（read view），可由融合生成；
  - `z_i`：角色标签，分为 `PRIMARY`（活跃、可检索）和 `EVIDENCE`（保留历史、但不独立参与回答检索）。

### 2.2 五类语义关系

对每一个传入观察与现有 Primary 记忆，ROAM 预测有序对关系：

`R = {IND, EQV, OSN, NSO, CON}`

- **IND（independent）**：两者可以同时为真，无严格蕴含关系。
- **EQV（equivalent）**：真值条件一致，互相蕴含。
- **OSN（old subsumed by new）**：新事实严格蕴含旧事实，并更具体，如“住在马萨诸塞州剑桥” 蕴含 “住在马萨诸塞州”。
- **NSO（new subsumed by old）**：旧事实严格蕴含新事实，新事实新增细节不足。
- **CON（conflict）**：在实体、属性和时间范围对齐后，描述互斥状态；显式时间限定词优先解释冲突。

### 2.3 关系驱动的确定性更新

- **候选检索**：用传入原子文本 `a_t` 从现有 Primary 中检索 top-k 相关记忆：  
  `C_t = ρ_k(a_t, P_{t-1})`
- **关系预测**：对候选逐一预测 `r_t(i) = Φ(a_t, a_i)`。
- **优先级选择**：若同一新事实与不同候选有不同的关系标签，选择最高优先级关系：  
  `CON ≻ OSN ≻ EQV ≻ NSO ≻ IND`
  即优先保护状态差异，其次偏向新增具体性，最后才合并冗余。
- **角色更新规则**（表 1）：
  - `IND`：传入记录作为新 Primary 插入，`v_t ← a_t`。
  - `EQV`：最早匹配的 Primary 保留，其余成为 Evidence，去除冗余。
  - `OSN`：传入记录成为新的 Primary，旧匹配记录降为 Evidence，保留新增具体性。
  - `NSO`：最早匹配的 Primary 保留，传入记录成为 Evidence，保留既有信息。
  - `CON`：传入记录成为当前 Primary，旧匹配记录变为 Evidence，构建时间历史。
- **融合 Fusion**：对存活 Primary 及其 Evidence 按时间排序后，用 `Fuse(View(S_1), ..., View(S_n); r*)` 更新 Primary 的读视图。融合只改变回答视图，不修改原子文本。
- **回答时检索**：只检索 Primary 的融合视图，Evidence 虽被保留但不参与竞争。

**算法 1** 概述了完整流式更新流程：候选检索 → 关系推断 → 优先级选择 → 角色更新 → 证据集合更新 → 融合视图。

## 3. 实验设计

### 3.1 评估场景

论文使用三个互补场景：

- **LongMemEval**：原始 500 问基准，用于测试自然长周期对话历史的迁移能力。
- **MEME-Post**：来自 MEME 基准的 694 个后变更问题，涉及多实体记忆与状态更新，测试多实体和时序变化场景。
- **LongMemEval Controlled**：基于 470 个有可用 gold-memory 标注的问题构造。固定答案关键记忆，仅改变干扰记忆（confounders）数量，设置 `N ∈ {0, 2, 4, 6, 8}`。用于精确诊断在有限检索预算下记忆组织策略抑制语义干扰的能力。

### 3.2 对比方法

- **Append-all**：保留所有候选作为独立可检索条目，不进行主动合并或删除；不使用管理器模型。
- **Mem0**：让管理器对每个传入记忆与已有历史选择 `ADD / UPDATE / DELETE / NONE`。
- **EverMemOS-style**：对短事实记忆做语义分组与合并，但不包含完整系统的 trace formation、profile building 和 agentic recollection。
- **ROAM（Ours）**：本文提出的关系引导管理方法。

## 6. 论文的主要结论与发现

- **鲁棒性优势**：ROAM 在所有非零干扰级别上均排名第一，三个管理器模型表现一致；在 N=8 时最多超过最强基线 29.8 个百分点。
- **自然场景迁移**：完整 LongMemEval 上，ROAM 在 3 个管理器下均最高（63.0%、59.8%、58.6%）；MEME-Post 上在多数管理器下排名第一，至少是最强受管理存储。
- **关系类型互补**：随着关系类型增加（`CON-only → CON+EQV → ROAM`），性能在干扰增大时更稳定；N=8 时为 32.1% → 62.3% → 71.9%。
- **融合独立有效**：在保持相同角色分配前提下，`ROAM w/o Fusion` 与完整 `ROAM` 对比显示融合在所有干扰级别都带来一致提升。
- **对管理器规模稳健**：ROAM 在 Gemma-4 E4B/12B/26B-A4B 上均第一，且容量收益在竞争加剧时更明显（N=8 时 69.4% → 71.3% → 74.5%）。
- **对预算约束稳健**：预算 128/256/512 下，N=8 时 ROAM 均领先，分别超过最强基线 14.9/29.8/4.1 个百分点。
- **机制验证**：ROAM 在 N=8、256 token 下实现 95.1% any-source coverage、73.8% all-source coverage、84.6% gold-source recall，并将 confounder token 占比降至 47.1%，说明其增益来自选择性地组织有限上下文，而非增加上下文量。
- **关系推断可靠**：Gemma-4-26B-A4B-it 对 EQV 和 CON 的 F1 分别约 93.2% 和 91.0%，但 OSN/NSO 的 F1 较低（76.1%/69.4%），说明方向性包含关系仍有一定挑战。

## 7. 优点

- **解耦设计**：将语义关系推断与物理存储突变分离，用确定性策略执行角色更新，管理更可控、可审计。
- **保留溯源但不污染检索**：Evidence 保留历史事实支持审计，而回答期只检索 Primary，避免过时/冗余原子独立竞争。
- **关系空间较细**：五类关系覆盖独立、等价、双向包含与冲突，比直接动作更具表达力和可解释性。
- **融合机制灵活**：对 EQV 去除冗余、对 OSN/NSO 保留兼容细节、对 CON 记录时间状态变化，生成紧凑回答视图。
- **实验诊断深入**：通过受控干扰、消融、规模/预算敏感性和检索诊断，较为有力地验证了机制而非仅报告端到端分数。
- **跨模型/跨基准一致性**：在多个管理器模型和多个基准上均表现出稳定增益，结论可迁移性较好。

## 8. 不足与局限

- **应用范围受限**：实验基于基准历史和受控检索预算，不能覆盖真实部署中的流长度、更新频率、上下文限制和对话复杂性差异。
- **表示形式单一**：ROAM 作用于短抽取事实单元，尚未扩展到层级化、事件级或更丰富的结构化记忆表示。
- **方向性包含关系精度有限**：OSN/NSO 的 F1 相对较低（76%/69%），可能影响涉及细节细化/泛化的记忆管理质量。
- **管理开销较大**：ROAM 的 LLM 调用次数显著高于 Mem0 和 EverMemOS-style（271.6 vs 30.1/18.6），虽然输出 token 少，但频繁调用可能带来延迟和资源消耗。
- **隐私/安全未解决**：Evidence 记录保留来源历史，但不构成隐私或安全机制；部署仍需单独考虑同意、访问控制、安全存储、删除政策等。
- **生成与评判偏差风险**：部分 confounders 和初始关系标签由 LLM 生成，答案裁判也由 LLM 担任；尽管有人工校验，仍可能残留偏差。
- **数据与规模覆盖有限**：管理器规模敏感性只用同一家族，未充分覆盖不同架构/更大规模模型；超长时程和多代理交互等场景未测试。
