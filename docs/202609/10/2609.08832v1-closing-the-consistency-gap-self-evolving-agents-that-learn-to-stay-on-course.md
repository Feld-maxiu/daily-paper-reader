## 摘要
由大语言模型（LLM）驱动的智能体可能平均表现准确，但在生产中不可靠，这一差异虽已被观察到，但在很大程度上仍未得到解决。在 AppWorld 基准上，使用 GPT-4.1 的 ReAct 智能体在相同任务执行五次时，仅有 53% 的任务能五次全部成功，尽管其单次运行通过率平均为 77%。我们将这 24 个百分点的差距称为一致性差距，并认为解决该问题是部署可信 AI 智能体的前提。我们提出一种自进化智能体框架，通过识别智能体轨迹中不稳定、低一致性的步骤并将其转化为情景记忆，供未来运行时调用，从而缩小这一差距。该框架的核心是一致性分析器，用于定位轨迹在执行间可能发生翻转的位置及原因；以及指南生成器，将诊断结果转化为针对性指南，存入记忆并注入未来在相似任务上的智能体执行过程。在 AppWorld 上使用 ReAct/GPT-4.1 时，我们的框架将五次运行全部成功的任务比例在相同任务评估中提高了 16 个百分点，在相似任务泛化中提高了 13 个百分点。

## Abstract
Large language model (LLM)-powered agents can be accurate on average yet unreliable in production, a discrepancy that has been observed but remains largely unaddressed. When given the same task five times, a ReAct agent on the AppWorld benchmark using GPT-4.1 succeeds in all five runs only 53% of the time, even though its per-run pass rate averages 77%. We call this 24-point shortfall the consistency gap, and we argue that addressing it is a precondition for trustworthy AI agent deployment. We present a self-evolving agent framework that reduces this gap by identifying unstable, low-consistency steps in agent trajectories and converting them into episodic memory the agent can draw on in future runs. At its core is a Consistency Analyzer that pinpoints where and why a trajectory is likely to flip across executions, and a Guideline Generator that converts the diagnosis into targeted guidelines, committed to memory and injected into future agent executions on similar tasks. On AppWorld with ReAct/GPT-4.1, our framework raises the fraction of tasks that succeed in all five runs by +16 points on same-task evaluation and +13 points on similar-task generalization.

## 1. 论文的核心问题与整体含义

- **核心问题**：LLM 驱动的智能体存在“平均准确但重复运行不可靠”的现象。论文将这种“单次平均通过率”与“多次运行全部通过率”之间的差距定义为 **一致性差距（consistency gap）**。
- **典型数据**：在 AppWorld 基准上，使用 GPT-4.1 的 ReAct 智能体单次运行平均通过率为 77%，但相同任务运行 5 次全部成功的比例仅为 53%，差距达约 24.4 个百分点。
- **整体含义**：这种差距意味着平均准确率并不能反映用户在生产环境中实际体验到的可靠性。论文认为，缩小一致性差距是部署可信 AI 智能体的前提，并将其作为第一等优化目标，而不是仅优化平均准确率。
- **关键观察**：
  - 一致性不等于准确率：高平均通过率可以与低“全通过率”并存。
  - 不一致性具有可测量的 token 级指纹：模型在每个推理点会产生一个 token 概率分布；当分布平坦、多个 token 接近并列时，即使采用温度为零的解码，决策也可能因平台噪声而在不同运行间翻转。
  - 可通过提示级别注入“一致性指南”来稳定易翻转的决策。

## 2. 论文提出的方法论

论文提出一个两阶段离线分析管道，并结合已有轨迹记忆框架实现自进化。

- **核心思想**：
  - 通过黑盒重采样识别轨迹中不稳定、低一致性的步骤。
  - 将诊断结果转化为针对性自然语言指南，存入情景记忆。
  - 在后续相似任务中检索并注入这些指南，从而减少重复运行的不一致性。

- **管道结构**：
  - **Detect 阶段：一致性分析器（Consistency Analyzer）**
    - 输入：单条记录轨迹 $T = \langle s_1, s_2, \dots, s_n \rangle$。
    - 对每个推理点 $s_i$，将相同提示重新发给同一 LLM 端点 $N$ 次（默认 $N=30$，温度 ≤ 0.5），得到响应集合 $D_i$。
    - 根据响应类型计算步骤一致性得分 $C(s_i) \in [0,1]$：
      - 自由文本/代码响应：使用 SBERT 嵌入的平均成对余弦相似度。
      - 分类响应（工具名、枚举参数等）：使用 token 集合上的平均成对 Jaccard 相似度。
      - 结构化组合响应：将字段分解后加权求和。
    - 聚合为轨迹一致性得分：$C_{\text{mean}}(T) = \frac{1}{n}\sum_{i=1}^n C(s_i)$。
    - 该方法无需访问模型内部 logits、激活或智能体源码，属于黑盒估计。
  - **Generate 阶段：指南生成器（Guideline Generator）**
    - 将低于阈值 $\theta_C = 0.85$ 且位于决策路径上的步骤标记为不一致步骤。
    - LLM 根据轨迹及带标记步骤生成指南，按 Fang et al.（2026）分类为：
      - **strategy**：强化正确但波动大的模式。
      - **recovery**：绕开与失败相关的高波动步骤。
      - **optimization**：跳过或简化非必要的高波动步骤。
    - 指南进入双索引记忆，支持余弦相似度检索和 LLM 引导查询，并在后续运行时注入提示。

- **关键公式与指标**：
  - $\text{Pass@}k(t)$：$k$ 次中至少一次成功。
  - $\text{Mean@}k(t)$：$k$ 次平均通过率。
  - $\text{Pass}\hat{\ }k(t)$：$k$ 次全部成功。
  - 一致性差距：$\text{Gap@}k(T) = \text{Mean@}k(T) - \text{Pass}\hat{\ }k(T)$。
  - 归一化一致性：$\text{Consistency@}k(T) = \text{Pass}\hat{\ }k(T) / \text{Mean@}k(T)$。

## 3. 实验设计

- **数据集与场景**：
  - 使用 **AppWorld** 基准的 `test normal` 划分，共 168 个交互式编码智能体任务。

  - AppWorld 将任务组织为 scenarios，每个 scenario 有 3 个相似变体 v1、v2、v3，用于测试相似任务泛化。

- **智能体与模型**：
  - 智能体架构：ReAct。
  - 模型：GPT-4.1（Microsoft Azure 云端端点）和 GPT-OSS-120B（AWS 云端端点）。
  - 每个任务运行 5 次，$k=5$。

- **对比条件**：
  - Baseline：无指南。
  - + Guidelines: Same Task：从同一任务的一条 baseline 轨迹生成指南，再次运行该任务。
  - + Guidelines: Similar Task：从 scenario 的 v1 轨迹生成指南，注入 v2 和 v3 运行。

- **其他评估**：
  - 在 50 个 AppWorld test challenge 任务上，用 AUROC 评估轨迹一致性得分能否预测轨迹通过/失败。

## 6. 论文的主要结论与发现

- **一致性差距显著**：
  - GPT-4.1：Mean@5 为 77.4%，Pass^5 为 53.0%，差距 24.4 pp，归一化一致性 0.69。
  - GPT-OSS-120B：Mean@5 为 33.9%，Pass^5 为 10.1%，差距 23.8 pp，归一化一致性仅 0.30，Hard 任务上为 0.00。
- **框架显著提升一致性**：
  - GPT-4.1：相同任务 Pass^5 提升 +16.0 pp，Mean@5 提升 +3.6 pp；相似任务 Pass^5 提升 +13.0 pp，Mean@5 提升 +2.1 pp。
  - GPT-OSS-120B：相同任务 Pass^5 提升 +6.0 pp，Mean@5 提升 +4.8 pp；相似任务 Pass^5 提升 +8.7 pp，Mean@5 提升 +6.6 pp。
  - 相对提升上，GPT-OSS-120B 的 Pass^5 相对提升（59%）高于 GPT-4.1（30%），说明基线越低，可挖掘的一致性空间越大。
- **一致性改善不牺牲平均准确率**：
  - GPT-4.1 的 Mean@5 在多数设置中保持不变或略有提升，支持“一致性目标与准确率目标可兼容”的设计假设。
- **轨迹一致性得分可作为结果预测信号**：
  - 单个轨迹的聚合一致性得分对轨迹通过/失败的 AUROC 达到 0.699，可在缺少 ground-truth rating 时辅助指南生成器判断轨迹结果。
- **不一致性的来源**：
  - 来自推理点处 token 概率分布的平坦性，而非单纯解码策略。因此仅使用 greedy 解码或固定种子不能解决该问题。

## 7. 优点

- **问题定义清晰**：明确区分平均准确率、单次成功率和多次全通过率，提出一致性差距和归一化一致性指标，概念贡献明确。
- **方法黑盒且通用**：一致性分析器只需重新调用 LLM 端点，不依赖模型内部参数或智能体源码，适用于基于托管 LLM 的各种智能体架构。
- **不侵入推理循环**：通过提示级别指南注入稳定决策，不改变在线推理过程，工程上容易集成。
- **面向智能体响应结构的评分设计**：针对自由文本、分类值和结构化响应分别使用不同相似度度量，比单纯预测熵更能反映语义上的等价与差异。
- **结合已有记忆框架**：在 Fang et al.（2026）的成熟记忆存储与检索机制之上只添加一致性目标的上游阶段，增加增量贡献的可信度。
- **评估维度全面**：不仅评估同任务改善，还评估相似任务泛化；并按难度分层，提供更细粒度结论。
- **对低能力模型也有正面效果**：GPT-OSS-120B 相对提升显著，表明方法不只对强模型有效。

## 8. 不足与局限

- **实验覆盖有限**：
  - 仅在 AppWorld 一个基准和 ReAct 一种智能体架构上评估，虽然作者提到非正式测试过 CUGA 等其他架构，但未量化。
  - 仅评估两个模型，未跨多个模型家族进行系统对比。
- **缺少指南验证机制**：
  - 生成的指南直接进入记忆，没有验证步骤来防止模糊、冲突或过拟合的指南进入记忆。作者也承认这是一个未来工作方向。
- **无法消除不一致性，Hard 任务上差距仍大**：
  - 框架只能改善而无法根除不一致性。GPT-OSS-120B 的 Hard 任务基线一致性为 0，提升后仍很低。
- **重采样成本高**：
  - 默认每个推理点重采样 30 次，token 成本约为单次运行的 30 倍，影响生产环境可扩展性。
- **一致性分析器只测稳定性，不测正确性**：
  - 一个“稳定但错误”的决策会被判定为高一致性，分析器本身不是验证器。
- **平台非确定性不可控**：
  - Pass^5 比较假设 baseline 与指南

注入运行的云端平台非确定性分布一致，但该假设无法验证，且云端平台的非确定性水平在不同时间、不同任务上可能波动。因此，Pass^5 的提升中可能混入平台噪声变化带来的偏差，作者也明确承认这一点。
