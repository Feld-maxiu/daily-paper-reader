## 摘要
近期Web智能体在测试时动作选择中使用世界模型，通过采样候选动作、预测所产生的网页状态，并用排序模型或过程奖励模型（PRM）对它们进行排序。这些世界模型通常通过监督式下一状态预测来训练，以生成固定表示，如HTML或AXTree快照。然而，这一目标与下游排序器不一致，后者依赖于预测状态在候选之间具有区分性，以便准确评分。为解决这一问题，我们提出了预测状态匹配（predicted-state matching），一种训练目标，其中预测表示必须将真实结果状态与替代动作所达到的状态区分开。我们使用从WebArena Go-Browse轨迹派生的分支式Web智能体数据集训练这些模型，其中每个决策点包含多个替代动作及其结果状态。在我们留出的预测状态匹配基准上的实验表明，我们的方法优于用监督式下一状态预测训练的世界模型。我们进一步表明，与仅动作PRM以及用监督式下一状态世界模型增强的PRM相比，我们的方法在WebPRMBench上改善了PRM风格的动作排序。最后，在WebArena-Lite上，使用我们的世界模型进行测试时动作选择提升了端到端任务成功率。项目主页见：https://dhruvpendharkar.github.io/dwm/。

## Abstract
Recent web agents use world models for test-time action selection by sampling candidate actions, predicting the resulting web states, and ranking them with a ranker model or a Process Reward Model (PRM). These world models are typically trained via supervised next-state prediction to generate fixed representations like HTML or AXTree snapshots. However, this objective is misaligned with the downstream ranker, which relies on predicted states being discriminative across candidates to accurately score them. To address this, we introduce predicted-state matching, a training objective where the predicted representation must distinguish the true resulting state from those reached by alternative actions. We train these models using a branching web-agent dataset derived from WebArena Go-Browse trajectories, where every decision point contains multiple alternative actions and their resulting states. Experiments on our held-out predicted-state matching benchmark show that our approach outperforms world models trained with supervised next-state prediction. We further show that our approach improves PRM-style action ranking on WebPRMBench compared with action-only PRMs and PRMs augmented with supervised-next-state world models. Finally, on WebArena-Lite, using our world model for test-time action selection improves end-to-end task success. Our project page is available at: https://dhruvpendharkar.github.io/dwm/.

## 一、论文的核心问题与整体含义

- **研究背景**：Web 智能体在测试时进行动作选择时，越来越多地采用“世界模型 + 排序器/过程奖励模型（PRM）”的规划范式：先采样候选动作，再预测每个动作导致的下一状态，最后根据预测状态对候选动作进行排序。
- **核心问题**：现有 Web 世界模型通常通过**监督式下一状态预测**训练，要求生成固定格式的目标表示（如 HTML、AXTree 快照或文本摘要）。然而，这种训练目标与下游排序器的实际需求不一致——排序器需要的是**能够区分不同候选动作后果的判别性表示**，而不是对某个固定格式的忠实重建。
- **整体含义**：世界模型的预测状态应当服务于“区分不同动作的结果”，而非“复现某个预定义状态格式”。论文提出 **predicted-state matching（预测状态匹配）** 这一表示无关的训练目标，将评估标准从“与固定目标一致”转向“能否将真实结果状态与替代动作结果状态区分开”，从而更直接地对齐下游动作排序任务。

## 二、方法论

### 1. 核心思想：预测状态匹配（Predicted-State Matching）

- 给定当前状态 \(s_t\)、任务指令 \(I\)、历史 \(h_t\) 和一个查询动作 \(a_t^{\mathrm{qry}}\)，世界模型生成一个**文本形式的预测下一状态表示** \(\hat{z}^{\mathrm{qry}}_{t+1}\)。
- 该表示不要求匹配任何预定义的目标字符串；相反，训练目标是让一个**固定的匹配裁判（matching judge）** 能够根据 \(\hat{z}^{\mathrm{qry}}_{t+1}\)，从两个候选下一状态中识别出真实结果状态 \(s^{\mathrm{qry}}_{t+1}\)，而不是替代动作导致的下一状态 \(s^{\mathrm{alt}}_{t+1}\)。
- 裁判只接收预测表示和两个候选状态，**不接收指令、历史、当前状态或查询动作**，因此预测表示自身必须包含足够信息来完成判别。

### 2. 分支式数据构建

- 基于 Go-Browse 在 WebArena 环境中收集的轨迹数据。
- 原始轨迹是线性的，但不同轨迹可能重复访问相同浏览器状态。论文将这些重复状态合并为**状态-动作图**，节点为浏览器状态（由 AXTree 表示），边为已执行动作及其观察到的下一状态。
- 共享同一当前状态且具有多个出边的节点形成**分支决策点**，每个决策点包含多个候选动作及其对应的下一状态。
- 最终构建的数据集包含 **7,730 个分支决策点**（来自 2,839 条轨迹），生成 **30,920 个成对匹配示例**。
- 数据按 WebArena 领域（Shopping、CMS、Reddit、GitLab、Map）进行分层划分，保持训练/评估分布相似。

### 3. 训练目标与奖励设计

- 世界模型基于 Qwen3-8B 微调，使用 **Group Relative Policy Optimization（GRPO）** 进行强化学习。
- 对每个输入采样 8 个完成结果，计算组相对优势。
- 序列级奖励由两部分组成：
  - **匹配奖励** \(R_{\mathrm{match}}\)：裁判成功选择真实结果状态为 1，否则为 0。
  - **格式奖励** \(R_{\mathrm{fmt}}\)：生成内容非空且满足 `<predicted_state>` XML 标签格式为 1，否则为 0。
- 总奖励：\(R = R_{\mathrm{match}} + \lambda_{\mathrm{fmt}} R_{\mathrm{fmt}}\)，主实验取 \(\lambda_{\mathrm{fmt}}=0.4\)。
- KL 正则化系数为 0.04；训练时采样温度 1.0，推理时使用贪心解码，最大生成长度 2048 tokens。
- 裁判模型在训练中使用 Qwen3-32B，评估时还使用 GPT-4o 和 Llama-3.1-70B-Instruct 测试跨模型泛化。

### 4. 下游动作排序接口

- 世界模型为每个候选动作 \(a_t^i\) 生成预测状态 \(\hat{z}^i_{t+1}\)。
- 下游 PRM/排序器以当前上下文和候选动作对为输入，可选地附加预测状态表示：
  \[
  \hat{y} \sim r_\phi\left(\cdot \mid I, h_t, s_t, (a_t^1, \hat{z}^1_{t+1}), (a_t^2, \hat{z}^2_{t+1})\right)
  \]
- 无状态情况下省略 \(\hat{z}\) 项，用于与仅动作排序进行对比。

- **端到端 WebArena-Lite**：

## 六、主要结论与发现

- 在预测状态匹配基准上，本文方法总体准确率达到 **80.80%**，显著优于 WebDreamer-7B（74.51%）、WebWorld-8B（70.17%）以及数据匹配的监督 SFT 基线（47.77%）。
- 跨裁判模型鲁棒性：使用 GPT-4o 和 Llama-3.1-70B 评估时，本文方法仍保持优势（81

% 左右），证明判别性表示不依赖特定裁判模型。

- 在下游 WebPRMBench 动作排序任务中，将 state-matching 预测状态加入奖励模型训练后，相较 Direct（无状态）和加入 WebWorld-8B 状态的设置，Pairwise Accuracy 与 Best-of-N Accuracy 均有稳定提升；其中 Best-of-N 指标提升更为明显，说明高质量的预测状态能帮助排序器在候选动作集合中更可靠地选出最优动作。
- 冻结排序器实验进一步表明，即使不重新训练奖励模型，仅在推理时为冻结的 Qwen2.5-3B/7B 排序器额外提供 state-matching 预测状态，也能一致提升排序准确率；这验证了预测状态本身具有可迁移的判别信息，而非仅靠训练过程中的偏好拟合。
- 在端到端 WebArena-Lite 评估中，Best-of-5 + state matching 的任务成功率高于 Best-of-5（仅动作排序）和 ReAct 单动作选择，证明本文世界模型在真实网页任务规划中能够有效改善动作选择质量。
- 消融实验显示，格式奖励系数 \(\lambda_{\mathrm{fmt}}\) 在 0.2、0.4、0.6、1.0 范围内均能保持较稳定的匹配准确率，说明方法对格式奖励强度的选择不敏感。
- 数据与算力效率方面，本文仅使用 30,920 个成对示例和 390 GPU-hours，即取得优于 WebDreamer-7B、WebWorld-8B 等大规模监督训练方法的匹配准确率；这表明以“区分动作后果”为目标的训练范式比单纯扩大状态重建数据规模更有效。

## 七、局限性与未来工作

- 分支决策数据来自已有 Go-Browse 轨迹的状态-动作图，并未对决策点的所有可能动作进行穷举采样，因此训练信号受限于行为策略覆盖，可能遗漏某些高风险或罕见动作的后果。
- 裁判模型与生成模型均基于 Qwen 系列，虽然使用 GPT-4o 和 Llama-3.1-70B 进行了跨模型鲁棒性验证，但仍可能存在共享的表示偏好或评估偏差。
- 当前实验主要围绕 WebArena 环境与 Go-Browse 收集的网页状态表示，对其他网页环境、动态页面和复杂交互范式的泛化性尚未充分验证。
- 下游排序器实验采用 answer-only 偏好训练设置，未与包含完整推理链或结构化思考的更强 PRM 训练策略结合；未来可探索将 state-matching 表示与推理式奖励模型结合。
- 世界模型当前仅输出文本形式的预测状态，未直接利用浏览器结构化 AXTree 或视觉信息；多模态状态表示与判别性训练目标的结合值得进一步研究。
- 未来工作可扩展到更多政策模型、更大规模分支数据自动收集，以及在真实在线网页任务中进行在线训练和持续学习。

## 八、总结

本文提出了 **predicted-state matching**，一种面向 Web 智能体动作排序的世界模型训练目标。该方法不要求预测状态匹配固定的下一状态格式，而是通过匹配裁判区分真实结果状态与替代动作结果状态，直接优化状态的判别性。实验表明，该训练目标在匹配准确率、下游 PRM 排序性能以及端到端任务成功率上均优于监督式下一状态预测和现有世界模型，同时所需数据和算力更少。该工作为构建更高效、更对齐下游决策的 Web 世界模型提供了新视角。
