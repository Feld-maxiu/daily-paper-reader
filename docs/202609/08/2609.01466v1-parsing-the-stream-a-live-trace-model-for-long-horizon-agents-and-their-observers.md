## 摘要
长时程智能体的运行轨迹会超出其两类使用者的处理能力：监控运行过程的人类观察者，以及智能体自身——轨迹必须被折叠回其有界上下文中。我们提出了一种实时轨迹模型，这是一种仅允许追加的事件账本，可增量折叠为类型化运行状态，并编译为面向不同使用者的视图；我们针对确定性真值对两类使用者进行了评估。在观察者侧，以LLM阅读器作为代理进行评估，与预算受限的单次读取原始轨迹相比，所编译视图在回答监控问题时所需输入token数量约为前者的1/14和1/15（因阅读器而异），成本降低5–7倍，且准确率更高（0.85–0.87对0.48）。由于这些问题与视图模式共同设计，我们将以模式覆盖为前提的token与成本降低视为可迁移的结果。对于智能体自身，在包含120条链路的顺序依赖任务上，在每步状态中维护任务运行统计量的机制能够成功，而全上下文提示则失败（在干净协议下为30/30对8/30，n=30，因基准系统共同开发而标记为描述性）；提示级暂存器以更低的成本达到了与折叠相同的准确率，一项双臂分解将折叠的准确率归因于其确定性聚合，将其成本优势归因于其紧凑性。与更便宜的替代方案相比，折叠的剩余价值在于确定性可审计性，以及能够从相同状态为观察者提供服务。我们从观察到的失败中推导出轨迹折叠的十一条候选需求，并用一个顺序敏感任务族来划定其边界，在该任务族上折叠不再有帮助。代码、基准、可再生成的合成语料库以及所有工作台轨迹均已发布。

## Abstract
A long-horizon agent's trace outgrows both of its consumers: the human observer monitoring the run, and the agent itself, whose bounded context the trace must be folded back into. We present a live trace model, an append-only event ledger folded incrementally into typed run state and compiled into per-consumer views, and evaluate it for both consumers against deterministic ground truth. For the observer side, evaluated with an LLM reader as proxy, the compiled view answers monitoring questions using approximately 14x and 15x fewer input tokens (by reader) and at 5-7x lower cost than a budget-capped single-call reading of the raw trace, with higher accuracy (0.85-0.87 versus 0.48). Because the questions were co-designed with the view schema, we treat the token and cost reduction, conditional on schema coverage, as the transferable result. For the agent, on 120-link sequential-dependency tasks, mechanisms that maintain the task's running statistic in per-step state succeed where full-context prompting fails (30/30 versus 8/30 under a clean protocol, n=30, labeled descriptive owing to benchmark-system co-development); a prompt-level scratchpad matches the fold's accuracy at lower cost, and a two-arm decomposition attributes the fold's accuracy to its deterministic aggregate and its cost advantage to its compactness. The fold's remaining value over cheaper alternatives is deterministic auditability and serving the observer from the same state. We derive eleven candidate requirements for trace folding from observed failures and delimit them with an order-sensitive task family on which the fold ceases to help. Code, benchmarks, a regenerable synthetic corpus, and all workbench traces are released.

## 1. 论文的核心问题与整体含义

- **研究动机**：长时程智能体的一次运行会持续产生单一产物——执行轨迹（trace）。这条轨迹会“压垮”两类使用者：
  - **人类观察者**：需要在中途判断智能体在做什么、什么已经确定、什么尚未完成；
  - **智能体自身**：必须把轨迹折叠回有界的上下文窗口，否则上下文不断膨胀。
- **背景痛点**：
  - 12 个真实会话共 112 MB，前沿模型读取原始轨迹尾部时，回答基础监控问题的准确率仅 **0.479**，同时消耗 779K 输入 token；
  - 在 120 链路的顺序依赖任务上，全上下文工作器的累计计费输入达到 **2.37M token**，成功率为 **7/30**（开发期注入错误）或 **8/30**（干净协议）；未缓存的扁平式全上下文每轮费用约 **$7.49**。
- **整体含义**：现有系统用两套独立工具分别服务观察者和智能体，而本文提出用**单一轨迹模型**同时服务二者，用确定性折叠减少重复理解成本，并保留审计能力。

## 2. 论文提出的方法论

- **核心思想**：将智能体运行看成一条**仅追加（append-only）的事件账本**，把它**增量折叠**为类型化运行状态（RunState），再编译成面向不同消费者的视图。
- **四层架构**（实现为 `tracelab`）：
  1. **Ledger（账本层）**：每个内容块产生一个类型化事件；带字节偏移可恢复；内容通过 SHA-256 指纹防篡改；对消息级用量做**按 API message id 去重**，避免 token 统计膨胀（最多可达 3.49×）。
  2. **RunState（单次折叠）**：维护目标、前沿、待处理调用、文件、成本以及 **facts**（按 `file:key` 源标识）；采用**出现身份**而非 newest-wins；**聚合保留驱逐**（被驱逐数值折叠进每个 key 的运行计数和总和）；对驱逐后重读保持幂等。
  3. **Derived nodes（版本化派生节点）**：带有效性生命周期（current / suspected-stale / invalidated/superseded），支持**后见之明重解析**；新的结果只会“取代”旧版本，不会改写历史。
  4. **Views（消费者视图）与 curator loop**：为观察者生成 HTML 页面（目标、前沿、异常徽章、统计卡、溯源链接、诚实水印）；为工作器生成紧凑文本块（GOAL/NOW/COUNTERS/FILES/KEY FACTS）；curator 每 `K` 步（默认 5）从工作器自身轨迹重新物化工作视图，形成闭环。
- **关键设计约束**：由失败驱动，总结为 **11 条需求**，包括：
  - 携带事实而非引用（requirement 1）；
  - 出现身份而非 newest-wins（req 2）；
  - 绝不静默截断（req 3）；
  - 源作用域身份（req 4）；
  - 确定性运行聚合（req 5）；
  - 聚合保留驱逐（req 6）；
  - 跨驱逐重读幂等（req 7）；
  - 跨抽取批次使用 canonical key schema（req 8）；
  - 对安全分类器拒绝容忍的分批（req 9）；
  - 对抽取事实做逐字验证（req 10）；
  - 聚合必须声明自身覆盖范围（req 11）。
- **算法流程简述**：账本逐事件折叠为状态；状态被物化为版本节点；视图从同一状态编译；工作器动作重新进入账本，供后续折叠使用。除可选的 LLM 语义抽取器外，非抽取路径是确定性的。

## 3. 实验设计

- **观察者侧 benchmark：COMPREHEND**
  - **数据**：12 个真实个人工作会话（112 MB），另有可字节级再生成的 12 个合成会话（11.4 MB）。
  - **任务**：6 类监控问题：最新用户请求、轮次数、最常用工具、触碰文件、最后错误、悬空调用。
  - **评分**：由账本真值机械生成；准确率为 [0,1] 序列得分（精确匹配、子串、集合 F1）。
  - **对比条件**：原始尾部（budget-capped raw tail）、扁平日志（flat log）、编译视图（compiled view）。
  - **阅读器**：Sonnet 5（前沿）与 Haiku 4.5（较小）；每个 transcript-condition 一次调用，共 70 个问题/条件。
- **智能体侧 benchmark：CONTINUE**
  - **任务族**：scatter、fix、chain、prose-chain、altchain；核心是 **chain 任务**：每个文件给出一个 delta 和下一个文件，答案是所有 delta 之和。
  - **主要对比**（120 links）：
    - 全上下文扁平（8/30，$7.13/run）；
    - curated view / fold（30/30，$1.59/run，cached）；
    - 提示级 scratchpad（30/30，$0.97/run，cached）；
    - 还包括 calculator tool、retrieval-over-trace、summarization（capped/uncapped）、mask+notes hybrid、deconfound arms 等。
  - **协议**：开发期使用每 call-index 预提交错误注入；最终协议无注入、n=30、相同种子；思考模式全程关闭。
- **其他实验**：
  - 缓存经济学（cache-read/write 计数、refresh 间隔 5/10/20）；
  - 解析器内推理（prose-chain 上 n=3/arm，固定模式 vs 调优模式 vs 小模型 vs 前沿模型吞噬管线）；
  - 边界任务 altchain（交替符号链）用于测试折叠失效条件。

## 6. 论文的主要结论与发现

- **观察者侧**：
  - 编译视图较原始尾部减少输入 token 约 **14×（Sonnet 5）和 15×（Haiku 4.5）**，同读者成本降低 **5–7×**；
  - 准确率：视图 **0.85–0.87** vs 原始尾部 **0.48**；
  - 小阅读器（Haiku 4.5）读编译视图（0.850，$0.08）优于前沿阅读器读原始尾部（0.479，$2.37）；
  - 聚合类问题（文件数、轮次数）在无视图时几乎不可答。
- **智能体侧**：
  - 在 120-link 链任务上，维护每步运行统计量的机制成功，全上下文失败：**30/30 vs 8/30**（干净协议）；
  - 提示级 scratchpad 以更低成本达到同样准确率；由此将折叠的价值定位为**确定性审计和同一状态服务观察者**；
  - 双因素分解表明：**确定性聚合决定准确率，有界性决定成本**；
  - 最小 harness 累加器（$0.67/run）也能 10/10，说明在该任务族上任务特定状态已经足够；折叠的额外价值在于通用 trace model 和可审计性。
- **边界结论**：
  - 在顺序敏感任务（交替符号链）上，折叠不再有帮助，甚至可能低于全上下文；
  - 组织为 **11 条轨迹折叠需求**，并指出它们只对本任务类有规定性。

## 7. 优点

- **统一架构**：用同一个折叠状态服务两类消费者，避免重复系统。
- **确定性审计与真值**：不使用 LLM 判分；所有分数对照确定性真值；合成语料可字节级再生成，确保可审计性。
- **失败驱动的方法学**：11 条需求全部来自实测失败，并伴随回归测试；记录了开发阶梯和边界条件。
- **成本与 token 精确核算**：纳入缓存读/写、缓存未命中、协议失败成本、解析器自推理预算，经济账更真实。
- **诚实标定**：区分描述性与确认性结论；将要求的作用范围限制在已验证的任务类上。
- **完整发布**：代码、4 个 benchmark harness、合成语料、所有工作台轨迹、支出账本和 99 个回归测试均已发布。

## 8. 不足与局限

- **样本量有限**：多数次要臂 n=3–10，仅少数 120-link 单元 n=30；n=3 曾被证明高估 60-link 崩溃。
- **基准—系统共同演化**：任务族、机制、扩展决策与生成器共同发展；虽然最终协议和冻结网格有所缓解，但外部任务尚未验证。
- **COMPREHEND 范围受限**：
  - 问题与视图 schema 共同设计，无法区分“视图保留了观察者所需”和“视图恰好包含基准所问”；
  - 使用 LLM 阅读器作为观察者代理，而非真实人类；真实工具调用匹配率 99.95% 但仍有接口派生残余。
- **单厂商栈**：worker、reader、extractor、定价、缓存、拒绝行为全部来自同一厂商，外部泛化性未知。
- **信任边界未分析**：curator 会把含工具输出的轨迹内容喂回工作器，研究了溯源但未处理提示注入、策略或秘密信息脱敏。
- **单一会话**：多会话、多智能体账本未测试。
- **检索被排除**：chain 任务构造上禁用搜索，缺少一个“检索对全部 arm 可用但单独仍不足”的任务族。
- **缓存匹配差异**：成本列比较的是“按部署配置”，不同 arm 缓存资格不同，未完全缓存匹配。
