## 摘要
检索增强生成（RAG）使大语言模型（LLM）能够访问外部知识，但其传统的“检索—拼接—生成”流程替模型做出了检索决策。随着工具使用和智能体循环变得更加可靠，智能体可以自行决定是否检索、检查什么以及何时停止。这一转变暴露了一个新的瓶颈：智能体可能不知道知识库包含什么。传统知识库将文档暴露为匿名的文本块，关于范围、目的、来源或关系的信息有限。我们提出 Knowledge-as-Skill，一种使知识库可发现、可导航且自描述的组织方案。它包含三层：以 SKILL.md 为中心的发现层；每个目录一个 index.md 的导航层；以及包含文档的知识层，文档带有 YAML 前置元数据，用于描述主题、类型、来源和生命周期。该设计遵循开放知识格式（OKF）和 Skill 协议，无需修改智能体框架。我们还提供了 knowledge-as-skill，一个将 PDF、Word 文件、网页导出和笔记等异构集合转换为这种结构的流水线。在 WixQA 企业客户支持基准上的初步评估中，我们的设置获得了 0.889 的事实性和 0.816 的上下文召回率，而已报道的 Corpus2Skill 数值分别为 0.767 和 0.708。它的忠实度略低、上下文精确度较低，并且交互轮次更多。由于模型、提示和知识包构造不同，这些结果是方向性的跨工作证据，而非受控比较。

## Abstract
Retrieval-augmented generation (RAG) gives large language models (LLMs) access to external knowledge, but its conventional retrieve-concatenate-generate pipeline makes retrieval decisions on behalf of the model. As tool use and agent loops become more reliable, an agent can decide whether to retrieve, what to inspect, and when to stop. This shift exposes a new bottleneck: the agent may not know what a knowledge base contains. Traditional knowledge bases expose documents as anonymous text chunks with limited information about scope, purpose, provenance, or relations.   We propose Knowledge-as-Skill, an organization scheme that makes a knowledge base discoverable, navigable, and self-descriptive. It has three layers: a discovery layer centered on SKILL.md; a navigation layer with one index.md per directory; and a knowledge layer containing documents with YAML frontmatter for topic, type, provenance, and lifecycle. The design follows the Open Knowledge Format (OKF) and the Skill protocol without modifying the agent framework. We also provide knowledge-as-skill, a pipeline for converting heterogeneous collections of PDFs, Word files, web exports, and notes into this structure.   In a preliminary evaluation on the WixQA enterprise customer-support benchmark, our setup obtains 0.889 Factuality and 0.816 Context Recall, compared with reported Corpus2Skill values of 0.767 and 0.708. It obtains slightly lower Faithfulness, lower Context Precision, and more interaction turns. Because the models, prompts, and knowledge-package construction differ, these results are directional cross-work evidence rather than a controlled comparison.

# 论文总结：Knowledge-as-Skill —— LLM 智能体自主使用知识库的结构化设计

## 1. 论文的核心问题与整体含义
- **研究背景**：传统 RAG 采用“检索—拼接—生成”的固定流程，由系统替模型决定是否检索、检索什么、注入多少内容，模型只是上下文接收者。
- **新趋势**：随着 LLM 工具使用和智能体循环更加可靠，检索决策权可以下放给智能体本人。
- **核心问题**：当智能体可以自主决定是否检索时，暴露出一个被掩盖的瓶颈——**智能体不知道知识库究竟包含什么**。传统知识库把文档暴露为匿名文本块，缺少范围、用途、来源、关系等信息，不利于自主探索。
- **整体含义**：知识库需要面向智能体重新设计，使其具备清晰边界、结构、文档和访问协议，从而可以被智能体像“技能”一样理解和使用。

## 2. 论文提出的方法论
- **核心思想**：将知识库组织为“知识即技能”（Knowledge-as-Skill），使其满足三个要求：
  - 可发现（Discoverable）：智能体能判断知识库是否与当前任务相关。
  - 可导航（Navigable）：进入知识库后，能通过显式结构逐步缩小搜索范围，而非只依赖关键词到文本块的单一接口。
  - 自描述（Self-descriptive）：每个文档都带有主题、用途、类型、来源、新鲜度等元数据，供智能体在阅读正文前判断价值。
- **三层结构设计**：
  - **发现层**：根目录 `SKILL.md`，frontmatter 包含知识库名称、描述、类型等触发元数据；正文说明适用范围、排除项、导航规则、常见入口、新鲜度约定和停止条件。
  - **导航层**：每个目录一个 `index.md`，每个条目由“链接 + 一句话描述”组成，提供语义线索，支持渐进式定位。
  - **知识层**：具体文档以 YAML frontmatter 开头，必备字段为 `type`、`title`、`description`；可选字段包括 `tags`、`sources`、`generated`、`verified`、`stale_after` 等，用于主题、类型、来源、生命周期管理。根目录 `log.md` 记录更新历史。
- **设计原则**：
  - 分层暴露：不同文件提供不同信息粒度，上下文成本与相关性更匹配。
  - 自描述：文档在阅读前即可自我解释。
  - 入口与结构分离：`SKILL.md` 只描述范围和用法，不包含领域知识；索引独立维护知识结构。
- **典型端到端交互流程**：
  1. 智能体根据技能名称和描述判断是否匹配任务。
  2. 读取 `SKILL.md` 了解范围、导航规则和边界。
  3. 从根 `index.md` 开始，选择有希望的目录/知识束。
  4. 利用文档 frontmatter 预筛文档，再读取全文。
  5. 证据不足时继续跟踪相关索引，或判定问题超出知识库范围而停止。
  6. 综合实际阅读的文档生成答案，并参考生命周期元数据处理时效性问题。
- **构建流水线**：
  - 枚举源文件，保留已有 Markdown，并使用 `mdconvert`（包装 MarkItDown）将 PDF、Word 等格式转换为 Markdown，保持目录结构。
  - 为每个文档生成 frontmatter，记录原始来源和生命周期字段。
  - 为每个知识束生成 `index.md`，初稿可人工修订。
  - 生成根 `SKILL.md`。
  - 使用 `okfcheck` 验证 OKF 一致性；`-agent-ready` 检查发现文件、必需元数据和缺失索引。
- **遵循标准**：遵循开放知识格式（OKF）和 Skill 协议，**无需修改智能体框架**。

## 3. 实验设计
- **数据集 / 场景**：WixQA 企业客户支持基准，由 6,221 篇 Wix 帮助中心文章构建。
- **评估子集**：200 个专家编写的问题，每个问题包含问题文本、参考答案和 1–3 篇金标准文档。
- **对比方法**：主要与 contemporaneous 工作 **Corpus2Skill** 报告的结果进行方向性参考对比；未在同一环境下与固定 RAG 基线直接比较。
- **评估系统**：
  - 最小智能体循环，系统提示包含完整 `SKILL.md` 和任务指令。
  - 三个只读工具：`list_dir`、`read_file`、`submit_answer`。
  - 最大轨迹长度 15 轮。
  - 回答模型为 DeepSeek-Flash，评判模型为 K3。
- **评估指标**：
  - Token F1（SQuAD 风格 token 级比较）
  - Factuality（LLM 评判，五点量表归一化）
  - Faithfulness (grounded)
  - Context Recall
  - Context Precision
  - Hallucination Rate（原始 Faithfulness ≤3 的问题比例）
  - Turns（智能体平均交互轮次）

## 6. 主要结论与发现
- **优势指标**：
  - Factuality：0.889（Corpus2Skill 报告 0.767），提升 12.2 个百分点。
  - Context Recall：0.816（Corpus2Skill 报告 0.708），提升 10.8 个百分点。
  - Hallucination Rate：两者均为 4.5%。
- **代价指标**：
  - Faithfulness (grounded)：0.810（对方 0.859），略低。
  - Context Precision：0.761（对方 0.829），较低。
  - 平均轮次：4.015（对方 2.38），交互更长。
  - Token F1：0.412（对方 0.456），略低。
- **核心发现**：显式分层导航可能**扩大证据发现范围**（更高事实性和召回率），但代价是**更多中间阅读、更长交互路径、较低精确度和较低的 grounded faithfulness**。
- **总体结论**：这些结果表明该结构设计方向上有潜力，但**不能证明结构化组织本身因果性地导致了改善**，需要受控实验验证。

## 7. 优点
- **视角新颖**：针对智能体自主检索背景下的“知识库不可理解”问题，提出知识库的智能体导向重构。
- **结构清晰**：发现层、导航层、知识层三层分离，符合渐进披露原则，有助于控制上下文成本。
- **兼容性强**：遵循 OKF 和 Skill 协议，无需修改智能体框架，便于现有系统集成。
- **工程实用**：提供自动化构建流水线，支持 PDF、Word、网页导出、笔记等异构来源。
- **可审计性**：文档 frontmatter 包含来源、生成、验证、过期时间等字段，支持可追溯性和新鲜度敏感回答。
- **与 Corpus2Skill 互补**：强调可控性、可审计性和领域边界内的增量维护，而非完全自动化冷启动。

## 8. 不足与局限
- **实验覆盖不足**：仅一个数据集、无消融、无固定 RAG 基线、无多数据集验证，结论的泛化性有限。
- **对比不公平**：与 Corpus2Skill 的比较未控制模型、提示、构建流程等变量，只能作为方向性参考。
- **指标敏感**：Factuality、Faithfulness 等 LLM 评判指标受评判模型和提示影响较大；Token F1 对措辞敏感。
- **工程成本**：人工维护索引需要持续投入；描述可能不完整或有偏差；额外导航轮次增加延迟和上下文消耗。
- **自动化风险**：自动生成索引和元数据可能产生不准确的摘要或错误元数据。
- **未评估维度**：未测量延迟、token 成本、知识随时间变化的影响、多跳问题上的跨索引导航效果，以及结构化导航与传统检索的混合系统。
- **篇幅和深度**：论文仅 7 页，评估部分较为初步，许多问题留待未来工作。
