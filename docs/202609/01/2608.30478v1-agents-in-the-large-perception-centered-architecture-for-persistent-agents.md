## 摘要
认知语言智能体通过为语言模型配备记忆、工具和决策流程取得了实质性进展，使智能体能够在交互式环境中推理和行动。现有框架大多将这些智能体视为解决用户指定、有界任务的系统。一个日益重要的目标是让语言智能体在长期场景中提供持续协助，其中用户需求、上下文和服务流程持续存在并变化，并且在随时间出现的广泛任务中保持有用。然而，我们仍缺乏一个框架来刻画持久 AI 智能体、组织现有工作并指导未来发展。为此，我们提出了持久智能体的以感知为中心的架构（Pera）。Pera 描述了一种围绕感知与控制组件组织的持久智能体，这些组件持续从阶段性任务执行、内部上下文以及周围环境变化中感知与服务相关的信号，并利用这些信号构建生命周期任务。这些任务驱动智能体服务流程的持续运行与适应。我们使用 Pera 回顾性地梳理近期工作，考察详细案例研究，并为构建能力更强的持久智能体提供前瞻性见解。正如软件工程从小规模编程迈向大规模编程，Pera 将语言智能体的演进界定为一种类似的架构转变，迈向长期、自适应智能系统。

## Abstract
Cognitive language agents have achieved substantial progress by equipping language models with memory, tools, and decision-making procedures, enabling agents to reason and act in interactive environments. Existing frameworks largely cast these agents as systems for solving user-specified, bounded tasks. An increasingly important goal is for language agents to provide persistent assistance in long-lived settings where user needs, context, and service procedures persist and change, and to remain useful across the broad range of tasks that arise over time. Yet we still lack a framework to characterize persistent AI agents, organize existing work, and guide future development. To this end, we propose a Perception-Centered Architecture for Persistent Agents (Pera). Pera describes a persistent agent organized around perception and control components that continually perceive service-relevant signals from episodic task executions, internal context, and changes in the surrounding environment, and use these signals to construct lifecycle tasks. These tasks drive the ongoing operation and adaptation of the agent's service procedures. We use Pera to retrospectively organize recent work, examine a detailed case study, and offer forward-looking insights for building more capable persistent agents. Just as software engineering moved from programming in the small to programming in the large, Pera frames the evolution of language agents as an analogous architectural transition toward long-lived, adaptive intelligence systems.

## 2. 方法论：核心思想与关键技术细节

- **核心框架**：提出 **Pera（Perception-Centered Architecture for Persistent Agents）**，一种以感知为中心的持久智能体架构。
- **架构组成**：
  - **持久智能体核心（Persistent Agent Core）**：包含**生命周期感知（Lifecycle Perception）**与**控制平面（Control Plane）**。
  - **生命周期感知**：持续捕获并解释两类信号：
    - **外部信号**：来自人类、物理环境、数字环境的变化（如用户反馈、传感器数据、文件系统事件）。
    - **内部信号**：来自任务执行轨迹、内部上下文记忆、感知与控制组件自身的变化（如重复失败、上下文过时、组件缺陷）。
  - **控制平面**：解释信号，决定是否需要进一步证据或工作；若需要适应，则构建**生命周期任务包（lifecycle task package）**并调度执行。
  - **任务代理规范（Task Agent Specification）**与**任务运行时（Task Runtime）**：负责实例化具体任务并执行。
- **两类任务**：
  - **阶段性任务（Episodic task）**：追求有界的面向用户的结果，完成条件对应用户目标。
  - **生命周期任务（Lifecycle task）**：建立或恢复未来服务所依赖的持久条件，如更新过时上下文、修订不可靠流程、验证更新效果、为新兴需求做准备。
- **关键动作空间**（Action Space）：
  - **感知（Sensing）**：主动监控外部与内部信号。
  - **调度（Dispatching）**：决定任务何时进入执行（立即、延迟、等待依赖或授权）。
  - **实例化（Instantiation）**：将可复用的代理规范绑定到具体任务，生成任务运行时。
  - **推理（Reasoning）**：对已有信息进行变换。
  - **检索（Retrieval）**：从内部上下文读取相关信息。
  - **更新（Updating）**：修改内部状态或实现（上下文、模型参数、源代码、工具、传感器等）。
  - **接地（Grounding）**：通过工具、通信或具身动作与外部环境交互。
- **生命周期级决策流程**：**处理（Processing）→ 构思（Formulation）→ 执行（Execution）→ 审查（Review）**。
  - 处理：将信号转化为领域特定语言描述的感知条件。
  - 构思：确定是否需要生命周期工作，并构造任务包（含目标、完成标准、任务专用流程、上下文、恢复机制、审查标准）。
  - 执行：通过任务级决策重复规划-行动循环。
  - 审查：评估执行轨迹、结果与持久效果，决定接受、修订或回滚更新；审查结果可产生新的内部信号，形成闭环。

## 6. 主要结论与发现

- **持久智能体的架构转变**：智能体设计焦点应从单一任务执行转向持续服务，感知是闭合跨任务可观察性缺口的关键。
- **生命周期任务的作用**：感知到的变化只有通过生命周期任务才能转化为影响未来服务的具体干预。
- **感知与控制的闭环**：生命周期感知使长期设置可观察，控制平面决定哪些变化需干预，任务运行时执行干预，审查阶段评估持久效果并产生新信号。
- **案例研究结论**：与任务中心、记忆增强、传感器接地、上下文感知主动系统相比，Pera 能同时保持跨任务上下文、感知长期变化并将变化转化为持久适应，从而在未来任务到来前更新共享服务程序。
- **前瞻方向**：提出六个可行动方向：
  1. 自适应感知（决定感知什么、何时、如何感知）。
  2. 信号表示（领域特定信号语言与跨信号聚合）。
  3. 上下文学习（从现实世界上下文学习新知识与时间有效性）。
  4. 主动性超出现有任务（发现并决定如何响应未来需求）。
  5. 生命周期控制（跨任务协调、生命周期感知调度、变更接受规范）。
  6. 代理自我改进（模型与脚手架/harness 的协同进化、安全自改进）。
