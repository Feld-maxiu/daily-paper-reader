## 摘要
自动生成的环境为训练通用智能体提供了可扩展的交互数据来源。然而，现有方法主要在单一环境内生成任务，而现实工作流要求智能体跨多个服务连接信息和动作。我们引入了组合式环境扩展（CompoWorld），通过组合有限的可重用服务库来扩展任务空间。编码智能体将工具规范转化为具有类型化状态和共享接口的已验证服务，而世界模型处理无法可靠实现的工具。随机游走过程通过依赖图连接服务，从而能够生成和验证需要信息在服务间流动的任务。经过验证的轨迹支持监督微调（SFT），而我们的以完成为导向的评分规则奖励通过强调每个 rollout 组内通过率较低的标准，引导强化学习（RL）实现完全任务完成。我们构建了 448 个服务，提供了 10,130 个工具，并使用 3K 条 SFT 轨迹和 1K 个 RL 任务来训练 Qwen3.6-35B-A3B。实验结果表明，CompoWorld 在八个基准上平均比其骨干模型提高了 9.17 分。在 AutomationBench 上，它超越了 Claude Opus 4.6 等前沿模型，并在所有比较的智能体专用 35B-A3B 模型中处于领先地位。

## Abstract
Automatically generated environments provide a scalable source of interaction data for training general agents. However, existing approaches mainly generate tasks within a single environment, while real-world workflows require agents to connect information and actions across multiple services. We introduce Compositional Environment Scaling (\textbf{CompoWorld}), which expands the task space by composing a finite library of reusable services. Coding agents turn tool specifications into verified services with typed states and shared interfaces, while a world model handles tools that cannot be reliably implemented. A random-walk procedure connects services through dependency graphs, enabling the generation and verification of tasks that require information to flow across services. Verified trajectories support supervised fine-tuning (SFT), while our Completion-Focused Rubric Reward guides reinforcement learning (RL) toward full task completion by emphasizing criteria with lower pass rates within each rollout group. We construct 448 services exposing 10,130 tools and use 3K SFT trajectories and 1K RL tasks to train Qwen3.6-35B-A3B. Experimental results show that CompoWorld improves on its backbone by 9.17 points on average across eight benchmarks. On AutomationBench, it surpasses frontier models such as Claude Opus 4.6 and leads all compared agent-specialized 35B-A3B models.

## 1. 论文的核心问题与整体含义

- **研究背景**：通用智能体（LLM agents）的训练需要大规模、可验证的交互环境。已有工作（如 AgentScaler、ScaleEnv、Agent-World）主要通过在**单一环境内**自动构建任务来扩展环境，但真实世界的工作流通常要求智能体**跨多个服务/系统**传递信息并协调动作（例如查询数据库 → 阅读 PDF 手册 → 发送邮件通知）。
- **核心问题**：如何把“环境扩展”从只增加单一环境数量，提升到**组合式环境扩展**——即通过组合有限的、可复用的服务，生成大量具有跨服务依赖关系的可验证任务。
- **整体含义**：提出 **CompoWorld**，将服务组合本身作为环境扩展的可控维度，用有限的服务库支撑远大于服务数量的跨服务工作流，从而训练智能体在新组合中复用熟悉技能，促进组合泛化。

## 2. 论文提出的方法论

- **总体框架**：CompoWorld 分为三部分：
  1. **构建单个可执行服务**；
  2. **生成并验证跨环境任务**；
  3. **利用任务进行 SFT + RL 训练**。

- **服务构建**：
  - 通过网络爬取收集 MCP 工具规范，归一化为统一函数调用格式；
  - 编码智能体（coding agent）在隔离沙箱中为每个服务推断实体、用 **Pydantic 模型**定义类型化状态，并实现工具；
  - 通过自生成测试 + 独立对抗性测试验证工具；
  - 无法可靠本地实现的工具由 **LLM 世界模型**模拟状态转移和观测，约占全部工具的 7.1%；
  - 最终得到 **448 个服务、10,130 个工具**，覆盖 13 个领域。

- **跨环境任务生成与验证**：
  - 从服务池采样 K 个服务形成产品环境 \(E_C = \bigotimes_{E_i \in C} E_i\)；
  - 使用**随机游走**构造服务级依赖图 \(G=(C,D)\)，约束包括：覆盖所有选中服务、连续访问不能是同一服务、访问长度 \(L > K\) 且至少一次重访；
  - 编码智能体在 **EXPLORE → DESIGN → PROBE → SUBMIT** 四个阶段中构建初始状态、用户指令、评分 rubric、可执行终态验证器，并通过真实工具调用验证参考解可达。

- **训练方法**：
  - **SFT**：使用已验证的成功轨迹进行监督微调；
  - **RL**：采用 GRPO；
  - 提出 **Completion-Focused Rubric Reward**：
    - 对每个 rollout 组中的每条轨迹，计算每个 rubric 条件的组内通过率 \(p_j\)；
    - 条件权重 \(w_j = \lambda + (1-p_j)\)，通过率越低权重越大；
    - 轨迹奖励 \(R_i = \frac{\sum_j w_j b_{ij}}{\sum_j w_j}\)，其中 \(b_{ij}\) 表示轨迹 i 是否满足条件 j；
    - 该奖励强调尚未可靠完成的子目标，比平均 rubric 奖励更有利于推动完整任务完成；
    - 梯度分析证明 \(1-p_j\) 正好是控制各项梯度权重的“完成缺口”。

## 7. 优点

- **新颖且可扩展的框架**：将服务组合作为环境扩展的一等公民，能够生成大量跨服务、可验证的训练任务。
- **类型化状态与统一接口**：Pydantic 状态模型 + 命名空间工具保证不同服务可组合、状态更新类型安全。
- **混合执行策略**：确定性代码 + 选择性世界模型模拟，平衡环境保真度与工具覆盖范围。
- **任务生成与验证闭环**：随机游走依赖图 + 四阶段 agentic 生成 + 可达性验证，保证任务有真实解且 rubric 可执行。
- **针对部分完成问题的奖励设计**：Completion-Focused Rubric Reward 通过组内通过率动态加权，比 uniform rubric 更能推动完整任务完成，且附有梯度解释。
- **大规模语料与多基准验证**：448 个服务、10,130 个工具，在 8 个高难度基准上全面评估，包含领域级分析。
- **透明的示例与附录**：提供完整工具轨迹、环境代码示例和奖励分析，便于理解与复现。
