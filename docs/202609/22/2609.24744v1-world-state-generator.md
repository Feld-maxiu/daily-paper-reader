## 摘要
语言智能体通过计划与动作来解决复杂任务。世界拒绝的某一步会使目标无法达成，而智能体接下来做什么决定了任务成败。基于提示的规划器正是在这一点上失败：它们用新的措辞重写被拒绝的步骤，却遭遇同样的拒绝，并在毫无进展中耗尽尝试预算。它们失败的原因在于计划从未与世界绑定，因此拒绝无法对应到计划中的任何内容。世界是任务运行之处，具有自身的规则、允许的动作和约束。我们在 7 个领域构建合成世界，并从中提取训练数据。程序执行每个世界的规则并对其目标进行评分；只有目标能从初始状态可达的世界才会被接纳。智能体在这些世界中运行，留下经过验证的失败及其修复记录，这些修复将运行推进到世界所认证的状态，共约 226K 条轨迹。基于这些记录，我们训练了世界状态生成器（WSG），该模型将计划编写为可核查的世界状态，并使计划与其运行所在的世界保持一致。这种一致性正是用语言书写的计划所缺乏的，因为计划运行的世界具有物理限制、逻辑依赖和必需顺序，这些规则语言从未说明，计划只有在某个状态失败时才会遇到它们。WSG 将这种失败视为世界所陈述的规则，并重写剩余状态以遵守该规则，从而使计划在运行过程中顺应世界。在 7 个公开基准上，WSG 将两个参数规模接近 30B 的开源模型的端到端成功率提升到超过基于提示的方法，并达到专有模型的水平。

## Abstract
Language agents solve complex tasks through plans and actions. A single step the world refuses puts the goal out of reach, and what the agent does next decides the task. Prompted planners fail at exactly this point, rewriting the refused step in new words, meeting the same refusal, and burning the attempt budget without moving. They fail because the plan was never tied to the world, so a refusal has nothing in the plan to attach to. A world is where a task runs, and it has its own rules, its own admissible actions, and its own constraints. We build synthetic worlds across 7 domains and extract training data from them. A program enforces each world's rules and grades its goal, and every world is admitted only if its goal is reachable from its initial state. Agents run inside and leave verified failures paired with repairs that carried the run to a state the world certified, a record of about 226K trajectories. On this record we train the World State Generator, a model that writes a plan as checkable states of the world and keeps that plan aligned with the world it runs in. That alignment is what a plan written in language lacks, since the world it runs in has physical limits, logical dependencies, and required orders the language never states, and the plan encounters these rules only when a state fails. WSG takes that failure as the rule the world has stated and rewrites the remaining states to obey it, so the plan bends to the world as the run goes on. Across 7 public benchmarks, WSG raises end-to-end success for two open models near 30B parameters over prompting and brings to the level of proprietary model.

## 1. 论文的核心问题与整体含义

- **核心问题**：语言智能体在执行长周期任务时，计划中的某个步骤若被环境拒绝，后续行动往往失败。基于提示（prompted）的规划器只会用不同措辞重写被拒绝的步骤，再次提交后仍遭遇同样拒绝，导致尝试预算耗尽而任务失败。
- **根本原因**：计划从未与环境（世界）绑定，缺乏对工具、接口条件、前置约束的显式表示，因此环境拒绝无法对应到计划中的具体内容，无法进行有效修复。
- **整体含义**：将一次拒绝视为“世界陈述了一条被计划遗漏的规则”，修复意味着读取该规则并重写剩余计划。论文提出 **World State Generator（WSG）**，把计划写成可核查的世界状态，在失败时依据世界反馈动态调整剩余状态，使计划在运行过程中逐渐与世界对齐。

## 2. 论文提出的方法论

- **世界构建与数据采集**
  - 在 **7 个领域**（物理、软件、网页搜索、工具使用、约束、推理、数学）构建合成世界，每个世界由实体属性、动作规则、目标三元组 $W=(E,A,g)$ 定义。
  - 目标包含自然语言描述 $\ell_g$ 和程序可执行检查 $\chi_g$。
  - 每个世界必须通过**目标可达性验证**：只有从初始状态可达到目标的世界才被接纳，避免不可修复的失败。
  - 智能体在 **State-Centric Decision Process（SDP）** 运行时中运行，每个步骤被写成一个可验证的世界状态谓词。
  - 运行时包含四个操作：`PROPOSE`（写计划）、`REALIZE`（执行动作）、`VALIDATE`（验证状态）、`REPLAN`（失败后重写计划）。
  - 当某个状态被拒绝时，验证器记录观察到的实际状态，形成 refutation $\tau=(s_f,o_f)$，即失败状态与观察到的证据。
  - 只保留那些**被世界程序验证过至少一个状态**的修复链，形成训练对 $(x,C)$，其中 $x=(g,c,\tau)$ 为输入，$C$ 为从当前前缀到目标的状态链。

- **WSG 模型与训练**
  - WSG 是在开源近 30B 参数骨干模型（Gemma4-31B、Qwen3.6-27B）上，通过 **LoRA** 适配器进行监督微调。
  - 训练目标为最大化修复链的负对数似然：  
    $\mathcal{L}(\theta)=-\sum_{(x,C)\in\mathcal{D}}\sum_{t=1}^{|C|}\log p_\theta(C_t\mid x,C_{<t})$  
    输入 $x$ 中的 token 不计算损失。
  - 训练语料约 **238,563 个修复示例**，来自约 226,316 条运行轨迹。
  - 采样按领域平衡，概率 $p_d\propto n_d^{1/2}$，防止大领域主导。
  - 关键设计：**只训练修复调用（repair call）**，首计划仍由原骨干提示生成。因为首计划仅基于目标，缺乏失败证据，加入训练会导致模型过拟合、丧失原有规划能力。

## 3. 实验设计

- **训练数据来源**
  - 7 个合成领域，三个提取模型（Qwen3-32B、Qwen3.6-27B、Gemma4-31B）在相同世界集合上运行，共产生 226,316 个 episodes。
  - 其中 75.3% 的 episodes 至少有一个状态被世界拒绝，共产生 775,180 次修复调用，保留 238,563 个修复示例（通过率 30.8%）。

- **评估基准**
  - 7 个公开智能体基准，零样本评估（训练语料不包含这些基准的任何世界、任务或轨迹）：
    - τ²-bench
    - ScienceWorld
    - ToolSandbox
    - PlanBench-XL
    - REAL
    - DeepPlanning（Shop）
    - AgentBoard（PDDL）
  - 每个基准使用其自身指标（准确率、平均分、成功率等）。

- **对比方法**
  - **SDP 条件**：同一骨干对所有 proposer 调用使用提示（prompting）。
  - **WSG 条件**：同一骨干写首计划，之后所有修复调用由 WSG 处理；实现器（realizer）和验证器（validator）保持不变。
  - 还与已发布的专有模型结果（如 Gemini、GPT-4、Sonnet 等）进行比较。

- **主要结果**
  - WSG 在 7 个基准上全部提升，提升幅度在 **+3.4 至 +31.9 分**之间。
  - 例如 Qwen3.6-27B 在 PlanBench-XL 上从 16.1 提升到 48.0（+31.9），DeepPlanning 从 29.1 提升到 51.2（+22.1）。
  - 两个骨干在多数基准上达到或接近已发布专有模型的水平。

## 6. 论文的主要结论与发现

- 通过将计划写成可核查的世界状态，并利用验证过的失败-修复对训练修复调用，WSG 能显著提升修复能力和端到端成功率。
- **收益集中在遇到拒绝之后**：当提示规划器恢复困难时，WSG 提升最大，例如 DeepPlanning 和 ScienceWorld 的恢复率提升 66%–187%。
- WSG 不再简单改写被拒绝状态，而是保留该状态并**插入世界规则所指出的条件**（参数范围、可能需先启用的按钮、必须进入的房间等）。
- 训练数据来自合成世界，但学到的修复能力可**零样本迁移**到未见过的真实基准。
- 监督学习即可学习修复，前提是训练对包含世界反馈证据；修复数据不能来自成功轨迹或自我纠错，因为缺少外部验证证据。
- 未训练的实现器和验证器仍是主要失败来源，现实化器在正确状态前失败的占比约 45%，验证器误拒占比约 20%。

## 7. 优点

- **数据质量高**：失败与修复均经过世界程序验证，而非人工主观判断；世界目标可达性提前过滤不可修复任务。
- **方法定位精准**：只训练修复调用而非整个规划器，避免覆盖原有规划能力，有效利用失败证据。
- **可解释的状态表示**：计划是自然语言状态谓词，可逐步运行时验证，兼顾可判定性与灵活性。
- **跨域迁移能力强**：7 个合成领域训练，7 个公开基准零样本评估，证明模型学到了通用的“读拒绝、改计划”能力。
- **对比评估公平**：同骨干、同运行时、同预算，直接衡量训练修复调用带来的净增益。
- **开源模型提升显著**：近 30B 模型达到专有模型水平，降低部署门槛。

## 8. 不足与局限

- **实现器与验证器未训练**：大量剩余失败来自这两个组件的错误，限制了整体性能上限。
- **部分基准与最先进专有模型仍有差距**：PlanBench-XL 和 DeepPlanning 上最强系统仍明显领先。
- **训练语料依赖特定合成世界**：尽管零样本迁移成功，但领域覆盖和规则多样性有限，可能存在未覆盖的失败模式。
- **训练成本不低**：需要大规模世界模拟和轨迹采集，以及多 GPU 训练；数据采集算力未报告。
- **实验未包含强化学习对比**：论文讨论中提出可用奖励信号训练，但尚未实验。

- **仅两个骨干模型**：训练效果在更大或更小模型上的泛化性未知。
