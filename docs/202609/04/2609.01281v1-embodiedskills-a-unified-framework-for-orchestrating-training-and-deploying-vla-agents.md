## 摘要
视觉-语言-动作（VLA）模型将视觉观察和语言指令直接映射为机器人动作，但长程任务需要的不仅仅是动作预测。智能体必须随着物理状态的演化协调感知、规划、执行、进度验证与恢复。单个动作预测或模型生成的技能决策本身并不能保证所提议的操作在当前状态下有效，也不能保证其结果会得到验证。我们提出 EmbodiedSkills，一个统一框架，将每个技能决策视为一个执行提案：运行时在执行前检查其前置条件，并在执行后验证结果。一个共享的可执行技能接口在单一智能体循环中连接高层技能选择、有界的低层 VLA 执行和动作后验证。由于该接口保持固定，低层 VLA 策略可以在不改变智能体循环的情况下被替换或适配。该接口还将规划、执行、验证和恢复事件记录为结构化轨迹，为各个组件提供监督，并可在有交互反馈时支持可选的在线适配。我们在 RoboTwin 2.0 和 LIBERO 上使用 Qwen3-VL 和 OpenPI/pi0.5 实例化 EmbodiedSkills。任务适配的低层 VLA 策略在 50 个 RoboTwin 2.0 任务上平均成功率为 86.20%，在四个 LIBERO 套件上为 97.40%。这些结果确立了 EmbodiedSkills 中所使用的任务适配低层 VLA 策略的执行性能。在四个依赖记忆的 RMBench 任务上，相同的任务适配执行方法平均成功率为 12.5%。该框架提供了一个可训练且可检查的智能体层，用于将这些策略转变为闭环具身系统。

## Abstract
Vision-language-action (VLA) models map visual observations and language instructions directly to robot actions, but long-horizon tasks require more than action prediction. An agent must coordinate perception, planning, execution, progress verification, and recovery as the physical state evolves. An action prediction or a model-generated skill decision does not, by itself, guarantee that the proposed operation is valid in the current state or that its outcome will be verified. We propose EmbodiedSkills, a unified framework that treats each skill decision as an execution proposal: the runtime checks its prerequisites before execution and verifies the outcome afterward. A shared executable-skill interface connects high-level skill selection, bounded low-level VLA execution, and post-action verification within a single agent loop. Because this interface remains fixed, low-level VLA policies can be replaced or adapted without changing the agent loop. The interface also records planning, execution, verification, and recovery events as structured trajectories, which provide supervision for individual components and can support optional online adaptation when interactive feedback is available. We instantiate EmbodiedSkills with Qwen3-VL and OpenPI/pi0.5 on RoboTwin 2.0 and LIBERO. Task-adapted low-level VLA policies achieve an average success rate of 86.20% across 50 RoboTwin 2.0 tasks and 97.40% across the four LIBERO suites. These results establish the execution performance of the task-adapted low-level VLA policies used in EmbodiedSkills. On four memory-dependent RMBench tasks, the same task-adapted execution approach achieves 12.5% average success. The framework provides a trainable and inspectable agent layer for turning these policies into closed-loop embodied systems.

## 2. 论文提出的方法论

### 2.1 核心思想

- **策略与运行时分离**：高层策略只负责提出结构化的技能决策，运行时负责执行语义校验、状态一致性和结果验证。
- **可执行技能契约**：每个技能由类型化输入/输出、前置条件、执行函数、后置更新和失败映射组成。
- **共享技能接口**：连接高层技能选择、有界低层 VLA 执行和动作后验证，使低层策略可替换而不改变智能体循环。

### 2.2 关键技术细节

- **智能体状态**  
  定义为  
  \(s_t = (z_t, M_t, H_t)\)，  
  其中 \(z_t\) 为当前阶段，\(M_t\) 为任务工件集合，\(H_t\) 为有序循环轨迹。

- **六个阶段**  
  \(Z = (\text{Observe}, \text{Plan}, \text{Preflight}, \text{Execute}, \text{Verify}, \text{Recover})\)。  
  各阶段具有语义化的代表性操作，例如 Observe 负责采集当前视觉证据，Plan 构建可验证子目标，Preflight 检查执行就绪性，Execute 执行有界动作块，Verify 判断子目标进度，Recover 生成修订后的执行上下文。

- **结构化技能决策**  
  策略从状态相关的动作集合中选择：  
  \(d_t \in \{ \text{RunSkill}(k, q), \text{AdvanceStage}, \text{FinishRun} \}\)。  
  每个决策经过运行时守卫校验，避免无效操作转化为物理动作。

- **守卫式运行时转换**  
  对技能提案、阶段前进和终止分别定义守卫函数：
  - \(G_{skill}\)：检查技能是否属于当前阶段、输入是否满足前置条件等。
  - \(G_{advance}\)：检查当前阶段是否产生后继阶段所需证据。
  - \(G_{finish}\)：终止控制。
  
  被阻断的决策会被记录为显式证据，供后续决策使用。

- **有界动作执行**  
  低层 VLA 策略根据活动子目标、当前观察、机器人状态和预检证据，生成有界动作块：  
  \(a_t = (\tau_t, U_t, H_t, \eta_t)\)。  
  运行时校验动作类型、维度、数值有效性、执行视野以及与当前子目标和观察的一致性。一个语义子目标可以通过多个有界动作块完成，每个块执行后重新采集证据。

- **验证与恢复**  
  Verify 阶段基于最新动作后的证据，预测语义路线：  
  \(V = \{\text{Advance}, \text{Continue}, \text{Reobserve}, \text{Replan}, \text{Recover}, \text{Finish}\}\)。  
  如果验证失败，进入 Recovery 阶段，生成修订后的执行上下文并再次通过守卫检查。

- **训练方法**
  - **组件级监督适应**：规划器、调度器、验证器和低层 VLA 策略可独立训练，低层策略通过子任务级演示微调。
  - **部署一致样本**：训练样本与部署时组件输入边界一致，避免使用测试时不可见的信息。
  - **可选在线适应**：当有交互反馈和可靠环境评估器时，可用 GRPO 风格的归一化优势和带掩码的截断目标进行在线策略优化，但论文将其定位为可选细化机制，并非主要结果来源。

## 7. 优点

- **清晰的策略-运行时分离**：使高层决策、低层执行和验证职责明确，失败可追踪、可诊断。

- **组件独立训练与替换**：规划器、调度器、验证器、低层 VLA 策略可以在不改动整个循环的情况下独立优化或替换。
- **跨基准验证**：在 RoboTwin 2.0、LIBERO 和 RMBench 上均进行了评估，体现接口的通用性。
- **消融实验设计合理**：分离了子任务条件、验证和多动作块三个核心机制的作用，为设计选择提供了直接证据。
- **结构化轨迹接口**：为后续离线训练、在线适应和失败分析提供了统一数据格式。

## 8. 不足与局限

- **任务适应成本高**：RoboTwin 2.0 上为每个任务单独微调一个 \(\pi0.5\) 策略，训练、存储和部署开销大，缺乏单一通用策略的简洁性。
- **整体性能仍受两层限制**：高层规划/验证和低层动作生成相互依赖，任一层失败都会影响最终成功率。
- **延迟增加**：额外的视觉语言模型调用、预检、后动作观察和验证会带来比单步动作策略更高的推理延迟。
