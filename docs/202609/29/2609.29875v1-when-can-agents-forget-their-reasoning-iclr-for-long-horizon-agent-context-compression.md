## 摘要
长时程语言模型智能体不断积累推理历史，即使早期决策已经执行并被观察，上下文长度和推理成本仍会增加。与静态思维链压缩不同，删除历史推理可能会改变未来动作以及由此产生的交互轨迹。我们研究何时可以安全地遗忘这些推理。我们提出面向长时程推理的交互感知压缩（ICLR），一种无需训练的在线方法，在保留动作、工具调用和观察的同时，利用冻结代理熵对推理块进行排序。在260个WorkBuddyBench任务上，ICLR将平均奖励从0.699提高到0.718，同时将输入、输出和缓存读取token分别减少25.5%、14.4%和33.3%。消融研究揭示了轨迹放大效应，即局部推理删除通过改变后续交互而导致总计算量发生非线性变化。表征探测、激活修补和受控轨迹分析进一步表明，一旦与任务相关的派生状态被可靠地外化到代码、文件、工具输出或环境反馈中，历史推理就变得更具可替换性。这些结果表明，智能体推理应被视为动态工作状态，而非永久交互历史。

## Abstract
Long horizon language model agents continually accumulate reasoning history, increasing context length and inference cost even after earlier decisions have been executed and observed. Unlike static Chain of Thought compression, removing historical reasoning can change future actions and the resulting interaction trajectory. We study when such reasoning can be safely forgotten. We propose Interaction Aware Compression for Long Horizon Reasoning (ICLR), a training free online method that ranks reasoning blocks using frozen proxy entropy while preserving actions, tool calls, and observations. On 260 WorkBuddyBench tasks, ICLR improves average reward from 0.699 to 0.718, while reducing input, output, and cache read tokens by 25.5%, 14.4%, and 33.3%, respectively. Ablations reveal trajectory amplification, where local reasoning deletion produces nonlinear changes in total computation by altering subsequent interaction. Representation probing, activation patching, and controlled trajectory analyses further suggest that historical reasoning becomes more replaceable once task relevant derived state has been reliably externalized into code, files, tool outputs, or environmental feedback. These results characterize agent reasoning as dynamic working state rather than permanent interaction history.

## 1. 论文核心问题与整体含义

- **研究背景与动机**：长时程语言模型智能体会在“推理—动作—环境反馈”的闭环中不断累积历史推理 token。即使早期决策已经执行并被观察，其推理文本仍会在后续请求中反复出现，导致上下文长度、推理延迟和缓存读取成本持续上升。
- **核心问题**：智能体的历史推理在何种条件下可以被安全删除？与静态思维链压缩不同，智能体环境中的推理删除会改变未来的动作、工具调用、观察和终止决策，属于“闭环决策干预”，而非单纯的文本精简。
- **整体含义**：论文主张智能体推理应被视为**动态工作状态**，而非永久交互历史。一旦任务相关的派生状态（计划、约束、结论、中间关系）被可靠地外部化到代码、文件、工具输出或环境反馈中，原始推理的必要性就会显著下降，甚至可以被替换。
- **主要贡献方向**：提出一种无需训练的在线推理压缩方法 ICLR；系统刻画“轨迹放大”现象；通过表征探测、激活修补和受控轨迹分析解释历史推理何时不再必要。

## 2. 方法论

- **核心思想**：在每个交互步结束后，只压缩刚完成的推理部分，同时**完整保留动作、工具调用、工具输出、观察和最终答案**；利用一个冻结的代理语言模型估计每个推理块的预测熵，优先删除低熵（即高可预测性）块。
- **交互步定义**：  
  \(S_t = (R_t, A_t, O_{t+1})\)，其中 \(R_t\) 为推理，\(A_t\) 为动作或工具调用，\(O_{t+1}\) 为环境观察。压缩前历史为  
  \(H_k = (P, S_1, \dots, S_{k-1})\)，P 为系统提示、工具定义和任务指令。ICLR 执行 \(H_k \rightarrow \tilde{H}_k \rightarrow A_k \rightarrow O_{k+1} \rightarrow H_{k+1}\)。
- **块划分**：推理按双换行符切分为非空块 \(R_t=(B_1,\dots,B_N)\)；当 \(N=1\) 时不删除。
- **代理熵计算**：使用冻结模型对每个 token 的下一个 token 分布计算香农熵：  
  \(h_t=-\sum_{v\in V} p_\theta(v\mid c_t)\log_2 p_\theta(v\mid c_t)\)，  
  块的得分为其 token 熵的均值 \(H(B_i)=\frac{1}{|B_i|}\sum_{t\in B_i} h_t\)。熵越低，说明在该上下文下预测越确定。
- **上下文条件排序**：打分器接收系统提示、工具定义、累积历史和当前完整步骤作为上下文，因此同一个推理块的得分会随任务状态变化，而非孤立评分。
- **删除规则**：在 N 个非空块中删除熵最低的 \(\lfloor 0.8N\rfloor\) 个块，用 `[SKIP]` 占位，保留块原序。推理历史一经写回便持续用于后续请求，不恢复。
- **执行与打分模型**：任务执行模型为 DeepSeek-V4-Flash；代理打分模型为冻结的 Qwen3.5 9B。打分器上下文上限为 42K token，超出时该步跳过压缩。
- **消融变体**：
  - **Step Only Entropy**：仅用当前步推理计算熵，不含更早轨迹上下文。
  - **Delete All Thinking**：删除完整推理但保留动作和观察。
  - **Random \(r\)**：随机删除固定比例 \(r\in\{5\%,10\%,20\%,40\%\}\) 的推理 token。
- **分析工具**：
  - **未来必要性探测**：在线性探针中，用当前隐藏状态预测后续是否发生重推导、额外推理或显式重规划；采用任务级嵌套划分避免泄漏。
  - **激活修补**：将删除历史条件下的残差替换为完整历史条件下的残差，计算 KL Repair，衡量对完整历史下一 token 分布的恢复程度。
  - **状态外化分析**：判断任务相关派生状态是否已写入代码、文件、工具输出或环境反馈；比较“仅存于推理中”与“已外化”状态下的未来行为风险。
  - **受控状态干预**：固定状态延续，分别保留/删除最新推理、在代码写盘后清除推理、隐藏/保留已观察环境反馈，观察后续决策变化。

## 3. 实验设计

- **数据集 / 场景**：
