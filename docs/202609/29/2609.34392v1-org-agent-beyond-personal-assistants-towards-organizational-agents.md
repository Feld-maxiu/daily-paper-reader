## 摘要
服务于组织的语言模型智能体必须协调来自多个用户的请求，同时利用分散在其交互过程中的知识。我们识别出该场景下两种互补能力：跨用户交互与决策，以及跨用户记忆与知识使用。这两种能力均受到组织约束的制约，涉及三个方面：用户身份、权限与访问许可；信息的归属与时效性；以及解决跨用户需求冲突的规则和联合决策的完成要求。这些约束决定了在行动继续之前必须获取哪些信息或决策，以及在执行过程中必须满足哪些条件。受此启发，我们提出了 Org-Agent，一个统一的以约束为中心的推理框架，将任务执行组织为三个阶段。具体而言，Org-Agent 将任务分解为原子子任务，并构建任务依赖图，其边编码子任务之间的依赖关系。在该图的基础上，它通过拓扑排序按依赖顺序调度子任务。然后，在执行每个子任务时考虑任务约束，并由证据获取和记忆管理工具提供支持。在 MUSES-Bench 和 GroupMemBench 上的实验证明了 Org-Agent 在这两种能力上的有效性，消融实验进一步支持依赖建模和工具使用的贡献。

## Abstract
Language model agents serving organizations must coordinate requests from multiple users while using knowledge distributed across their interactions. We identify two complementary capabilities for this setting, namely cross-user interaction and decision-making, as well as cross-user memory and knowledge use. Both capabilities are governed by organizational constraints across three aspects: user identity, authority, and access permissions; the attribution and temporal validity of information; and rules for resolving conflicting requirements across users and completion requirements for joint decisions. These constraints shape what information or decisions must be obtained before an action can proceed and what conditions must be satisfied during its execution. Motivated by this, we introduce Org-Agent, a unified constraint-centric reasoning framework that organizes task execution in three stages. Specifically, Org-Agent decomposes a task into atomic subtasks and constructs a task dependency graph whose edges encode the dependencies among them. Building on this graph, it schedules the subtasks in dependency order through topological sorting. It then executes each subtask while accounting for the task's constraints, supported by evidence-acquisition and memory-management tools. Experiments on MUSES-Bench and GroupMemBench demonstrate the effectiveness of Org-Agent on both capabilities, and ablations further support the contributions of dependency modeling and tool use.

## 2. 论文提出的方法论

- **总体框架**：Org-Agent 是一个**约束中心的推理框架**，将任务执行分为三个阶段：任务依赖图构建、依赖感知调度、约束感知节点执行。
- **阶段一：任务依赖图（TDG）构建**
  - 将当前待处理请求分解为**原子子任务**，每个子任务对应图中的一个节点。
  - 定义三类节点：
    - **inquiry 节点**：从交互历史检索记录或向用户请求信息；
    - **decision 节点**：做出任务特定决策（如接受/拒绝指令）；
    - **response 节点**：回复用户请求。
  - 边表示依赖关系，即执行某节点需要另一节点的输出。
  - 构建过程包含三步：子任务分解、依赖识别（LLM 完成，并检查/修正环）、图更新（新用户输入可触发局部更新或重建）。
- **阶段二：依赖感知调度**
  - 对有向无环图进行**拓扑排序**，得到执行顺序，确保每个节点在其所有前驱节点完成后执行。
  - 支持顺序执行或分层并行执行（同一层节点无依赖可并行）。
- **阶段三：约束感知节点执行**
  - 每个节点根据其执行上下文（节点目标、相关用户信息、相关约束、记忆内容）调用 LLM 和工具集完成任务。
  - 执行动作：`a_j = Execute(v_j, C_j, F)`，其中 `C_j` 是组装后的上下文，`F` 是工具集。
  - **证据获取工具**：
    - 相似度评分：结合 BM25 词汇相关性和稠密向量语义相似度（权重 α）；
    - 条件过滤：按元数据（作者、角色、项目阶段、话题、渠道等）筛选记录；
    - 关系遍历：从指定记录沿显式链接（回复、被回复、后续决策等）追踪。
  - **记忆管理工具**：
    - 维护执行记忆 `M`，保存累积信息和中间结果；
    - 读操作组装节点上下文：`C_j = Assemble(C_base_j, Read(M))`；
    - 写操作在执行后更新记忆：`M ← Write(M, a_j, o_j)`。
  - 记忆可以是结构化记录/字段，也可以是运行摘要，由 LLM 更新。

## 6. 论文的主要结论与发现

- Org-Agent 在 GroupMemBench 上平均准确率达到 **44.03%**，显著优于所有基线：比 BM25 高 6.31 个百分点，比最强记忆系统 Hindsight 高 5.24 个百分点。
- 现有智能体记忆系统（MemGPT、LightMem、SimpleMem 等）在跨用户记忆任务上并不始终优于基础检索基线 BM25，说明简单压缩或存储可能丢失关键上下文。
- Org-Agent 在 MUSES-Bench 上平均得分对三个骨干模型均有提升：GPT-4o-mini +8.27、DeepSeek-V4.1-Flash +4.24、Qwen3-32B +5.29；其中 Meeting 任务提升最大（GPT-4o-mini 上 +23.15）。
- 消融实验表明，依赖感知调度和约束感知工具（条件过滤、关系遍历、记忆管理）对性能均有贡献，移除任一部分都会导致分数下降。
- 随用户数增加，Org-Agent 的性能下降速度明显慢于 vanilla 基线（斜率更平缓），说明框架能更好地应对协调负担。
- 在不同骨干（Qwen3-8B）上仍保持优势；超参数 α=0.5（平衡词汇与语义）效果最佳；Org-Agent 以中等 token 成本（5.5M）实现最高准确率，远低于 Hindsight（117.5M）和 LightMem（21.6M）。

## 7. 优点

- **约束显式建模**：将用户身份、权限、信息时效、冲突解决等组织约束纳入统一的执行框架，而不是依赖模型隐式推理。
- **任务依赖图 + 拓扑调度**：动态构建 TDG，保证先决条件满足，支持分层并行，适合多轮多用户协调。
- **工具增强执行**：证据获取工具（相似度、条件过滤、关系遍历）和记忆管理工具（读写执行记忆）提升检索精度和跨节点信息复用。
- **模型无关**：在 GPT-4o-mini、DeepSeek、Qwen3 等多个骨干上均有效，尤其能补偿较弱骨干的推理不足。
- **成本效益高**：查询时动态构建依赖图，无需预先构建全局记忆图或索引，token 消耗显著低于图/记忆构建类基线。
- **实验全面**：覆盖两个基准、多个基线、消融、规模、超参数、成本与案例，验证充分。

## 9. 可改进方向与未来工作

- **引入更强的验证与自检机制**：对 LLM 生成的 TDG 增加符号规则校验、图完整性检查（无环、连通性、节点类型合法），并对分解错误进行自动修复或人工反馈循环。
- **扩展用户规模与真实组织数据**：将用户数扩展到 100+，并在真实组织协作数据（如 Slack、邮件、工单系统）上评估，验证约束感知框架在大规模并发下的可扩展性。
- **优化成本与延迟权衡**：研究分层缓存、记忆压缩、TDG 复用和工具调用批处理，降低长对话中的 token 开销与首字延迟，尤其针对开源本地骨干。
- **融合置信度与主动询问**：对记忆检索结果引入置信度估计，当证据不足或冲突未解决时主动向相应用户确认，避免在不满足完成要求时强行决策。
- **跨骨干与跨任务的系统对比**：在更多 LLM 与更多组织任务（如权限审批流、预算分配、多方谈判）上检验框架的通用性，并建立统一的 org-agent 评测协议。
