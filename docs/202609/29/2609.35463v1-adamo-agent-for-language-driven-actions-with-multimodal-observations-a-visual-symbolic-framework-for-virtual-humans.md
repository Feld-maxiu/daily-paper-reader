## 摘要
创建可信的虚拟人需要将感知、推理和以语言为媒介的动作连贯地整合起来。一个核心挑战是将这些组件结合到以交互式三维环境为基础的控制回路中。为此，我们提出 A.D.A.M.O.（语言驱动动作与多模态观测智能体），这是一种面向语言驱动虚拟人的视觉-符号框架，利用预训练的视觉语言模型（VLM）及工具调用能力，在单一控制回路中统一感知、推理和动作。A.D.A.M.O. 维护一个视觉-符号双重世界模型，结合自我中心视觉输入和同步符号状态，以支持从自然语言提示出发的具身任务导向行为。为支持诊断性评估，我们引入了一个受控任务套件，其按照 CD 分类法组织，将空间任务分解为程序复杂性和语言复杂性。在受控场景中的实验表明，语义标注会显著影响任务完成情况和失败模式，在降低感知歧义的同时使失败更多转向下游执行，而推理错误则相对较少。

## Abstract
Creating believable vh requires the coherent integration of perception, reasoning, and action mediated by language. A central challenge is to combine these components into a control loop grounded in interactive 3D environments. To this end, we present A.D.A.M.O. (Agent for language-Driven Actions with Multimodal Observations), a visual-symbolic framework for language-driven vh that leverages a pretrained vlm with tool calling to unify perception, reasoning, and action within a single control loop. A.D.A.M.O. maintains a dual visual-symbolic world model that combines egocentric visual input and synchronized symbolic state to support grounded task-oriented behavior from natural language prompts. To support diagnostic evaluation, we introduce a controlled task suite organized by a cd taxonomy that breaks down spatial tasks into procedural and linguistic complexity. Experiments in controlled scenes show that semantic labeling strongly influences task completion and failure modes, reducing perceptual ambiguity while shifting failures toward downstream execution, whereas reasoning errors remain comparatively rare.

## 1. 核心问题与整体含义

- **研究背景**：创建可信虚拟人（Virtual Humans, VHs）需要将感知、推理和以语言为媒介的动作连贯地整合在一起，并嵌入可交互的 3D 环境中。
- **现有局限**：
  - 具身对话智能体（ECA）语言交互能力强，但缺乏 3D 空间感知和物体操作等具身基础。
  - 经典通用智能体（GCA）通过强化学习获得稳健控制，但多基于符号状态，语言和视觉基础较弱。
  - 近期 LLM 驱动的具身智能体虽集成语言与动作，但在动态 3D 场景中紧密耦合视觉观测、符号推理与具身控制仍十分困难。
- **整体含义**：本文提出 A.D.A.M.O. 框架，目标是利用预训练视觉语言模型（VLM）和工具调用能力，在单一决策回路中统一感知、推理与动作，从而为语言驱动的虚拟人提供一种系统级、可解释的控制方案。

## 2. 方法论

### 2.1 总体架构

- 采用 **Perceive–Reason–Act（感知—推理—动作）** 闭环，基于 ReAct 框架实现。
- 仿真引擎拥有完整世界状态，而智能体仅通过自我中心感知获得**部分、序列化**的局部信息。
- 核心模块：
  - **Thought**：VLM 生成结构化推理笔记（显式中间推理痕迹），然后选择具体工具。
  - **Act**：以工具调用形式执行动作，调用 `Look`、`Walk`、`Pick`、`Drop` 四种原语；仿真引擎保证物理一致性（如自动重定位）。
  - **Observation**：融合感知信息和动作反馈，形成下一轮输入。

### 2.2 双重视觉—符号世界模型

- **视觉流**：RGB 帧 + 物体标签 + 可交互对象的边界框 + 投影到相机视图的稀疏参考点（6×6 网格射线投射，提供稳定 3D 空间锚点）。
- **符号流**：结构化文本，包含当前可交互对象列表（与视觉标签一致）、3D 坐标、物体体积、参考点位置、智能体位姿（`agent state`）。
- **执行反馈**：上一次工具调用的总结，如成功、失败或自动纠偏。

### 2.3 多模态短期记忆（MSTM）

- 使用 ChatML 消息结构组织角色：`system`、`AI`、`tool`、`human`。
- 内容构成：
  - 固定指令（行为规则、工具语义）。
  - 动态更新的符号状态。
  - 滚动缓冲区：保留最近 `k=50` 步的人类消息（初始提示 + 自我中心图像）、AI 消息（推理笔记 + 工具调用）和工具消息（环境反馈）。

### 2.4 基础设施与执行流程

- **Runtime Engine**（Unity）：管理 3D 环境、渲染、物理和 I/O；内嵌 Action Server，将高层工具调用转为 Unity 可执行操作。
- **Cognitive Server**（Python）：编排 Thought–Act–Observation 回路，维护提示构建、记忆更新和工具调用。
- **VLM Inference Server**：统一接口访问预训练 VLM/LLM。
- 执行流程：任务提示和初始观测 → Cognitive Server 组装多模态提示 → VLM 返回工具调用或终止决定 → Action Server 执行并返回新观测 → 更新 MSTM → 循环直到任务完成。

## 3. 实验设计

### 3.1 场景与任务

- 定义 **15 个自包含 episode**，每个 episode 由三元组 `(S, T, C)` 组成：
  - `S`：3D 场景、物体布局和智能体初始位姿。
  - `T`：自然语言任务提示（如“拿起黑色物体并放到球形物体附近”）。
  - `C`：确定性任务完成度检查器，输出归一化分数 `[0,1]`。
- **两个场景**均含 19 个可交互对象：
  - **S1**：桌面场景，所有物体放在一张桌子上。
  - **S2**：客厅场景，物体分散在多件家具上，空间布局更复杂。
- 任务提示结合基本操作（`pick`、`place`）与空间约束（`near`、`on`），难度通过 C-D 分类法量化。

### 3.2 Capability–Difficulty（C-D）分类法

- 将每个任务分解为三类单元并赋分：
  - **ACT**：操作原语数量（`pick`/`drop` 各 1 分）。
  - **REF**：识别目标对象所需描述成本（数字 ID=0、语义标签/名称=1、颜色=1、形状=2、分组过滤=2、图案=3、极值=3）。
  - **REL**：空间约束成本（地板=1、邻近物体=2、指定区域=4）。
- 任务 C-D 等级为各单元成本之和，范围从 T1 的 1 到 T15 的 20。

### 3.3 对比条件与评估指标

- **模型骨干**：GPT-4o-vision（G4O）与 Claude-Sonnet-3.5（S35）。
- **标注方案**：
  - **SEM**：语义标签，包含类别和实例信息。
  - **OPAQ**：仅使用数字 ID 的不透明标签。
- **重复与采样**：每个 VLM × 标注方案下，每个 episode 执行 15 次，单次上限 10 分钟；解码使用贪心采样（temperature=0.0, top-p=0.0）。
- **评估指标**：完成率（CR）、工具调用次数、每次调用耗时、Walk/Look/Pick/Drop 动作计数。
- **消融实验**（在 S1 + G4O + SEM 下进行）：MSTM 缓冲区大小、VLM 采样参数、3D 参考点密度、输入图像分辨率。

## 6. 主要结论与发现

- **语义标注是最主要的影响因素**：SEM 使完成率显著提升（G4O：0.48→0.88；S35：0.38→0.83），同时减少探索性 `Look` 动作和总动作数。
- **模型骨干影响效率与失败方式，而非整体可解决性**：G4O 平均完成率略高（0.68 vs 0.61），但执行动作更多；S35 更易提前终止，G4O 更倾向于坚持到环境反馈确认完成。
- **失败模式随标注方案变化**：
  - OPAQ 下失败主要为感知错误（83.5%），执行错误占 14.2%。
  - SEM 下感知错误降至 65.8%，执行相关失败升至 31.1%。
  - 推理相关错误在两种设置下都很少（2–3%）。
- **场景复杂度影响明显**：S2 完成率低于 S1，并导致更多 `Walk` 和 `Look` 探索行为；G4O 的探索更积极，部分补偿了可见性降低。
- **任务难度与完成率负相关**：C-D 等级与完成率之间存在显著负秩相关（Spearman ρ = −0.53, p < 0.05）。
- **消融结论**：
  - MSTM 缓冲区越大性能和连贯性越好，`k=50` 基线最佳。
  - 准确定性解码对结构化工具调用最可靠；适度随机性会降低可靠性。
  - 3×3 到 6×6 参考点密度提升性能，但 7×7 反而因视觉/符号杂乱而下降。
  - 图像分辨率从 640×360 提高到 1920×1080 显著改善完成率，但推理延迟也增加。

## 7. 优点

- **双重世界模型

将视觉观测与符号状态显式对齐，使 VLM 能在有限上下文内获得稳定、可解释的 3D 空间锚点，缓解纯图像输入带来的空间推理困难。  
- **工具化动作空间设计简洁且可扩展**：仅通过 `Look`、`Walk`、`Pick`、`Drop` 四种原语即可覆盖桌面与客厅场景中的主要操作需求，同时便于接入已有仿真引擎或真实机器人中间件。  
- **结构化推理痕迹与多模态短期记忆**：Thought 笔记和滚动缓冲区提供了显式、可审计的决策链，有利于错误归因和后续提示优化，也增强了系统行为的可解释性。  
- **C-D 分类法与确定性检查器**：将任务难度拆解为 ACT、REF、REL 三类成本，并提供可重复的量化评估方式，使不同 VLM、不同标注方案和不同场景之间的比较更具可操作性。  
- **系统模块解耦清晰**：Runtime Engine、Cognitive Server 与 VLM Inference Server 分离，便于替换模型骨干、扩展仿真环境或部署到其他具身平台。

## 8. 局限性与潜在问题

- **实验证据强度有限**：论文未报告方差、置信区间或显著性检验结果，主要结论依赖均值和比例，难以判断不同条件间差异是否稳健。  
- **任务与场景规模较小**：仅两个室内场景、15 个任务，且布局高度受控；对动态物体、遮挡、光照变化、多智能体交互或长时程任务的泛化性缺乏验证。  
- **仅评估闭源商业模型**：未与开源 VLM、纯 LLM 加视觉模块、传统 GCA 或模块化感知—规划—控制系统进行横向对比，难以判断 A.D.A.M.O. 框架本身的增益相对于模型能力有多大。  
- **依赖精确的语义标注**：SEM 方案需要场景侧的类别和实例信息，实际部署中可能需额外检测、分割或人工标注，闭环中的标注误差影响未充分讨论。  
- **实时性不足**：单次 VLM 调用平均约 6–8 秒，距离实时人机交互或持续控制仍有明显差距；API 调用成本和时延可能限制实际应用。  
- **推理可靠性依赖提示与解码策略**：研究显示贪心解码、固定缓冲区和参考点密度对性能敏感，提示工程和超参数调整可能削弱框架的即插即用性。  
- **缺乏学习或恢复机制**：VLM 的失败主要被记录和归因，但系统未利用失败样本进行在线学习、记忆压缩或策略改进，难以从错误中持续优化。

## 9. 总体评价与启示

- 该论文的核心贡献在于提出了一个将预训练 VLM 与统一感知—推理—动作回路结合起来的可复现框架，并通过系统的任务难度分类和消融实验，揭示了语义标注、视觉—符号世界模型和记忆设计对具身 VLM 性能的关键影响。  
- 从方法论角度看，A.D.A.M.O. 提供的 ReAct 式工具调用、多模态短期记忆和确定性完成检查器，为后续研究提供了一个灵活、可扩展的评估基线和工程模板。  
- 不过，由于实验规模、统计严谨性和模型覆盖范围有限，其结果更适合视为一种系统级设计探索，而非对“VLM 驱动虚拟人”能力的最终结论。  
- 未来工作若能在更复杂环境中引入更细粒度的错误分析、在线记忆压缩、真实机器人验证以及与更多开源模型和基线方法的对比，将显著提升该框架的可信度和实际适用性。
