## 摘要
部署在长任务流中的使用工具的语言模型智能体得不到奖励，因此无法判断自身是否成功、无法安全重试，也无法为其改进所需的经验打标签。我们提出 SelfSuite，其中智能体自身的基础模型仅利用世界的公开材料，设计一个由加权评判器和有依据的逐任务简报组成的小型评估套件，将其冻结，并用它来对“保留最佳结果”的重试进行门控，以及为类型化且结果可追踪的记忆打标签。在 tau2-bench 和 AppWorld 上匹配的五次重复基准测试中，SelfSuite 在没有任何标签的情况下得分高于普通智能体，在 tau2-bench 上与获得十个专家标签的方法持平，而在 AppWorld 上则落后于 Agentic Context Engineering (ACE)，因为代码执行提供了直接的成功信号。在相同任务上开展的消融实验中，它在每一次重复中都优于无标签的 ACE，而门控的第二次尝试是唯一一个在每次重复中移除后都会损害性能的组件。我们还模拟了一位领域专家，对每个世界的十个入门任务进行评分。使用这些标签来校准 SelfSuite 的评估器会带来小幅且一致的提升，而使用它们来预热 ACE 的记忆则使 ACE 提升到与校准后的 SelfSuite 打平。在第二个模型家族上的单次运行研究显示出相同的顺序。

## Abstract
A tool-using language-model agent deployed over a long stream of tasks receives no reward, so it cannot tell whether it succeeded, cannot safely retry, and cannot label the experience it needs to improve. We present SelfSuite, in which the agent's own base model, given only the world's public materials, designs a small evaluation suite of weighted judges and grounded per-task briefs, freezes it, and uses it to gate a keep-best retry and to label a typed, outcome-tracked memory. On matched five-repeat benchmarks over tau2-bench and AppWorld, SelfSuite scores above the plain agent without any labels, matches methods given ten expert labels on tau2-bench, and trails Agentic Context Engineering (ACE) on AppWorld, where code execution gives a direct success signal. In an ablation campaign run on the same tasks, it is above label-free ACE in every repeat, and the gated second attempt is the only component whose removal hurts in every repeat. We also simulate a subject-matter expert who grades ten onboarding tasks per world. Using those labels to calibrate SelfSuite's evaluator gives a small, consistent gain, and using them to warm up ACE's memory lifts ACE to tie calibrated SelfSuite. A single-run study on a second model family shows the same ordering.

# Self-Designed Evaluators and Warm Memory for Long-Horizon Agents 论文总结

## 1. 论文的核心问题与整体含义

- **核心问题**：部署在长期任务流中的工具使用型语言模型智能体无法获得奖励信号，因此无法判断自身是否成功、无法安全重试，也无法为经验打标签以持续改进。
- **背景与动机**：
  - 现有“自我改进智能体”研究大多依赖基准自带的地面真值（GT）、单元测试或环境执行信号。
  - 真实部署中不存在这样的信号；人工编写校验器（成功率规约、策略断言、状态回读、单元测试）工作量大、世界特定且脆弱。
  - 论文提出：让智能体自己的基础模型**从公开材料中设计评估器**，无需任何标签即可支持重试门控和经验标记。
- **整体含义**：验证了“模型可以自己写校验器”这一思路，并证明该自设计评估器足以让智能体在无标签条件下超越普通基线，且一个人类专家在入职阶段提供的少量标签能带来额外但有限的提升。

## 2. 论文提出的方法论

论文提出 **SelfSuite**，包含两个阶段：一次性的评估器自设计与在线部署循环，全程不依赖地面真值。

- **自设计阶段（离线，每个世界一次）**
  - **架构师**：智能体自己的基础模型，输入世界摘要、公共策略、工具签名以及 3 个无标签任务样本，输出一个 JSON 套件规范。
  - 套件包含：
    - **k 个评判器**：每个评判器是一个测量准则，输出布尔通过、[0,1] 分数和理由；分为 **VETO（一票否决）** 和 **SOFT（加权聚合）** 两类。
    - **TaskBrief 策略**：将任务指令分解为成功标准、所需证据、顺序约束和约束项；通过 **grounding**（检查是否受公开材料支持）和 **gating**（保守的前置条件检查）保证简不容易产生假阴性。
    - **聚合规则与阈值 τ**：如 min、mean、weighted；任一 VETO 失败则尝试失败，且 SOFT 聚合分数须 ≥ τ 才通过。
    - **记忆分类法与重试策略**：指定任务族用于路由经验，指定尝试次数与反馈形成方式。
    - 评判器是温度 0 的独立调用，使用智能体自身的基础模型，没有单独的更强评分器。
- **状态回读**
  - 每次尝试后，世界适配器重建环境并运行有界只读查询，将观察结果序列化到 `{state}` 槽。
  - 状态回读不接触基准奖励、黄金动作或隐藏测试；若回读失败，状态条件评判器中性弃权（0.5 分，标记 no_state），避免制造假否决。
- **部署循环（在线，每个任务）**
  1. **检索**：将任务路由到任务族，先按族收集、按锚点状态和最近性预排序，再用 LLM 相关性排名取前 5 条经验。
  2. **尝试**：ReAct 智能体在注入经验的情况下执行任务。
  3. **评判**：构建并 grounding brief，读回状态，每个评判器输出通过与分数，先执行 VETO 折叠，再按 τ 聚合。
  4. **重试**：若失败且还有预算（总共两次尝试），将失败评判器的理由蒸馏为一条反馈指令，让智能体用该反馈再次尝试。
  5. **保留最佳（keep-best）**：套件通过的尝试优先；平局取最早；后续尝试只有聚合分数超过当前最佳 **margin m**（重复实验为 0.30，单次研究为 0.15）才替换，避免噪声第二次尝试排挤好的第一次。
  6. **学习**：从完成任务中提取经验写入记忆，任务结果更新被检索过的经验的记账（PnL ledger）。
- **类型化、结果跟踪的记忆**
  - 经验分为正面“do”和负面“avoid”，按策略、常见错误、领域知识分节，路由到架构师指定的族，每个桶上限 30 条，桶达 20 条时进行近重复蒸馏，全局上限 200 条。
  - 每条经验带 **uses / helps / hurts** 计数：成功后前被检索的经验加分，失败前被检索的经验扣分；持续有害的经验被降权并可被逐出。
- **专家校准（可选）**
  - 模拟 10 个带标签的入职任务，以 6 个拟合 / 4 个门控的划分，确定性地重新折叠、聚合和设定阈值。
  - 只允许修改哪些评判器被保留、折叠模式、聚合规则和阈值，不动 actor、brief、记忆策略等。
  - 接受提案要求门控集上一致性严格提升，且假阳性和假阴性不增加；否则保留原套件。

## 6. 论文的主要结论与发现

- **无标签 SelfSuite 的效果**
  - 在 matched five-repeat benchmark 中，fresh suite 的 SelfSuite 在平均值上高于 plain agent（整体 +6.0 pp，95% CI [−0.3, +12.3]）。
  - 在 tau2 上，SelfSuite 均值排名第二，与所有带标签的学习器在噪声范围内持平；在 AppWorld 上落后于两个 ACE 行（有代码执行直接成功信号）。
  - 消融实验中，SelfSuite 在 **所有五次重复中都高于无标签 ACE**（配对 +4.6 ± 2.3 pp，p=0.011），也显著高于 plain agent。
- **专家标签的价值**
  - 用 10 个标签校准 SelfSuite 评估器：整体配对 +2.0 pp（CI [+0.2, +3.8]，每次重复差异非负），带来最一致的小幅提升。
  - 将 10 个标签作为预热记忆注入 ACE：使 ACE 从 81.2 升至 84.0（整体 +2.8 ± 5.9 pp，统计不显著），并与校准后的 SelfSuite（84.4）打平。
- **组件消融的关键发现**
  - **移除由冻结套件门控的第二次尝试**是唯一在每次重复中均降低性能的组件（整体 −7.8 ± 3.5 pp，p=0.007；tau2 上 −14.9 ± 5.7 pp）。
  - 平衡记忆比默认记忆小幅但一致地更好（+2.7 ± 1.9 pp，p=0.032）。
  - 记忆极性、TaskBrief、判断器分解（单个整体评论家）总体上在噪声范围内；但负极性记忆在 tau2 的 5 次重复中有 4 次低于参考。
- **套件行为的机制解释**
  - 自设计的 fresh suite 很保守：判断通过率远低于 GT 成功率，假阳性极少但假阴性多，导致大量重试；keep-best 将保守性转化为低风险重试收益。
  - 校准后的套件更宽松：判断通过率接近 GT，重试率降低，假阳性率提高但每世界平均损失不到一个任务。
  - 剩余差距主要在于 **选择器**：agent 经常产生一个正确尝试，但 GT-free 套件未选中它（oracle 与部署成绩之间的缺口，称为 selection headroom）。
- **跨模型验证**
  - 在 9 个单元中，SelfSuite 在 7 个上最好或并列；两个模型家族上的排序基本一致；oracle 判断器在 8/9 单元上具有正判别力。

## 7. 优点

- **无标签、无人工校验器**：采用公开材料一次性自设计评估套件，降低新世界接入成本。
- **世界状态 grounding**：评判器读取结果状态而非仅看对话文本，减少“transcript 看起来对”的假阳性。
- **保守设计降低自动重试风险**：VETO 折叠、grounded brief 和 keep-best margin 规则共同限制重试的负面影响。
- **结果可追踪记忆**：每条经验带 PnL 记账，持续有害经验被降权/逐出，缓解“自我评分膨胀”问题。
- **严格实验协议**：匹配任务、配对统计、5 次重复、置信区间、噪声底线；模拟专家标签的两种使用方式，增强现实可用性。
- **消融与诊断结合**：既揭示关键组件，又用逐尝试记录解释机制（保守性、重试收益、选择器头空间）。

## 8. 不足与局限

- **自我评估循环性**：评判器、brief 接地器、记忆排序器和智能体是同一个模型；分解、接地和状态回读只是缓解而非消除自评估偏差（如 Opus-4.8 telecom 中负判别力 + 18 pp 头空间）。
- **设计方差**：fresh suite 在重复之间会变化，部分报告方差来自设计差异；校准套件虽消除这一方差，但代价是冻结在 10 个热身任务所支持的内容上。
- **统计功效有限**：5 次重复只能分辨约 ±4 pp（50 任务单元）；更小的效应（记忆极性、fresh vs calibrated 在 tau2 上的差异）未被解析。
- **覆盖范围有限**：
  - AppWorld challenge 未在匹配的基准活动 A 中单独出现；
  - Opus-4.8 只出现在单次运行研究中；
  - airline 世界在两模型上均未击败 plain agent，论文将其报告为方法局限而未专门调优。
- **未做成本归一化**：SelfSuite 增加了评判器、brief、检索和重试的每次任务调用，缺少每任务 token 核算。
- **在线 rubric 演进无效**：基于 GT-free disagreement mining 的在线修订没有优于冻结的校准套件，更大的仲裁预算下是否可以改进仍未解决。
- **标签效果有限**：10 个专家标签的收益不大且并非总是统计显著，说明该方法在无标签场景下的增量价值更值得关注，但绝对性能仍受限。
