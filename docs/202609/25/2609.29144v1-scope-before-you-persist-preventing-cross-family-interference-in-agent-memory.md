## 摘要
持久记忆使语言模型智能体能够在无需更新模型权重的情况下改进提示和技能。我们表明，使检索范围与认证范围相匹配，能让这些编辑支持在反复出现的任务族中进行可靠的重复适应。我们在 ProcStream-RSI（一个 12 轮代码修复流）上研究冻结模型智能体，使用正交回归控制（ORC），一种基于执行的持久技能编辑门控。在一项保持提案和门控决策固定的干预中，仅针对每个被接受技能的原始任务族进行检索，将平均隐藏轨迹效用从全局记忆下的 0.713 提高到 0.816，并将有害部署从八次中的六次降为零。在 27 个配对的随机顺序流中，Scoped-ORC 相比 Global-ORC 将平均轨迹效用提高了 0.063 [0.037, 0.094]，接受了 63 次而非 12 次更新，并在 19/27 个流中产生了多次被接受的更新，有害接受为 0/63。全局控制达到 0.713，低于静态智能体的 0.775，因为局部有效的编辑可能会干扰不相关的任务族。这些结果确立了作用域匹配作为持久智能体记忆的一种补充控制：认证决定一个编辑是否得到支持，而检索作用域决定该证据授权其在何处使用。

## Abstract
Persistent memory lets language-model agents improve prompts and skills without updating model weights. We show that matching retrieval scope to certification scope enables these edits to support reliable repeated adaptation across recurring task families. We study frozen-model agents on ProcStream-RSI, a 12-round code-repair stream, using Orthogonal Regression Control (ORC), an execution-grounded gate for persistent skill edits. In an intervention that holds proposals and gate decisions fixed, retrieving each accepted skill only for its originating family raises mean hidden trajectory utility from 0.713 under global memory to 0.816 and changes harmful deployments from six of eight to none. In 27 paired randomized-order streams, Scoped-ORC improves mean trajectory utility by 0.063 [0.037, 0.094] over Global-ORC, accepts 63 rather than 12 updates, and produces multiple accepted updates in 19/27 streams, with 0/63 harmful acceptances. The global control reaches 0.713, below the static agent's 0.775, because locally valid edits can interfere with unrelated families. These results establish scope matching as a complementary control for persistent agent memory: certification determines whether an edit is supported, while retrieval scope determines where that evidence authorizes its use.

## 1. 论文的核心问题与整体含义

- **研究背景**：语言模型智能体可以通过持久记忆（persistent memory）在不更新模型权重的情况下改进提示词与技能，形成“自我改进”系统。但已有工作多关注“选出最优存档成员”，较少关注部署后的完整演化轨迹。
- **核心问题**：持久技能编辑在何种条件下能真正提升部署智能体在**反复出现的任务族**上的表现，而不是只对产生最新反馈的那个任务族有效？
- **关键冲突**：一个编辑可能在产生它的任务族内被证据支持（局部有效），但一旦写入全局共享技能，就可能干扰其他不相关的任务族，导致整体性能甚至低于静态智能体。
- **整体含义**：持久智能体记忆需要同时回答两个问题：**一个更新是否被证据支持（认证）**，以及**该证据授权它在哪些地方被使用（检索范围）**。两者不匹配是跨任务族干扰（cross-family interference）的根源。

## 2. 论文提出的方法论

- **核心思想**：匹配检索范围与认证范围。证据在某一个任务族内收集，就只能授权在该任务族内使用该编辑，而不是全局部署。
- **Scoped-ORC（作用域化正交回归控制）**：
  - 每个任务族维护独立的技能槽位 `K(f)`。
  - 对来自任务族 `f` 的任务，智能体使用该族已接受的技能；若该族尚无已接受技能，则回退到初始技能 `K0`。
  - **关键设计**：技能文本长度仍固定为 360 字符；改变的只是“检索哪一个技能”，不增加提示预算。
  - 提案生成和门控逻辑与 Global-ORC 完全一致，仅部署范围不同，从而隔离出作用域机制本身。
- **正交回归控制（ORC）门控**：
  - 在每个探针任务上，同时评估现任策略和候选策略。
  - 三个在线证据通道：公开示例（pub）、私有精确输出测试（priv）、答案无关的变形测试（meta）。
  - 对每组任务（当前族 + 每个历史族）分别计算通道级配对 bootstrap 95% 置信下界 `L_{g,c}`。
  - 部署条件：当前族公开/变形通道的非回归约束、当前族私有通道的严格增益约束，以及所有历史族各通道的非回归约束，且无任何不安全程序报告。
- **形式化表征**：论文引入命题 1 说明门控漂移——仅当 `παG > (1−π)βL` 时期望部署变化为正；并指出若多个证据通道的误接受事件相同，增加通道不会降低有害接受率。该命题只能覆盖证据中出现的任务族，无法保护未出现的族，因此需要作用域匹配。

  - 每轮包含 4 个发现任务和 4 个探针任务；另有固定检查点银行（每族 1 个）和最终银行（每族 2 个），每流共 123 个任务。
  - 公开示例区分族特定修复规则；探针、检查点和最终示例为中性（提供的 buggy 程序已通过它们）。
  - 隐藏用例、私有测试与公开输入两两不重叠，隐藏用例对在线智能体不可见。
- **对比方法**：
  - `Static`：从不提出更新。
  - `Frozen-compute`：与 ORC 相同的调用但从不部署。

## 6. 论文的主要结论与发现

- **全局控制暴露作用域匹配的价值**：Static 和 Frozen-compute 均为 0.775 平均轨迹效用；Latest-only 仅 0.703，Self-judge 0.736，Replay 0.707，ORC 0.713。所有全局更新方法均低于 Static，原因是全局编辑对无关族产生影响。
- **固定输出干预**：在保持提案、决策、程序、分数不变的情况下，仅将检索范围改为族作用域，平均隐藏轨迹效用从 0.713 提高到 0.816，有害部署从 6/8 降到 0。
- **随机进入复制**：Scoped-ORC 对比 Global-ORC 的检查点效用差值为 0.041 [−0.004, 0.107]，最终银行效应 0.031 [0.001, 0.070]；两者共享当前族增益，但 Scoped-ORC 防止了所有非当前族的变化。
- **完整随机顺序扩展**：Scoped-ORC 相比 Global-ORC 平均轨迹效用提高 0.063 [0.037, 0.094]（p < 10⁻⁴）；接受 63 次更新而非 12 次；19/27 个流产生多次接受；有害接受为 0/63 对比 6/12。
- **正交证据在作用域内改善选择**：公开通道 AUROC 0.752，私有/变形通道 AUROC 0.998；但全局部署时，8 次 ORC 接受中只有 2 次改善下一个全局检查点，说明强局部选择仍需作用域匹配部署。
- **路由鲁棒性**：学习到的路由器在模板化基准上达到 100% 检查点分类准确率；保守 fallback 曲线显示路由缺失会逐渐降低效用。

## 7. 优点

- **清晰的机制隔离**：固定输出干预只改变检索范围，而保持提案和门控决策不变，有力地证明了跨族暴露是干扰的直接机制。
- **严密的实验控制**：配对设计、随机进入复制、完整扩展、预注册协议、隐藏审计、事务性账本等措施增强了内部效度和可重复性。
- **将“部署轨迹”作为评估对象**：不依赖 archive-best 检查点，而是评估完整部署序列，更贴近真实持续适应场景。
- **低成本、可执行的对策**：作用域化检索不增加提示长度或推理成本，只需按任务族维护技能槽位。
- **执行接地的验证**：私有精确输出测试和变形测试提供强不对称性，减少评估器与 actor 共同走捷径的风险。
- **外部迁移诊断**：用 HumanEval+ 和 GPT-OSS 进行跨基准、跨 actor 的初步迁移检验，体现了对泛化性的关注。

## 8. 不足与局限

- **模型单一**：主研究只使用一个冻结模型（Qwen3-Coder-Next），外部诊断模型也有限，未覆盖多种模型 / 编辑器 / 搜索骨干。
- **任务领域狭窄**：仅覆盖九种代码契约族，且属于同一类代码修复任务，结论外推到开放世界、真实软件工程或其他领域需谨慎。
- **路由假设简化**：Scoped-ORC 假设能够准确知道任务属于哪个族；论文自己提到 open-world 和 wrong-slot routing 仍是未来工作。学习的路由器在模板化基准上 100% 准确，可能是任务模板过于可预测，而非现实路由难度。
- **累积控制不足**：Batch-ORC 在所有情况下均未接受任何提案，因此未能充分检验“累积一次性更新”作为复合效应的对照；作用域多更新是否真正复合仍有待更强对照。
- **阈值与保守性**：ORC 门控非常保守，主研究中仅在 round 0 接受一次，8 个流后不再接受；这种保守性可能掩盖了编辑质量变化。
- **可能的模板过拟合**：基准任务由程序生成，语义固定，且公开/私有/隐藏输入按固定规则构造；学习到的路由和技能可能依赖于模板特征。
- **通用性限制**：研究关注“可检查的脚手架编辑”，不涉及权重更新、开放世界技能发现、自动学习不变式等更复杂的自我改进形式。
- **未完全解决评估器误差依赖**：论文强调证据在作用域内，但门控本身仍依赖私有/变形测试质量；如果这些测试也存在偏置，作用域匹配只能防止跨族暴露，不能完全解决评估器与 actor 的共谋。
