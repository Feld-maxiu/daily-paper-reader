## 摘要
视觉-语言-动作模型、世界模型和智能体规划器分别推动了物理智能的发展，然而它们的组合缺乏通用的执行抽象、共享状态、语义验证以及跨异构形态的持久经验。我们提出PhyAgentOS，一个运行时基础框架，将调度、验证、记忆、基准测试与安全作为系统级服务提供。其以会话为中心的运行时将会话而非动作视为调度、兼容性预检、监督执行、证据收集和验收的最小单元。为了将认知与物理执行解耦，认知-物理边界是一个文件系统：状态即文件协议将跨层状态具体化为带YAML的Markdown文件，生成可检查、可版本化的记录，且智能体层与运行时层之间无代码依赖。这些视图构成一个统一的认知状态空间，将意图、能力、环境、执行和经验对齐。会话验证器通过基于证据的成功、失败或重规划判定，区分执行终止与语义任务完成。经验证的输出通过认知记忆整合为可复用的知识和纠正性教训，在无需重新训练的情况下闭合试错循环。基准测试复用部署会话和验证路径，因此结果可追溯至真实执行。分层安全约束同时作用于策略驱动和智能体驱动的执行：预检、动作桥接、安全守卫、心跳监控和目标本地约束。验证是递进的：游戏测试认知规划，仿真加入动力学和控制，真实机器人引入硬件噪声，认知层保持恒定。PhyAgentOS在Optimus-67、StarDojo和DST-Dojo上进行了基准测试，在超过19种仿真和物理形态上得到验证，并在多个VLA模型上对LIBERO、Calvin和RoboCasa365取得性能提升。

## Abstract
Vision-language-action models, world models, and agentic planners each advance physical intelligence, yet their composition lacks a common execution abstraction, shared state, semantic verification, and persistent experience across heterogeneous embodiments. We present PhyAgentOS, a runtime foundation delivering scheduling, verification, memory, benchmarking, and safety as system-level services. Its Session-Centered Runtime treats a session, not an action, as the minimum unit of scheduling, compatibility preflight, supervised execution, evidence collection, and acceptance. To decouple cognition from physical execution, the cognition-physics boundary is a file system: the State-as-a-File protocol materializes cross-layer state as Markdown with YAML, yielding inspectable, versionable records without code dependencies between Agent and Runtime layers. These views form a unified cognitive state space aligning intent, capabilities, environment, execution, and experience. The SessionVerifier distinguishes execution termination from semantic task completion via evidence-grounded verdicts of success, failure, or replan. Verified outcomes are consolidated through epistemic memory into reusable knowledge and corrective lessons, closing a trial-and-error loop without retraining. Benchmarking reuses the deployment session and verification path, so results trace to real execution. Layered safety constrains both policy-driven and agent-driven execution: preflight, action bridges, SafetyGuard, heartbeat monitoring, and target-local constraints. Validation is progressive: games test cognitive planning, simulation adds dynamics and control, real robots add hardware noise, with the cognitive layer held constant. PhyAgentOS is benchmarked on Optimus-67, StarDojo, and DST-Dojo, validated on 19+ simulated and physical embodiments, and gains on LIBERO, Calvin, and RoboCasa365 across multiple VLA models.

## 1. 论文的核心问题与整体含义

- **核心问题**：当前的具身智能系统通常将视觉-语言-动作（VLA）模型、世界模型和智能体规划器分别发展，但将它们简单组合时，会出现几个结构性的缺陷：
  - 缺少跨层的共享状态表示和语义验证，导致系统无法判断物理任务是否真正成功（例如，机械臂轨迹正常结束却未抓到杯子）。
  - 认知规划与物理执行紧耦合，代码依赖严重，难以跨异构硬件复用。
  - 缺乏持久记忆，每次会话结束后学到的经验被丢弃，无法形成持续改进。
- **整体含义**：PhyAgentOS 并非再造一个垂直智能体，而是位于 VLA 模型、世界模型和规划器之下的一层“操作系统”，提供调度、验证、记忆、基准测试与安全等基础服务，使得不同智能模块能够协同工作并持续自我演化。

## 2. 方法论

PhyAgentOS 的核心设计思想是将认知与物理执行彻底解耦，并以文件系统作为两者之间的接口。

- **三层架构**
  - **Agent 层**：负责目标规划、任务分解与执行方法选择，输出结构化的“会话”（session）合约，不直接控制硬件。
  - **Runtime 层**：由 WatchdogSupervisor 监督，负责会话的生命周期管理、兼容性预检、执行与证据收集。
  - **协议层**：由一系列 Markdown + YAML 文件（如 `SESSIONS.md`、`TARGETS.md`、`ENVIRONMENT.md`、`LESSONS.md` 等）构成，提供可审计、可版本化的共享状态，也被称作认知状态空间。

- **核心机制**
  - **状态即文件协议**：任何跨层数据都以 Markdown/YAML 形式持久化，形成追加式审计日志，避免直接代码依赖。
  - **会话为中心的运行时**：会话是最小调度单元，由 WatchdogSupervisor 原子性地认领、监控并写入结果，确保执行契约。
  - **会话验证器**：在物理执行终止后，依据证据包（初始/终止观测、环境快照、任务定义等）对会话进行语义验收，给出成功、失败或重规划的判定，从而将“执行终止”与“任务完成”分开。
  - **认知记忆闭环**：验证后的结果经诊断、修正并再次验证后，才被巩固到 `KNOWLEDGE.md`（成功知识）和 `LESSONS.md`（失败教训）中，形成无需模型重训的试错学习循环。
  - **基准测试即运行时代码**：基准评估使用与部署相同的会话、运行时和验证路径，确保指标可追溯，并可作为迭代改进的数据引擎。
  - **分层安全架构**：从兼容性预检、动作桥接、SafetyGuard 校验、心跳监控到目标本地约束，形成纵深防御。

- **双执行流**：支持策略驱动的连续控制（`PolicySkillRuntime`）和智能体指导的工具调用（`BuiltinSkillRuntime`），两者共享相同的会话、监督和验证接口。

## 6. 主要结论与发现

- 认知与物理解耦的“状态即文件”架构有效解决了具身智能体缺乏共享状态、语义验证和运行时监督的难题。
- 会话验证器通过基于证据的成功/失败/重规划判定，可靠地区分执行终止与任务完成，显著减少“自我欺骗”式的失败。
- 认知记忆闭环可在不重新训练模型的情况下持续改进智能体行为，失败教训固化后能避免重复错误。
- 基准测试与部署共享同一路径，使评估结果更可信、可追溯。
- 分层安全能够在各种扰动下保证实时机器人执行的安全。
- 递进验证表明，在游戏、仿真和真实硬件上，PhyAgentOS 均能可靠驱动多种策略和机器人形态，并带来一致的性能提升。

## 7. 优点

- **架构创新**：将操作系统理念引入具身智能，统一了调度、验证、记忆和安全。
- **极低耦合**：文件协议使 Agent 和 Runtime 完全独立，支持跨语言、跨形态复用。
- **语义级闭环**：会话验证器提供证据驱动的高层判决，而非简单依赖控制器返回值。
- **持续自演化**：通过真实记忆（知与教训的分离存储）和基准测试的嵌入式自迭代，为无需重训的系统进化提供了实用路径。
- **递进验证体系**：游戏→仿真→真实机器人的分层评估，增强了实验的内部有效性和可解释性。

## 8. 不足与局限

- **协议延迟**：当前采用轮询方式读取文件来发现新状态，在实时性要求极高的场景下可能引入不可忽略的延迟。虽可改进为事件驱动，但需保证原子写入一致性。
- **记忆膨胀**：`LESSONS.md` 和 `KNOWLEDGE.md` 会随会话数量单调增长，缺乏理论上的检索上界保证，可能导致上下文构建时遗漏关键经验。
- **真机评测有限**：真实机器人实验侧重于零样本迁移和安全属性，缺乏大规模长时间的任务成功率统计。
- **部分模块未完全实现**：如目标图和会话编译器的 DAG 级多智能体协调功能仍在规划中，世界模型的深度整合也在展望阶段。
