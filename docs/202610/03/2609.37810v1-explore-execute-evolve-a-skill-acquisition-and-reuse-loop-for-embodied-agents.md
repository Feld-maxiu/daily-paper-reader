## 摘要
视觉-语言-动作模型和世界-动作模型已在机器人领域展现出令人印象深刻的能力，但对未见任务的泛化仍具挑战。近期，通用多模态智能体在零样本机器人任务求解方面展现出巨大潜力。然而，它们通常因从头推理和探索物理世界而产生高昂的执行成本。为降低这些成本，我们提出 RoboSkill，这是一个通过“探索、执行、进化”循环将技能获取与复用连接起来的框架。在该循环中，智能体通过探索收集任务相关信息，在适应反馈的同时执行任务，并根据执行记录进化其技能库。随后，它复用这些技能来引导下一轮循环中的探索与执行，从而闭合循环。为提高循环效率，我们结合触觉反馈来补充视觉，以减少物理交互中的不确定性。此外，我们用可复用代码增强文本引导，以减少技能复用时的推理开销。在 LIBERO-10 上，RoboSkill 将四个智能体的首次情节成功率提高了 12.5--25.0 个百分点，并将平均运行时间降低了 7.6--72.4%。在真实机器人上，它将成功率提高了 8.3 个百分点，并将成功试验的平均运行时间至少降低了 14.4%。

## Abstract
Vision-language-action and world-action models have demonstrated impressive capabilities in robotics, yet generalization to unseen tasks remains challenging. More recently, general-purpose multimodal agents have shown great potential for zero-shot robotic task solving. However, they often incur high execution costs by reasoning and exploring the physical world from scratch. To reduce these costs, we introduce RoboSkill, a framework that connects skill acquisition and reuse through an Explore, Execute, Evolve loop. Within this loop, the agent explores to gather task-relevant information, executes tasks while adapting to feedback, and evolves its skill library based on execution records. It then reuses these skills to guide exploration and execution in the next cycle, closing the loop. To improve loop efficiency, we complement vision with tactile feedback to reduce uncertainty during physical interaction. We further augment textual guidance with reusable code to reduce reasoning overhead during skill reuse. On LIBERO-10, RoboSkill improves first-episode success rates by 12.5--25.0 percentage points and reduces average runtime by 7.6--72.4% across four agents. On real robots, it improves success rates by 8.3 percentage points and reduces average runtime for successful trials by at least 14.4%.

## 1. 论文的核心问题与整体含义

- **研究背景**：视觉-语言-动作模型（VLA）与世界-动作模型（WAM）在机器人控制中已取得显著进展，但对未见任务的泛化能力仍然有限。近期兴起的通用多模态智能体虽然具备零样本任务求解潜力，却往往需要从零开始进行感知、物理试错与失败恢复，导致执行成本高昂。
- **核心问题**：如何让具身智能体复用先前执行中获取的技能，从而降低推理与探索开销，提升任务成功率和执行效率。
- **整体含义**：论文提出一种闭环框架 RoboSkill，将技能获取与复用统一在“探索—执行—进化”循环中，强调通过物理交互积累可迁移经验，而不是每次任务都从零开始。

## 2. 论文提出的方法论

- **总体框架：Explore, Execute, Evolve 循环**
  - 智能体接收任务指令、被选技能和环境 SDK 访问权限。
  - 需要补充信息时，先求解探索子任务获取任务知识。
  - 基于探索结果与技能执行主任务，并根据反馈调整动作。
  - 任务结束后，汇总执行记录与代码，构建或更新技能库，用于指导下一次探索与执行。

- **探索（Explore）**
  - 将“获取缺失信息”作为显式子任务，其目标不同于主任务，但服务于主任务的可靠完成。
  - 探索本身也遵循执行—反馈的嵌套循环。
  - 例如：抓取奶油奶酪失败后，智能体可通过 RGB-D 估计桌高；若深度不确定，则下降至接触，获得约 0.446 m 的桌高，再继续抓取。
  - 探索发现以“任务知识”形式保留在会话中，或经进化阶段固化为技能。

- **执行（Execute）**
  - 上下文包括任务指令、机器人控制与感知 API 规范、探索知识、选定技能包。
  - 观测包含 RGB、深度以及触觉反馈（压力/力/力矩信号），用于补充视觉难以判断的接触与碰撞信息。
  - 通过 SDK 而非独立工具进行交互，使智能体能构建可复用代码，如 `depth_pointcloud.py`、`verify_table_height.py`。
  - 执行期间记录交互过程与已执行代码，作为进化阶段的输入。

- **进化（Evolve）**
  - 任务结束后进行一次统一回顾，而不是每个子任务后都调用回顾，以减少开销。
  - 每个技能包含：
    - **文本指导**：任务策略、适用条件、失败教训；
    - **可复用代码**：按层级组织的可执行程序；
    - **支持记录**：失败案例、完整执行轨迹、元数据（简要描述、视觉关键帧）。
  - 智能体作为自身评审者，从会话记录和实际执行代码中抽取、整合技能；若已有对应技能则补充，否则新建。
  - **技能使用**：新任务时，智能体根据元数据选择最多 K=3 个相关技能包，放入工作区供探索和执行调用。

- **两个关键设计**
  - **触觉反馈**：降低物理交互不确定性；
  - **可执行代码**：在技能复用中保留程序性知识，减少每次重建过程的推理开销。
