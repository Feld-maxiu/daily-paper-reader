## 摘要
现代语言模型智能体越来越多地在长时程、多步骤轨迹中与外部环境交互，累积的交互历史可能迅速超出实际上下文预算。为确保可靠性，智能体必须在长时程内维护事实信息，记住执行错误与纠正性反馈，并跟踪跨动作的进展。已提出多种方法在无需在上下文中保留完整执行历史的情况下实现这一目标，例如利用推理与动作历史、通过覆写机制学习维护固定大小记忆，以及周期性摘要。尽管覆写记忆原则上可以保留仅追加记忆能保留的任何内容，但它必须学习在每次后续覆写中携带每项事实，而这难以从稀疏结果奖励中习得；对于网页智能体这类交互应用，我们发现训练得到的覆写记忆会删除轨迹所需的关键信息以及从环境中获得的纠正性反馈。我们提出 AMBER（用于证据保留的仅追加记忆库）——一个简单且可扩展的框架，智能体联合学习推理、行动和写入自由形式记忆，同时仅追加规则从构造上保证记忆保留。这使得 AMBER 能够利用结果奖励的强化学习进行端到端训练，而无需大量精心整理的监督微调数据。在 WebArena Lite 上，AMBER 相较基于覆写的记忆将平均成功率提高 4.09 个百分点，将在五次重复运行中解决的任务比例提高 4.8 个百分点，并与在显著更昂贵的精心整理监督上训练的覆写基线性能相当。AMBER 在保持实用 token 预算的同时取得这些改进，在上下文效率、任务性能与可靠的长时程执行之间提供了良好平衡。

## Abstract
Modern language-model agents increasingly interact with external environments over long-horizon, multi-step trajectories, where the accumulated interaction history can quickly exceed practical context budgets. To ensure reliability, agents must maintain factual information over long horizons, remember execution errors and corrective feedback, and track progress across actions. Several approaches have been proposed to achieve this without the need for maintaining the entire execution history in context, such as using the reasoning and action history, learning to maintain a fixed-size memory through an overwrite mechanism, and periodic summarization. Although overwrite memory can in principle retain anything an append-only memory can, it must learn to carry each fact through every subsequent rewrite, which is difficult to learn from sparse outcome rewards; for interactive applications like web agents, we find that trained overwrite memories delete key information required by the trajectory, as well as corrective feedback received from the environment. We introduce AMBER (Append-only Memory Bank for Evidence Retention) - a simple and scalable framework where an agent jointly learns to reason, act, and write free-form memory, while an append-only rule guarantees retention by construction. This allows AMBER to be trained end-to-end with reinforcement learning from outcome rewards without the need for extensive curated SFT data. On WebArena Lite, AMBER improves average success over overwrite-based memory by 4.09 percentage points, increases the fraction of tasks solved in five repeated runs by 4.8 percentage points, and matches an overwrite baseline trained on substantially more expensive curated supervision. AMBER achieves these improvements while maintaining a practical token budget, providing a strong balance between context efficiency, task performance, and reliable long-horizon execution.

## 2. 方法论

### 2.1 核心思想

- AMBER（Append-only Memory Bank for Evidence Retention）的核心是：**智能体只学习“写什么”，而“保留什么”由仅追加规则在构造上保证**。
- 与覆写式记忆不同，AMBER 的记忆条目一旦写入便不可修改或删除，从机制上保证关键信息不会因后续覆写而丢失。

### 2.2 两步对话记忆生成与追加保留

- 每个环境步骤内，智能体与策略模型进行**两步对话**：
  1. **第一步**：输入当前任务 `x`、当前观察 `o_t`、记忆库 `C_t`，生成推理 `r_t` 和执行动作 `a_t`。
  2. **第二步**：基于当前任务、观察、记忆库以及刚生成的推理和动作，生成自由形式记忆条目 `m_t`。
- 记忆生成发生在动作执行之后、观察到动作结果之前。
- 更新规则为：
  \[
  C_{t+1} = C_t \parallel [m_t]
  \]
  其中 `C_0` 为空，`[·]` 表示追加操作。
- 每次环境步骤结束后，步骤内的对话被丢弃；后续步骤只携带记忆条目，不重放过去的观察、推理和动作。

### 2.3 端到端强化学习优化

- AMBER 使用 **GRPO（Group Relative Policy Optimization）** 从结果奖励进行端到端训练，联合优化推理、动作生成和记忆生成。
- 训练流程：
  1. 先基于离线轨迹进行**监督微调（SFT）**初始化策略。
  2. 再将 SFT 策略作为参考策略，用 RL 进行优化。
- 每个训练任务生成一组 `G` 条多步轨迹，每条轨迹获得一个终端奖励 `R_g ∈ {0,1}`。
- 组内相对优势计算为：
  \[
  A_g = \frac{R_g - \text{mean}(R)}{\text{std}(R) + \delta}
  \]
- 同一轨迹内每一步的所有助手生成 token（推理、动作、记忆）共享同一优势 `A_g`。
- 使用重要性采样比和裁剪机制更新策略，并加入与 SFT 参考策略的 KL 散度惩罚。
- 关键点：**AMBER 没有单独的记忆奖励**；记忆写入行为完全通过最终任务奖励涌现。

### 2.4 Rollout 基础设施

- 将**模型推理、浏览器执行、网站服务**分离为可独立扩展的组件：
  - 模型推理：SGLang 异步服务器。
  - 浏览器执行：基于 Ray actor 和 FastAPI 环境服务器。
  - 网站服务：独立虚拟机托管 WebArena 容器。
- 每个 rollout 拥有独立的浏览器会话和网站容器，避免 cookie、状态等跨 rollout 污染。
- Rollout 在交互步骤级别异步执行，推理与环境交互可跨 rollout 重叠，提升 GPU 利用率。

## 6. 主要结论与发现

- **仅追加保留显著提升成功率**：
  - Qwen 3.5 9B：AMBER 平均成功率 36.85%，比覆写记忆 MemAgent 的 32.76% 高 **4.09 个百分点**。
  - Qwen 3.5 27B：AMBER 48.82%，比 MemAgent 的 46.77% 高 **2.05 个百分点**。
  - AMBER（27B）超过 Haiku 4.5 的 46.72%。
- **提升重复运行可靠性**：
  - 9B 模型在所有阈值（≥1/5 至 5/5）均领先。
  - 27B 模型在 ≥2/5、≥3/5、5/5 领先；在严格 5/5 准则下，AMBER 29B? 注意是 27B，达到 35.4%，优于覆写和推理+动作历史。
- **上下文成本可接受**：
  - 第 30 步时 AMBER 约 7.4k tokens，MemAgent 4k tokens，WebAgent-R1 9k tokens，完整历史约 90k tokens。
  - AMBER 用适度增加的上下文换取更强的可靠执行。
- **监督强度与保留先验的关系**：
  - 精化监督数据使 MemAgent 平均成功率从 32.76% 提升到 35.59%，与 AMBER 的 36.85% 接近。
  - 但精化监督需要更复杂昂贵的生成-评判-修订管道；AMBER 无需该额外流程即可达到同等水平。
- **轨迹层面的机制证据**：
  - 覆写记忆中的环境错误反馈在 1 步后保留 100%，2 步后仅 25.6%，4 步后仅 4.5%，5 步后 0.8%。
  - AMBER 重复无效动作 1.29 次/事件，而 MemAgent 1.95 次/事件；MemAgent 在 15.4% 事件中重复 6 次以上，而 AMBER 仅 3.3%。
  - 覆写记忆存在“递归压缩损失”：先正确记录的关键证据在后续覆写中被丢弃，导致最终回答遗漏或错误。

## 7. 优点

- **机制简洁且具可解释性**：将“写什么”和“保留什么”解耦，仅追加规则从构造上保证耐久性，降低了策略的学习负担。
- **监督成本低**：只需基础 SFT + 结果奖励 RL，无需复杂的精化监督管道即可达到覆写基线在昂贵监督下的性能。
- **公平的实验设计**：控制其他四个轴（观察表示、模型家族、训练策略、评估环境）不变，仅改变保留策略，比较结果可信。
- **深入的轨迹分析**：不仅报告成功率，还通过具体案例和统计揭示覆写记忆失败的两个关键模式（错误反馈丢失、递归压缩损失）。
- **可扩展的 rollout 架构**：异步分离推理、浏览器和网站服务，提升训练效率。
- **实用上下文预算**：在取得性能提升的同时，上下文长度仍保持在实用范围内。

- **记忆幻觉问题**：作者观察到模型有时会生成幻觉记忆，可能源于仅用结果奖励进行 RL；论文未给出缓解方案。
- **信息损失分析偏定性**：虽然给出了明确失败

- **信息损失分析偏定性**：虽然给出了明确失败案例和反馈保留比例，但未系统统计所有失败任务中信息丢失的频率和类型，难以量化该问题对整体性能的贡献。

- **仅追加记忆的长期可扩展性**：虽然当前 30 步内上下文可接受，但若任务步数远超该范围，线性增长仍可能带来显著开销，需要进一步设计选择或合并机制。  

## 9. 总体评价

AMBER 通过仅追加记忆机制，在低监督成本下实现了长时程网页智能体的可靠记忆保留，核心贡献在于将记忆写入策略与保留规则解耦，以构造性保证解决覆写记忆的压缩丢失问题。实验结果和轨迹分析支持其有效性，同时揭示了覆写记忆失败的两个关键模式：错误反馈丢失和递归压缩损失。尽管存在上下文线性增长等局限，但 AMBER 为记忆机制设计提供了一个简单而有效的基线，未来可在选择性压缩、幻觉抑制和多环境验证上进一步改进。
