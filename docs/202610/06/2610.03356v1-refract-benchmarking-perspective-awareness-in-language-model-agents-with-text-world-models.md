## 摘要
大型语言模型（LLM）智能体正越来越多地部署在工业维护与设备故障排查等高风险场景中，这些场景中的工作人员承担着多种角色。因此，一个合格的智能体必须以校准用户角色的方式行动：采取的行动和提供的信息要尊重该角色的知识与能力边界。与代码编写中错误通常可恢复不同，这些场景下智能体的响应会直接作用于物理设备，因而可能导致不可逆的设备损坏、生产损失或人员伤害。然而，现有基准在很大程度上忽视了智能体推断角色意图并仅通过该角色可合法使用的工具行动的需求，我们将这种能力称为“视角意识”。为此，我们引入了 ReFract，一个包含 150 条经专家验证条目的基准，其中智能体必须根据用户角色对同一查询做出不同行动。ReFract 的条目源自领域支持对话中的匿名查询，我们据此构建文本世界模型，模拟智能体的操作环境并组装具备视角意识的行动轨迹。最先进的 LLM 最多只能解决 69% 的任务，且其超过 50% 的轨迹包含试图采取违背视角的行动。ReFract 揭示视角意识是智能体评估中一个独特且基本尚未解决的维度，并推动智能体不仅校准如何行动，还要校准为谁行动。

## Abstract
Large Language Model (LLM) agents are increasingly deployed in high-stakes settings such as industrial maintenance and equipment fault troubleshooting, where workers occupy a variety of roles. A capable agent must therefore act in a way that is calibrated to user's role: taking actions and providing information that respect the role's knowledge and capability boundaries. Unlike coding, where mistakes are usually recoverable, agent responses in these settings are enacted on physical equipment, and can therefore cause irreversible equipment damage, production loss, or personnel harm. Existing benchmarks, however, largely overlook the need for agents to infer what a role intends and acting only through tools that role may legitimately use, a capability which we term Perspective Awareness. To this end, we introduce ReFract, a benchmark of 150 expert-validated entries in which an agent must act differently in response to the same query depending on user's role. Entries of ReFract are grounded in anonymized queries from domain support conversations, against which we construct Text World Models that simulate the agent's operating environments and assemble perspective-aware action trajectories. State-of-the-art LLMs solve at most 69% of the tasks with more than 50% of their trajectories contain attempts of taking perspective-violating actions. ReFract exposes perspective awareness as a distinct, largely unsolved axis of agent evaluation and motivates agents that calibrate not just how to act, but for whom.

## 1. 论文的核心问题与整体含义

- **研究动机与背景**：大型语言模型（LLM）智能体正被部署到工业维护、设备故障排查等高风险场景。这些场景中的用户可能扮演不同角色（如操作员、技术员、控制工程师、计划员、经理），同一问题对不同角色的正确响应应不同：既要完成用户目标，又不能超出该角色的能力和授权边界。
- **核心问题**：现有智能体基准主要关注工具调用、任务完成、安全合规、角色扮演等，但普遍忽视“视角意识”（Perspective Awareness）——即智能体需要：
  1. 推断同一角色在提出查询时的意图；
  2. 仅通过该角色可合法使用的工具、可理解和解释的信息来行动；
  3. 当任务超出角色权限或知识范围时，将任务升级/路由给合适角色。
- **整体含义**：在高风险环境中，角色不匹配的行动会直接作用于物理设备，可能造成不可逆损害。因此，视角意识应成为智能体能力和安全性的一个独立评估维度，而不仅仅关注最终答案是否正确。
- **论文目标**：提出 ReFract 基准，系统量化、分析 LLM 智能体的视角意识，揭示现有模型的不足。

## 2. 论文提出的方法论

- **核心思想**：将“视角意识”形式化为两个互补维度：
  - **Perspective-Taking（视角理解）**：根据用户角色推断意图，并在该角色的能力与知识边界内行动；
  - **Perspective-Routing（视角路由）**：当任务超出用户职责时，将工作升级到具备相应能力和知识的角色。
- **任务形式化**：每个条目建模为部分可观测马尔可夫决策过程（POMDP）：
  \[
  \langle S, A, O, T, \Omega, G, R\rangle
  \]
  其中 \(S\) 为状态空间，\(A\) 为动作空间，\(O\) 为观测空间，\(T\) 为转移函数，\(\Omega\) 为观测函数，\(G\) 为目标状态，\(R_G\) 为基于目标达成度的奖励：
  \[
  R_G(S_T)=\frac{|G\cap S_T|}{|G|}
  \]
  智能体策略必须满足角色约束，即每一步动作都在角色的能力边界和知识边界内。
- **关键组件：Text World Model（TWM）**
  - **Domain File（\(D\)）**：声明领域文件，包括：
    - predicates（谓词，用于构建事实）；
    - capability gates（能力门控：角色是否有权执行某动作）；
    - knowledge gates（知识门控：角色是否有能力解释某些信息）；
    - retrieval sources（检索源）；
    - tool taxonomy（工具分类：retrieval、inspection、action、terminal）；
    - tools（工具，具有前置条件、输入槽、输出槽、效果、能力/知识门控）。
  - **Problem File（\(P(q)\)）**：针对每个查询，从 Domain File 中实例化一个可执行的世界模型，包括初始状态、可用工具、目标状态、参考轨迹。
  - 一个工具 \(t\) 只有在其前置条件已满足、所需输入值已产生、且角色的能力与知识门控允许时才能执行。
- **六阶段构建管道**：
  1. 从领域支持对话中筛选“视角敏感”查询；
  2. 通过 LLM 集成投票生成目标状态，并由专家标注；
  3. LLM 为每个目标生成候选世界模型和行动轨迹；
  4. 使用 Python 解释器执行并通过规则反馈进行有界修复；
  5. 根据角色能力/知识门控实例化角色变体并验证可达性；
  6. 重放参考轨迹，专家签署后纳入基准。
- **评估设置**：
  - **Query-Specific Tool Set (QTS)**：仅暴露与查询相关的工具，减少工具规划的干扰；
  - **Full Tool Set (FTS)**：暴露全部工具库（含大量无关工具），模拟真实部署。
- **指标**：
  - **Pass Rate (P.R.)**：最终状态满足目标的比例；
  - **Persona Compliance (P.C.)**：动作轨迹完全在角色边界内的比例；
  - **Over Reach (O.R.)**：越权使用工具的比例；
  - **Under Reach (U.R.)**：因过度保守而未使用本可合法使用的工具导致失败的比例；
  - **Efficiency (Eff.)**：相对参考轨迹的每步目标推进效率；
  - **Off-Goal Rate**：在角色可执行动作中却使目标不可达的动作比例。

## 3. 实验设计

- **数据集/场景**：
  - ReFract 基准包含 **150 个角色×任务条目**，来自 **40 个唯一会话**；
  - 覆盖 **5 种角色**：Operator（操作员）、Technician（技术员）、Controls Engineer（控制工程师）、Planner（计划员）、Manager（经理）；
  - 任务类型涵盖故障排查、流程 QA、协调、监控、报告等；
  - 任务形状包括控制配置、检查、机械修理、完整锁止修理、仅知识信息等；
  - 能力门控条目 102 个，知识门控条目 48 个。
- **对比模型**：
  - 开源模型：Qwen3-32B、Qwen3-80B-A3B、Qwen3-235B-A22B、GPT-OSS-20B、GPT-OSS-120B、Gemma-4-26B-A4B、Gemma-4-31B；
  - 专有模型：GPT-5.5、GPT-5.6-Luna、GPT-5.6-Terra、GPT-5.6-Sol；
  - 因为 Claude 系列参与数据生成，为避免循环，不将 Claude 系列作为基线。
- **智能体脚手架**：
  - **Function Calling**：原生结构化工具调用；
  - **ReAct**：在调用工具前可进行文字推理。
- **实验设置**：
  - 两种工具集：QTS、FTS；
  - 每个模型推理运行 **5 次** 以评估方差；
  - 所有模型使用默认超参数；
  - 开源模型通过本地高效推理引擎以 OpenAI 兼容接口提供服务，专有模型通过托管 API 访问。

## 6. 论文的主要结论与发现

- **ReFract 对现有最强模型仍然困难**：
  - 最强配置（GPT-5.6-Sol + ReAct）在 QTS 下 Pass Rate 只有 **0.685**；
  - 多数开源模型 Pass Rate 不超过 50%；
  - FTS 下最好 Pass Rate 降至 **0.473**（Function Calling）或 **0.466**（ReAct）。
- **扩大工具空间会显著削弱视角意识**：
  - QTS → FTS 时，所有模型的 Pass Rate 和 Persona Compliance 均下降；
  - 鲁棒性与 QTS 强度呈负相关（Spearman \(\rho = -0.64\)，Function Calling；ReAct 下 \(\rho = -0.90\)）。
- **主要失败模式是过度保守而非越权**：
  - 强模型如 GPT-5.6 系列大多倾向于 Under Reach（例如 Sol：0.566 Under vs. 0.175 Over）；
  - 作者认为这可能是安全对齐的副作用——模型倾向于全局谨慎，而非根据角色边界灵活调整。
- **知识门控比能力门控更容易被突破**：
  - 平均而言，知识边界违规是能力边界违规的 **1.54 倍**；
  - Qwen3 家族知识违规尤为突出（Qwen3-235B: 0.227 知识 vs. 0.093 能力）。
- **存在干扰工具时，升级/咨询行为大幅崩溃**：
  - 在知识门控“咨询”轨迹中，FTS 下正确咨询率从 QTS 的 67–71% 降至 **42%**（Function Calling）和 **17%**（ReAct）。
- **宽权限角色最难合规**：
  - Planner 和 Manager 等宽权限角色 Pass Rate 较高但 Persona Compliance 较低；
  - 因为他们拥有较多工具权限，需要主动“选择不作为”并升级给正确角色，这对模型尤其困难。
- **轨迹分歧不等于真正的角色差异化**：
  - 偏离参考轨迹更大的模型并不一定获得更高 Pass Rate；
  - 最强 GPT 模型的轨迹分歧接近参考值（0.31–0.35），而过度偏离者表现较差。
- **总体结论**：视角意识是独立且尚未解决的智能体评估维度；需要“多元对齐”（pluralistic alignment）使智能体根据不同的角色边界校准行为，而非采用全局一刀切的谨慎策略。

## 7. 优点

- **问题定义清晰且重要**：首次明确将“视角意识”分解为 Perspective-Taking 和 Perspective-Routing，并强调其在高风险工业场景中的安全意义。
- **环境可控且可执行**：使用手写 Python 文本世界模型，而不是纯 LLM 模拟，保证状态转移确定、可复现、可验证，降低 LLM 模拟不可靠性的影响。
- **双轴门控设计**：能力（authority to act）与知识（competence to interpret）相互独立，能细致区分越权执行与无法解读信息两类错误。
- **专家深度参与**：领域文件由专家共同编写，150 条目标均经专家标注，增强了基准的领域可信度。
- **生成管道严谨**：LLM 提案 + 确定性执行检查 + 专家审核的管道，每一阶段都有否决机制，减少低质量数据进入。
- **评估指标丰富**：不仅看最终通过率，还分解为合规、越权、过度保守、效率、离目标率等，能揭示失败原因。
- **实验覆盖广**：开源与专有模型、两种脚手架、两种工具空间、多次重复，结果具有说服力。
- **避免生成器偏差**：基准生成中使用的 Claude 系列被排除在评测模型之外，降低了循环偏差。

## 8. 不足与局限

- **领域与角色单一**：当前 150 条目只覆盖工业维护一个领域和五个固定角色；是否能推广到临床、法律、金融等其他高风险领域仍需验证。
- **规模有限**：样本量受专家标注成本限制，统计功效较弱，尤其是细粒度角色/任务切片上差异可能不够可靠。
- **世界模型理想化**：文本世界模型是确定性的、封闭的，没有随机动态、传感器噪声、部分可观测不确定性或开放世界工具发现，与真实部署仍有差距。
- **生成器偏差风险**：尽管排除了 Claude 基线，但数据筛选、目标生成、世界模型起草仍由 Claude 模型完成，可能对保留的查询、目标、可行性轨迹产生偏好。
- **角色直接给出且单轮评估**：智能体在推理时直接获得角色标签，无需从对话中推断用户身份；评估是单轮、非交互的，无法考察主动澄清或动态角色识别。
- **未明确计算资源**：论文未报告 GPU 型号、数量、推理成本等，影响实验复现性和资源估算。
- **GPT-OSS-20B 在 ReAct 下缺席**：因不符合文本工具调用协议被排除，可能影响该模型在不同脚手架下的完整比较。
- **扩展性受限**：未来扩展到新领域需要重新编写 Domain File，且每条数据的专家验证成本较高。
