## 摘要
近期研究表明，基于执行反馈的强化学习能够大幅提升文本到 SQL 的性能，往往使较小模型达到甚至超过更大的系统。然而，现有大多数方法将 SQL 生成视为单轮任务，限制了模型通过迭代修正从错误中恢复的能力。我们提出 ReToolSQL，一个用于文本到 SQL 的两阶段训练框架，结合了 (i) 在拒绝采样推理轨迹上的监督热启动与 (ii) 在多轮工具使用轨迹上的智能体强化微调（RFT）。其核心洞察在于这两个阶段作用于互补的维度：在经验证的特权教师轨迹上的监督微调（SFT）扩大了可解答问题的集合（在最困难情况下提高了 pass@k 覆盖率），而 RFT 通过教会模型何时进行验证、检索何种证据以及如何根据执行反馈修复有缺陷的 SQL，将这种扩展的能力转化为更高的单遍准确率。应用于 Gemma 4 指令微调模型（31B）时，仅 RFT 就在 BIRD-SQL 开发基准上取得了 73.66% 的执行准确率（EX）（使用自洽性时为 74.12% EX）。从 SFT 检查点初始化 RFT（SFT→RFT）得到了我们最强的模型，单遍 EX 为 74.32%，使用自洽性时为 74.77% EX。截至撰写本文时，该模型在 BIRD 单模型开发集排行榜上排名第一。该方法使用以执行正确性为锚定的复合奖励，除了基准本身之外无需任何人工标注，并且在单个稠密 31B 模型中运行，表明在工具使用轨迹上精心设计的 SFT→RFT 流水线是实现稳健企业级文本到 SQL 的实用路径。

## Abstract
Recent work has shown that reinforcement learning from execution feedback can substantially improve text-to-SQL performance, often enabling smaller models to match or exceed much larger systems. However, most existing approaches treat SQL generation as a single-turn task, limiting the model's ability to recover from errors through iterative refinement. We present ReToolSQL, a two-stage training framework for text-to-SQL that combines (i) a supervised warm-start on rejection-sampled reasoning traces with (ii) agentic reinforcement fine-tuning (RFT) over multi-turn tool-use trajectories. The key insight is that the two stages act on complementary axes, the supervised fine-tuning (SFT) on verified privileged-teacher traces expands the set of solvable questions (raising pass@k coverage on the hardest cases), while RFT converts that expanded capability into higher single-pass accuracy by teaching the model when to verify, what evidence to retrieve, and how to repair faulty SQL from execution feedback. Applied to Gemma 4 instruction-tuned (31B), RFT alone achieves 73.66% execution accuracy (EX) on the BIRD-SQL development benchmark (74.12% EX with self-consistency). Initializing RFT from the SFT checkpoint (SFT$\to$RFT) yields our strongest model at 74.32% EX single-pass and 74.77% EX with self-consistency. At the time of writing, this ranked first on the BIRD single-model development-set leaderboard. The approach uses composite rewards anchored on execution correctness, requires no human annotation beyond the benchmark itself, and operates within a single dense 31B model, showing that a properly designed SFT$\to$RFT pipeline over tool-use trajectories is a practical path toward robust enterprise-grade text-to-SQL.

# ReToolSQL 论文详细总结

## 1. 论文的核心问题与整体含义

- **研究背景**：文本到 SQL 是自然语言访问数据库的关键接口，但在真实场景中仍面临 schema 庞大、取值噪声多、执行正确性难以保证等挑战。BIRD 基准以执行准确率（EX）为核心指标，暴露了现有模型在 schema 链接、值对齐、数值/时间推理等方面的不足。
- **核心问题**：当前基于执行反馈的强化学习（RLVR）虽然能显著提升文本到 SQL 性能，但大多将 SQL 生成视为**单轮任务**——模型只生成一次查询并接收终局奖励，缺少从执行错误中**迭代恢复**的机制。与此同时，许多强系统依赖多生成器、选择器或编排管线，推理复杂度高、部署成本大。
- **整体含义**：能否让一个**单稠密模型**通过工具交互学会“提议—验证—修复”的完整闭环，同时保持简单的服务架构？ReToolSQL 通过两阶段 SFT→RFT 训练给出肯定回答，证明智能体式强化学习可以内化验证与修复能力，为稳健的企业级文本到 SQL 提供实用路径。

## 2. 论文提出的方法论

### 2.1 核心思想：两阶段互补训练

- **SFT 热启动**：在拒绝采样的验证轨迹上做监督微调，包含“特权教师轨迹”（针对模型无法解决的难题，利用 gold SQL 生成逐步推理链并验证执行正确）和“自我轨迹”（针对模型已能解决的题目，收集自身正确推理）。其作用是**扩大可解问题集合**，提升 hard 问题的 pass@16 覆盖率。
- **智能体强化微调（RFT）**：在多轮工具使用轨迹上做 GRPO 式强化学习，使模型学会**何时验证、检索什么证据、如何修复错误 SQL**，将扩展后的能力转化为更高的单遍准确率。
- **互补性**：SFT 扩覆盖，RFT 提单遍；两者组合（SFT→RFT）优于任一单独阶段。

### 2.2 技术细节

- **问题建模**：将文本到 SQL 建模为 POMDP，策略为单自回归语言模型，与环境中的只读工具交互，轨迹终止于 `<final_answer>` 或达到 8 轮工具预算。
- **Schema 表示**：采用 M-Schema 编码，为每列提供类型、语义、空值/区分度统计、Top 值和示例值等，使 schema 链接基于真实数据证据而非列名相似度。
- **工具套件（验证优先）**：
  - `sqlite_query`：沙盒 SQL 执行器（仅 SELECT/WITH），返回结果或结构化错误。
  - `sqlite_peek`：列分析器，返回类型、空值/区分度统计、极值、样例等，用于消除类型/尺度/日期格式歧义。
  - `bm25_search_sqlite`：混合词法搜索，结合 BM25 与正则/子串回退，用于修复字符串/类别字面量不匹配。
- **强化学习目标**：GRPO + DAPO 变体，采用组相对优势、非对称裁剪（下限 0.20，上限 0.28）、衰减 KL 惩罚（β 从 0.005→0.001→0）以保持熵。
- **动态采样**：每个训练步从备份池过采样 12 倍 prompt，每组生成 16 条轨迹，仅保留执行奖励标准差 ≥ 10⁻⁶ 的组，避免零方差组浪费计算。
- **工具观测掩码**：对工具返回的环境观测 token 做损失掩码，防止模型记忆数据库内容，同时保留其在注意力上下文中供后续轮次使用。
- **复合奖励**：7 个可验证项加权和：
  - 执行结果等价（EX）：权重 2.0（主导项）；
  - 语法正确：0.5；
  - 格式合规：0.2；
  - 表集合覆盖 gold 表：0.5；
  - 列 Jaccard 相似度：0.5；
  - 非空结果：0.1；
  - 长度惩罚（DAPO soft overlong）：0.1。
- **推理时自洽性**：采样 16 条候选轨迹，按执行结果聚类，返回最大簇的代表 SQL，无需学习选择器。

### 2.3 训练流程

- 先 SFT 热启动：在 BIRD 训练集中挖掘“全错带”，用 gold SQL 提示生成特权教师轨迹并验证；简单/中等题收集自我轨迹；合并后做因果语言模型微调。
- 再从 SFT 检查点初始化 RFT，在工具交互环境中用 GRPO 优化完整轨迹。

## 6. 论文的主要结论与发现

- **两阶段互补**：SFT 提升 pass@16 覆盖率（76.9%→81.29%），RFT 提升单遍准确率（71.19%→73.66%），SFT→RFT 结合二者，达到最优 74.32% 单遍、74.77% 自洽性。
- **RL 与工具存在交互效应**：工具访问本身仅带来 +2.02%；RL 无工具仅 +0.45%；两者结合 +3.97%，超出加性部分 1.50%，说明 RL 专门教会了模型有效使用工具。
- **熵保持至关重要**：在 E4B 上，衰减 β 调度比无 KL 惩罚提升 2.09% 贪婪准确率和 1.96% 自洽性，且熵下降慢约 2 倍，防止了过早熵崩溃。
- **模型规模影响**：E4B 从 RL 获得的相对增益更大（+3.33% vs. +1.95%），且样本多样性更高（每次 16 采样有 6.31 个唯一 SQL vs. 3.37），推理自洽性提升更明显；但 31B 绝对性能仍更高。
- **难度分层**：RL 模型在 Moderate 提升最大（+5.19%），工具增强验证对复杂查询最有效；Challenging 题目最终准确率最高（75.32%），与 rich hint 相关。
- **单模型可竞争复杂管线**：在 BIRD 单模型开发榜上，单个 31B 稠密模型通过简单自洽性即达到或超过多生成器/选择器/MoE 系统。

## 7. 优点

- **方法设计巧妙**：将工具使用直接嵌入 RL 训练环境，让模型从执行反馈中学习“提议—验证—修复”，而非仅作为后处理过滤器。
- **两阶段互补清晰**：SFT 扩覆盖、RFT 提单遍的机制在实验中得到了定量验证，具有较强解释性。
- **工程实现扎实**：DAPO 动态采样、工具观测掩码、衰减 KL 调度等细节有效解决了 RL 训练中的熵崩溃、零梯度组、token 泄漏等问题。
- **单模型架构简单**：部署只需单个稠密 31B 模型和自洽性解码，无需外部检索器、选择器或编排层，推理成本低。
- **奖励设计二元为主**：执行正确性权重最大，辅以 schema 链接信号，兼顾稀疏奖励与梯度稳定性；权重启发式但实验表明不敏感。

## 8. 不足与局限

- **未在 BIRD 官方 test 集上评估**：仅报告 dev 集结果，虽 dev 数据库与训练不重叠，但仍存在开发集调优偏差；真实泛化能力需 test 集验证。
- **自洽性增益有限**：31B 模型 16 采样仅从 74.32% 提升至 74.77%（+0.45%），主要由高一致性导致；论文也承认 pass@16 上限有约 3% 的未实现潜力，但未给出更好的选择器方案。
