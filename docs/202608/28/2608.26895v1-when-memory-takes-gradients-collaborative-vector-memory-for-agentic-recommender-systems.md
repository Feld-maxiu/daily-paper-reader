## 摘要
智能体推荐系统将大语言模型（LLM）的每个决策建立在用户的持久记忆之上，而现有智能体中的记忆是文本：由进一步的大语言模型调用编写和维护的叙述。文本在两方面限制了这种记忆。它一次只更新一次重写，因此利用完整的交互历史代价高昂；并且协同证据（在整个目录上的分级相似性）在转化为句子后无法保留。我们提出 CoVeMem（协同向量记忆），它将智能体记忆的协同核心向量化。冻结的 LightGCN 用户和物品状态构成记忆库；在每次决策时，候选集本身检索最相关的历史状态，这些状态以软令牌的形式与轻量文本画像一起进入 LLM 的上下文。通过对比对齐到物品语义锚点，随后与掩码候选进行列表式联合训练，教会模型读取这些状态并据此进行排序；逐点的“是/否”读出为每个候选评分。在四个基于指令的推荐基准上，CoVeMem 在 20 个指标单元中的 19 个上达到或超过了最强的协同文本记忆智能体，同时除了共享的静态画像外，无需额外的 LLM 调用来维护记忆，而文本记忆则需要每次交互都调用。现在记忆参与梯度更新：文本无法企及的完整交互历史，成为智能体记忆内容及其读取记忆方式可用的训练数据。

## Abstract
Agentic recommender systems ground each decision of a large language model (LLM) in a persistent memory of the user, and in existing agents that memory is text: a narrative written and maintained by further LLM calls. Text limits this memory in two ways. It is updated one rewrite at a time, so exploiting the full interaction history is prohibitively expensive; and collaborative evidence, graded similarity over an entire catalog, does not survive translation into sentences. We propose CoVeMem (Collaborative Vector Memory), which vectorizes the collaborative core of the agent's memory. Frozen LightGCN user and item states form the memory bank; at each decision, the candidate set itself retrieves the most relevant historical states, which enter the LLM's context as soft tokens alongside a light textual profile. Contrastive alignment to item-semantic anchors, followed by listwise co-training with masked candidates, teaches the model to read these states and to rank through them; a pointwise yes/no readout scores each candidate. Across four instruction-grounded recommendation benchmarks, CoVeMem matches or exceeds the strongest collaborative text-memory agent on 19 of 20 metric cells while requiring zero additional LLM calls for memory maintenance beyond the shared static profile, against per-interaction calls for text memory. The memory now takes gradients: the full interaction history, out of reach for text, becomes available as training data for what the agent remembers and for how it reads what it remembers.

## 1. 论文的核心问题与整体含义

- **研究背景**：智能体推荐系统（Agentic Recommender Systems）将大语言模型（LLM）置于用户与推荐平台之间，依赖持久记忆来累积用户偏好并裁决候选项目。现有智能体记忆几乎都采用文本叙述形式，由额外的 LLM 调用逐次重写维护。
- **核心问题**：文本记忆存在两个根本局限：
  - **维护成本高**：每次吸收新交互都需要一次 LLM 重写，难以利用完整交互历史；
  - **协同结构丢失**：协同过滤中的全局分级相似性（覆盖整个目录）在序列化为句子时被压缩，文本只能“说出”少数邻居或方面，大量几何信息在序列化中丢失。
- **整体含义**：论文提出将智能体记忆的协同核心向量化，使记忆本身可被推荐目标训练，并让排序梯度直接优化“如何读取”记忆，突破文本记忆的可扩展性与表达能力瓶颈。

## 2. 方法论

- **核心思想**：用向量状态存储协同证据，通过可训练的“参数化记忆读取器”（projector + LoRA）将向量状态映射为 LLM 可读的软令牌，从而在 LLM 上下文中保留协同信息。
- **记忆库构建**：
  - 使用 LightGCN 在训练交互图上学习用户和物品状态（维度 d=64），随后冻结；
  - 用户保留一份轻量文本画像（从训练评论中蒸馏一次）；
  - 候选集决定检索：计算候选集中各物品状态的平均质心 \(\bar{c}\)，再从用户可用历史中检索与 \(\bar{c}\) 内积最大的 K=5 个历史物品，实现目标感知检索（无需 LLM 调用）。
- **记忆注入**：
  - 门控投影器 \(\phi\) 将用户、历史物品、候选物品状态映射到 LLM 输入嵌入空间，每个状态占用一个软令牌位置；
  - 提示中包含固定记忆模式：文本画像、token 历史行、标题行、用户 token、候选行（标题 + 物品 token）。
- **训练读取器（两阶段）**：
  - **阶段 1：语义锚点对齐**：为每个物品构建语义锚 \(y_i\)（物品标题和类别嵌入的平均），用对称 in-batch 对比损失训练投影器，使投影状态进入有意义的语言空间。
  - **阶段 2：列表式共训练**：将每个训练交互构造为排名事件（前缀为历史、正项为交互项、负项从用户序列外采样）。候选项以 50% 概率掩码标题，使模型必须依赖协同 token 进行区分；通过边界损失（hinge loss）在竞争池上优化排名。当正项被掩码时，损失只在被掩码候选中计算，强制模型读取协同证据。
  - **防止文本捷径**：掩码 + 列表式竞争确保标题不能单独解决问题；软令牌门控从 0 到 1 逐步开启，减少初期不稳定。
- **推理与评分**：
  - 采用点式 yes/no 读出：每个候选单独生成一个紧凑提示，输出 “Yes” 令牌的 logit 作为分数，并行评分 N 个候选，避免生成式排名解析失败；
  - 指令位置（early/middle/late）通过零样本规则卡（只使用训练集统计量）预测，每个数据集选择一个位置。

## 6. 主要结论与发现

- **总体性能**：CoVeMem 在 4 个数据集 × 5 指标共 20 个单元中，19 个达到或超过最强文本记忆智能体 MemRec；尤其在 Goodreads 上优势显著（Hit@1 0.7730 对 MemRec 0.3087）。
- **消融发现**：
  - 目标感知检索有帮助，但主要提升来自注入的协同状态；
  - 移除 LoRA 后性能骤降至接近或低于随机水平，说明适配器是读取向量记忆的关键。
- **骨干影响**：方法可迁移到不同协同骨干，但记忆库质量直接决定收益，SVD++ 表现最好，SASRec 最弱且无清晰优势。
- **效率优势**：CoVeMem 的 LLM 记忆维护成本为零（向量组件一次性离线构建），决策 token 成本最低，处于高精度 Pareto 前沿。
- **核心结论**：记忆载体本身成为设计轴——向量记忆使完整交互历史成为训练数据，记忆可接受梯度，不再只是代理需要书写的产物，而是可训练组件。

## 7. 优点

- **方法创新**：首次将协同向量状态作为智能体推荐系统的持久协同记忆，并训练 LLM 读取这些状态，而非仅仅作为条件输入。
- **训练设计巧妙**：语义锚点对齐 + 掩码列表式共训练有效防止文本捷径，迫使模型真正利用协同证据；门控机制稳定训练。
- **效率突出**：与文本记忆智能体相比，记忆维护零额外 LLM 调用，推理阶段用点式 yes/no 避免生成解析失败，决策成本最低。
- **模块化设计**：记忆库可替换为不同协同骨干，验证了方法的通用性和协同信号的可移植性。
- **实验全面**：覆盖四个域、多个基线、消融、骨干研究、效率分析，统计检验充分。

## 8. 不足与局限

- **训练与推理不一致**：训练时故意省略用户指令，而推理时加入指令，可能影响模型对指令与协同记忆之间交互的建模。
- **候选集规模有限**：仅评估 N=10 候选，实际推荐系统往往需要从更大候选池中排序，方法在大规模候选下的表现未知。
- **单 LLM 骨干**：实验仅使用 Qwen2.5-7B-Instruct，未验证其他 LLM 上的有效性。
- **记忆库静态且一次性**：LightGCN 状态冻结，类别新增或交互更新需重新训练图状态，无法在线更新协同信号。
- **训练期信息使用**：记忆库和文本画像使用全训练期构建，可能与因果评估略有冲突（作者承认但认为与基线一致）；测试目标虽已排除，但训练事件的前缀因果性仅在候选集层面保证。
- **对骨干质量敏感**：若协同骨干质量差，向量记忆可能无益甚至干扰，缺乏对低质量状态的自动降级机制。
- **指令位置选择依赖零样本规则卡**：虽未使用验证反馈，但规则卡可能隐含作者先验，且未对比所有位置的敏感性。
