## 摘要
大型语言模型（LLMs）越来越多地作为自主智能体执行复杂、长期运行的程序性技能。现有的智能体运行时通过不断将观察、动作和中间推理轨迹追加到不断增长的对话历史中来维持执行，导致长时间跨度下的延迟退化和上下文污染故障。我们提出 SKILL.state，一种用显式的、可变的执行状态取代仅追加式对话历史的运行时架构。在每个执行步骤中，模型仅接收不可变的技能规范、当前结构化执行状态和最新观察。中间推理在生成经过验证的状态更新后立即被丢弃，从而防止提示随执行历史增长。在多样化的数据集、模型和执行环境中，SKILL.state 提高了任务准确性，同时大幅减少了累积 token 消耗。我们的结果表明，显式执行状态是一种有效且与架构无关的抽象，适用于可扩展的长时程智能体技能。

## Abstract
Large Language Models (LLMs) increasingly act as autonomous agents executing complex, long-running procedural skills. Existing agent runtimes maintain execution by continually appending observations, actions, and intermediate reasoning traces to an ever-growing conversation history, causing latency degradation and context-poisoning failures over long horizons. We present SKILL.state, a runtime architecture that replaces append-only conversational history with an explicit, mutable execution state. At each execution step, the model receives only the immutable skill specification, the current structured execution state, and the latest observation. Intermediate reasoning is discarded immediately after producing a validated state update, preventing prompt growth with execution history. Across diverse datasets, models, and execution environments, SKILL.state improves task accuracy while substantially reducing cumulative token consumption. Our results demonstrate that explicit execution state is an effective and architecture-agnostic abstraction for scalable long-horizon agent skills.

  - 执行正确性越来越依赖从累积文本历史中重建状态，而非直接维护当前世界状态。
- **整体含义**：长时程智能体执行不只是一个推理问题，更是一个系统架构问题。论文主张用**显式的、可变的执行状态**取代追加式对话历史，使执行成为“状态转移”而非“历史重放”，从而从根本上控制上下文增长。

## 2. 论文提出的方法论

### 2.1 核心思想

- SKILL.state 将程序性技能执行重新表述为**显式状态转移过程**，每一步输入仅为：
  \[
  A_t = (P, \Sigma_t, O_t)
  \]
  其中 \(P\) 为不可变技能规范，\(\Sigma_t\) 为当前结构化执行状态，\(O_t\) 为最新环境观察。
- 模型**不会**收到先前的观察、动作或推理轨迹；历史对话被完全移除。
- 中间推理仅作为产生状态更新的临时计算，在通过验证后被**永久丢弃**。

### 2.2 状态与模式设计

- 执行状态 \(\Sigma_t\) 是运行时的一等抽象，只包含未来执行所需的信息，使用按领域定义的**结构化模式（schema）**表示。
- 模式按领域（而非任务）一次性编写。例如，InterCode CTF 的 100 个不同挑战实例复用同一个 5 字段模式：`discovered_flags`、`tested_hypotheses`、`active_files`、`working_dir`、`cmd_summary`。
- 状态更新采用 JSON 字典补丁（key 的修改与删除），`null` 表示删除键。

### 2.3 执行流程（Algorithm 1 概括）

1. 接收最新观察 \(O_t\)；
2. 构造提示 \((P, \Sigma_t, O_t)\)；
3. LLM 生成三元组：
   \[
   (R_t, \Delta\Sigma_t, a_t)
   \]
   其中 \(R_t\) 为多步思维链推理，\(\Delta\Sigma_t\) 为结构化状态更新（JSON 字典），\(a_t\) 为待执行动作；
4. 确定性验证 \(\Delta\Sigma_t\)；
5. 应用状态更新：
   \[
   \Sigma_{t+1} = \Sigma_t \oplus \Delta\Sigma_t
   \]
   其中 \(\oplus\) 是带 null 删除语义的字典合并算子；
6. 执行动作 \(a_t\)，进入下一轮。
- 步骤内的多步推理完整保留，以支持复杂演绎规划；但推理痕迹在状态转换后立即抛弃，不进入后续提示。

### 2.4 复杂度分析

- 对话式运行时：第 \(t\) 步提示长度 \(|C_t| = O(t)\)，累计 token 复杂度：
  \[
  \sum_{t=1}^{T}|C_t| = O(T^2)
  \]
- SKILL.state 每一步提示为：
  \[
  |P_t| = O(|P| + |\Sigma| + |O|)
  \]
  与历史步数 \(t\) 无关，提示规模为 \(O(1)\)；累计复杂度为：
  \[
  \sum_{t=1}^{T}|P_t| = O(T)
  \]

## 6. 论文的主要结论与发现

- **长时程扩展**：SKILL.state 在所有时段上保持或超过基线准确率，同时维持近似恒定的平均 prompt 大小（约 1,736–1,905 tokens）。在 \(T=100\) 的 Warehouse 任务上，Stateful 消耗 1,062,387 tokens，SKILL.state 仅消耗 65,408 tokens，减少约 16.2 倍；在 \(T=200\) 时，SKILL.state 准确率保持 0.94，而 Memory 基线累计消耗膨胀至 610 万 tokens。
- **噪声鲁棒性**：标准 Prompt 在噪声 5 到 50 事件/轮时准确率从 0.68 降至 0.53；SKILL.state 始终保持在 0.97–0.98，因为干扰在状态补丁生成过程中被过滤，不会进入后续提示。
- **状态恢复**：历史上基于语境的基线在外部状态漂移后需要 5–8 个连续步骤才会恢复，而 SKILL.state 在收到纠正性观察后立即更新结构化状态，恢复步数为 0。
- **公共基准**：SKILL.state 在所有三个公共基准上取得最高成功率，并显著降低 token 消耗。InterCode CTF pass@1 达到 54.2%，比最强基线高 7.8 个百分点，比 Stateful 高 12.4 个百分点；总 token 比 ReAct 减少 60.4%，比 Stateful 减少 65.9%。τ-Bench Retail 和 Airline 也分别领先，Airline 中 SKILL.state 维持约 2,800 tokens/步的平坦足迹。
- **预算匹配对比**：当把压缩基线强制到与 SKILL.state 相同的 token 预算时，所有压缩基线均出现灾难性失败：滑动窗口截断降至 0.18，LLMLingua 降至 0.22；而 SKILL.state 保持 0.94。说明性能提升来自结构化状态表示，而非简单缩短 prompt。
- **开源模型错误分类**：在 Gemma-4-31B 上失败主要源于结构化输出遵从问题，而非推理能力，包括：过早覆盖/删除状态（68%）、模式理解与类型强制（20%）、JSON 语法/格式错误（12%）。

## 7. 优点

- **架构无关性**：SKILL.state 是一种可叠加在任意 LLM 之上的运行时抽象，不依赖特定模型或框架。
- **严格的理论基础**：给出明确的复杂度分析，提示规模 \(O(1)\)、累计 token \(O(T)\)，与经验结果一致。
- **状态作为充分统计量**：丢弃中间推理而非压缩历史，从根本上避免上下文污染和过时信息干扰。
- **实验设计严谨**：
  - 同时使用受控合成基准和真实公共基准；
  - 固定随机种子、确定性解码、5 种子统计检验，保证公平可复现；
  - 引入预算匹配控制，区分“缩短 prompt”与“结构化状态表示”的贡献。
- **鲁棒性强**：在噪声干扰下保持高性能，外部状态漂移下实现零恢复步数。
- **资源节省显著**：在多个任务上将 token 消耗降低数十倍，同时准确率不降反升。

## 8. 不足与局限

- **核心假设限制**：SKILL.state 假设执行状态可以成为未来执行的充分统计量，即所有与未来行为相关的历史信息都能在已知时立即投影到结构化状态中。该假设在以下三种情况失效：
  1. 执行前未知固定模式，相关状态结构必须在执行过程中动态发现；
  2. 某个早期观察的相关性当时未被识别，因而从未被写入状态；
  3. 任务目标本身定义在历史轨迹上（如审计、调试溯源、解释过去行为），历史是目标输出而非操作开销。
- **单智能体限制**：当前实现仅针对单智能体程序性执行。虽然显式状态抽象可自然扩展到多智能体系统，但多智能体环境会引入并发写入，需要在合并算子 \(\oplus\) 中设计确定性冲突解决语义，而本文未涉及。
- **对模型结构化输出能力的依赖**：SKILL.state 依赖 LLM 生成有效的结构化状态补丁。对于较小的开放权重模型，结构化输出遵从性较差，需要引入语法约束解码来消除语法格式错误。
- **实验覆盖有限**：公共基准只有两个（InterCode CTF、τ-Bench），模型仅三个（Gemini-3-Flash、Gemma-4-31B-it、Qwen-3-8B-it）；未在更复杂、更大规模的真实生产工作流中验证。
- **未讨论训练或微调**：论文没有涉及任何针对状态补丁生成的模型训练或微调，也未报告推理阶段的具体硬件开销。
