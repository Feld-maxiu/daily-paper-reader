## 摘要
面向大语言模型的强化学习（RL）正朝着多轮智能体工作负载发展，其中 rollout 任务会反复因外部环境而暂停、在上下文不断增长的情况下恢复，并在高度可变的时间完成。在这一场景下，以训练吞吐量衡量的 RL 训练有效吞吐量比单纯的 GPU 占用率更为重要：GPU 等待和重复的 prefill 重计算都是纯粹的开销。我们提出 TideRL，一个具备就绪感知能力的弹性 RL 系统，包含连续任务批处理（Continuous Task Batching）、资源感知的 Ref-Actor 流水线（Resource-Aware Ref-Actor Pipelining）以及弹性资源伸缩（Elastic Resource Scaling）。CTB 保留有用的 rollout 状态，\textrm{RA}^2\textrm{P} 根据就绪积压和到达间隔在解耦流式与共置聚合之间进行选择，ERS 利用相同的就绪信号在 rollout 与训练之间移动 rank。在纯文本和多模态智能体工作负载上，TideRL 相比同步基线将 RL 训练有效吞吐量提升最高 5.6 倍，相比异步基线提升超过 33%，同时达到相近的任务性能。它还将 KV 缓存命中率提高 1.58 倍，将每步训练时间最多降低 44.3%，并将总等待时间最多减少 77.6%。

## Abstract
Reinforcement learning (RL) for large language models is moving toward multi-turn agentic workloads, where rollout tasks repeatedly pause for external environments, resume with growing contexts, and finish at highly variable times. In this setting, RL training goodput, measured by training throughput, matters more than raw GPU occupancy: GPU waiting and repeated prefill recomputation are pure overhead. We present TideRL, a readiness-aware elastic RL system with Continuous Task Batching, Resource-Aware Ref-Actor Pipelining, and Elastic Resource Scaling. CTB preserves useful rollout state, $\textrm{RA}^2\textrm{P}$ selects between decoupled streaming and colocated aggregation from the ready backlog and arrival interval, and ERS moves ranks between rollout and training using the same readiness signals. Across text-only and multi-modal agentic workloads, TideRL improves RL training goodput by up to 5.6$\times$ over synchronous baselines and over 33% over asynchronous baselines, while reaching similar task performance. It also improves KV cache hit rate by 1.58$\times$, reduces per-step training time by up to 44.3%, and cuts total waiting time by up to 77.6%.

## 1. 论文的核心问题与整体含义

- **研究背景**：大语言模型（LLM）的强化学习（RL）正从单轮推理任务转向多轮智能体（agentic）工作负载。在智能体 RL 中，rollout 任务会反复因等待外部环境反馈而暂停，在上下文不断增长的情况下恢复，并在高度可变的时间完成。
- **核心问题**：传统 RL 系统以 GPU 占用率为优化目标，但在多轮智能体场景下，真正重要的是**训练有效吞吐量（goodput）**，即“被 Trainer 实际消费并推动模型更新的 rollout token 数/秒”。GPU 空等与重复 prefill 重计算属于纯粹开销。
- **三大具体瓶颈**：
  1. **KV 缓存抢占**：请求级连续批处理在多轮交互间歇会贪婪地驱逐缓存，任务恢复时出现灾难性缓存未命中，导致重复 prefill。
  2. **训练停滞与抖动**：Trainer 中 Ref 和 Actor 模型共享 GPU，要么等待完整全局批次造成 GPU 空闲，要么频繁切换模型造成 I/O 抖动。
  3. **静态资源分配僵化**：rollout 与训练之间的资源比例固定，无法适应生产者-消费者瓶颈的动态转移。
- **整体含义**：该论文提出一种**就绪感知（readiness-aware）的弹性 RL 系统**，通过统一调度 roll-out 状态、训练执行模式与 GPU 资源分配，最大化多轮智能体 RL 的训练有效吞吐。

## 2. 论文提出的方法论

TideRL 由三个协同设计的组件组成，共享就绪信号（RAS 和 TPRM）：

### 2.1 连续任务批处理（CTB）
- **核心思想**：将 rollout 调度从请求级提升到任务级，以保留有用的任务状态（尤其是 KV 缓存）。
- **关键技术细节**：
  - **Token 感知准入控制**：将每个数据并行 rank 视为 token 预算池，通过轻量探测任务估计首轮 token 足迹，仅在剩余缓存空间足够时准入新任务。
  - **语义感知暂停与恢复**：当某 rank 的缓存预算超限时，按优先级暂停低优先级任务；优先级公式为  
    \(P(t) = \omega_1 \cdot I_{\text{eval}} + \omega_2 \cdot G_{\text{completion}} + \omega_3 \cdot I_{\text{active}} + \omega_4 \cdot L_{\text{context}}\)  
    其中评估任务、GRPO 组完成度、正在执行的任务和上下文长度分别赋予不同权重。
  - **恢复策略**：优先恢复暂停任务而非准入新任务，并基于组 ID 实施 worker 亲和性，以保留共享前缀缓存。
- **算法流程**：如 Algorithm 1 所示，循环更新活跃任务 token 足迹，超预算时暂停最低优先级任务，恢复缓存空间后优先恢复暂停任务，再准入新任务。

### 2.2 资源感知的 Ref-Actor 流水线（RA²P）
- **核心思想**：根据两个数据就绪信号动态选择 Ref-Actor 执行模式：
  - **RAS（Ready-at-Start）**：训练步骤开始时已就绪的微批次数量。
  - **TPRM（Time Per Ready Micro-batch）**：步骤开始后新微批次到达的平均间隔。
- **两种执行模式**：
  1. **解耦流式模式**：当 RAS 大或 TPRM 短时，将 Ref 和 Actor 分布在不同 GPU 上，消除模型切换开销。重构计算图，将损失计算（含 KL 惩罚）从 forward 推迟到 backward，实现 Ref forward、Actor forward 与 Actor backward 的重叠。
  2. **优化共置模式**：当 RAS 小且 TPRM 长时，将 Ref 和 Actor 放在同一 GPU 上，通过**就绪批次聚合**（一次加载 Ref 处理多个就绪微批，再切换 Actor 处理）和**零拷贝共享内存传输**（同节点内绕过网络序列化）来摊销模型切换成本。
- **模式选择模型**：比较解耦模式延迟 \(C_{\text{dec}}\)（含流水线填充气泡和稳态计算时间）与共置模式延迟 \(C_{\text{col}}\)（算法模拟调度过程），根据 RAS 和 TPRM 选择成本较低者。
- **微批次调度**：早期微批次尽量填满所有 DP rank 的算力，最后一个小批次刻意保持最小以缩短流水线 flush 气泡；共置模式采用 zig-zag 最长处理时间优先分配，解耦模式将最小序列放在最后。

### 2.3 弹性资源伸缩（ERS）
- **核心思想**：读取 RAS 和 TPRM，在 rollout 与训练之间动态迁移 GPU rank，消除静态分区导致的瓶颈。
- **计划生成逻辑**：
  - **生成不足**（小 RAS + 长 TPRM）→ 选择共置 RA²P 并增加 rollout rank，降低 TWT。
  - **消费不足**（大 RAS + 短 TPRM）→ 选择解耦 RA²P 并增加 Trainer 容量，降低 RWT。
  - 使用队列指标（生成/消费赤字、队头延迟）平滑瞬时波动，避免抖动。
- **零开销伸缩操作**：
  - **无缓存任务迁移**：利用 on-policy RL 在每次权重同步后 KV 缓存必然失效的特性，将任务迁移与缓存刷新边界对齐，无需物理传输 KV 缓存。
  - **延迟隐藏角色切换**：将权重 PCIe 传输与 `sync_params` 广播重叠，减少关键路径延迟。

## 6. 论文的主要结论与发现

- **端到端训练吞吐**：相比同步 VeRL，TideRL 在文本任务上最高提升 5.6 倍；相比异步 AReaL 提升 1.8 倍；相比 StreamRL 提升超过 7 倍（在 14B 上 StreamRL 无法完成）。多模态任务上，较 VeRL 提升 6.02 倍，较异步基线提升超过 33%。

- **组件贡献**：
  - CTB 将 KV 缓存命中率提高 1.58 倍，生成吞吐提高 1.15 倍，步骤时间减少 15.6%。
  - RA²P 在就绪微批处理中减少每步训练时间最多 44.3%。
  - ERS 将总等待时间（RWT + TWT）降低 68.6%–77.6%，消融中单独贡献 35.7% 吞吐提升（叠加 RA²P 后）。

- **任务性能**：TideRL 在异步框架中取得最佳任务性能，接近同步 VeRL（BoN reward 差距 0.01，pass rate 差距 0.5%）；多模态场景下优于所有异步基线，但略低于同步 VeRL。

## 7. 优点

- **系统性协同设计**：CTB、RA²P、ERS 共享就绪信号，形成完整反馈闭环，而非孤立优化。
- **零开销弹性伸缩**：巧妙利用 on-policy RL 每次同步后 KV 缓存必然失效的特性，将 rank 迁移与缓存刷新边界对齐，避免传统弹性系统的高昂代价。
- **计算图重构**：将损失计算推迟到 backward，解除 Ref forward 对 Actor forward 的依赖，实现细粒度流水线重叠。
- **实用性强**：支持主流训练（Megatron、FSDP）和推理（vLLM、SGLang）后端，具有模块化架构，易于集成；同时考虑了评估任务与容错恢复。
- **实验证据扎实**：从端到端性能到组件消融再到微基准，多维度验证了三个瓶颈的缓解效果。

## 8. 不足与局限

- **评估规模有限**：仅使用 4 节点 32 块 H100，未验证更大规模集群下的表现；多模态模型规模相对较小（4B、9B）。
- **异步策略固有 staleness**：虽然通过 KL 惩罚和严格 staleness 约束缓解，但 TideRL 的任务性能仍略低于完全同步的 VeRL，尤其多模态场景下存在一个 step 的 off-policy 差距。
