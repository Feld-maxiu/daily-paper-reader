## 摘要
随着基于大语言模型（LLM）的智能体被部署到更长、更高风险的任务中，其记忆系统仍存在关键缺口。现有记忆基准大多聚焦于以回忆为主的任务，而我们主张，一个有效的记忆系统必须跟踪外部世界不断演化的状态；随着事实、约束和决策在长期交互中被修订，回答必须反映当前状态，而不是已被取代的状态。我们将这一能力定义为状态跟踪，并在 StateMemBench 中予以实例化；该基准包含 234 个多会话场景，覆盖两种对话长度区间。其封闭池评分方式判断回答反映的是当前状态、被取代的状态，还是其他失败情况，从而在构造上将状态跟踪失败与其他错误区分开来。我们的分析表明，该任务对现有记忆系统、检索增强基线和长上下文基线都具有挑战性。随后，我们提出 StateMem，一种状态优先的记忆方法，显式跟踪取代关系和关系依赖；结果表明，在 DeepSeek-V4-Flash 上，其当前状态准确率比最强的同骨干基线提高 1.8 倍（0.205 -> 0.363）；在 Qwen-3.5-9B 上，比最强记忆系统提高 1.6 倍（0.149 -> 0.233），同时仍与长上下文基线保持竞争力。最后，我们表明同一状态方法可作为轻量级单次调用包装器应用于现有记忆系统之上，在六个记忆与检索后端上，将 StateMemBench 上的当前状态准确率提升 +32 至 +67 个百分点。长度与成本匹配的对照实验表明，其中 +15 至 +32 个百分点的提升来自状态结构，而非新增上下文。

## Abstract
As LLM-based agents are deployed for longer and higher-stakes tasks, their memory systems continue to have crucial gaps. While existing memory benchmarks focus largely on recall-shaped tasks, we argue an effective memory system must track the evolving state of the world; as facts, constraints, and decisions are revised over a long interaction, answers must reflect the current state and not a superseded one. We define this capability as state tracking and instantiate it in StateMemBench, a benchmark of 234 multi-session scenarios spanning two conversation-length regimes. Its closed-pool grading scores whether an answer reflects the current state, the superseded state, or fails otherwise, separating state-tracking failures from other errors by construction. Our analysis shows that this task is challenging for existing memory systems, retrieval-augmented baselines, and long-context baselines. We then present StateMem, a state-first memory method that explicitly tracks supersession and relational dependencies, and show it improves current-state accuracy over the strongest same-backbone baseline by 1.8x (0.205 -> 0.363) on DeepSeek-V4-Flash and over the strongest memory system by 1.6x (0.149 -> 0.233) on Qwen-3.5-9B, while remaining competitive with the long-context baselines. Finally, we show the same state approach can be applied as a lightweight single-call wrapper over existing memory systems, lifting current-state accuracy by +32 to +67 points on StateMemBench across six memory and retrieval backends. A length- and cost-matched control attributes +15 to +32 of those points to state structure rather than added context.

- **整体含义**：状态跟踪是与“回忆”“推理”不同的能力维度；仅提升检索质量或上下文长度并不能自动解决状态漂移。因此需要专门的基准来测量它，也需要专门的记忆机制来改善它。
- **关键区别**：论文强调，以往工作常把状态漂移与其他错误混在一起，而本文通过构造性方法将“使用了被取代状态”与“检索失败、格式错误、推理失败”等区分开。

## 2. 论文提出的方法论

### 2.1 StateMem 记忆方法

StateMem 是一种 **状态优先的显式记忆表示方法**，将多轮对话记忆表示为一组 **结构化状态单元 state units**。其运行分为三个阶段：

- **Ingestion / 提取阶段**
  - 使用 **TurnEncoder**，每一轮对话调用一次 LLM，将当前轮解析为 0 个或多个状态单元。
  - 每个状态单元包含：`id`、`content`、`priority`（hard / soft）、`source`、`deps`（依赖关系）。
  - 依赖类型包括：
    - `derived_from`：表示当前单元的值由其他单元计算得到。
    - `coupled_with`：表示当前单元的有效性取决于其他单元的状态。
    - `triggers`：可记录基于日期或事件的有效性触发条件。
  - 状态单元会跨会话持久化保存在 StateStore 中。
  - 编码器可以在提取时标记已有单元“有被取代风险”，并主动提出替换。

- **Update / 更新阶段**
  - StateStore 执行已标记的取代操作：将被取代单元标记为 `superseded`，并把新单元加入为 active。
  - 确定性 **Rechecker** 遍历依赖图 `G=(U,E)`；如果某单元 `u_i` 依赖的单元状态发生变化，则将 `u_i` 标记为 `needs_recheck`，表示其内容可能已经过时。
  - 该步骤复杂度为 `O(|E|)`，不增加任何 LLM 调用。

- **Test time / 回答阶段**
  - 系统从 StateStore 中确定性地收集所有 active 单元，包括被标记为 `needs_recheck` 的单元。
  - 将状态按 priority 和 source 分组，并以结构化块形式渲染，同时展示导致重检的触发信息。
  - 再用一次 LLM 调用，基于当前状态块和问题，在 **Recompute Guidance** 的提示下重新推导答案。
  - 被取代单元保留在存储中用于审计，但不会进入回答上下文。

### 2.2 StateMemBench 的构造方法

- **符号事件程序**：每个场景由一个符号事件程序驱动，包含类型化状态操作：规则声明、值更新、作用域例外、承诺、撤回等。
- **封闭池评分**：每个 probe 有一个封闭候选池，包括：
  - gold truth：当前正确状态；
  - drift answer：被特定失败策略选中的旧状态；
  - neutral distractors。
- **失败模式**：通过“懒读者策略”与完整程序重放的分歧来生成陷阱场景，区分五类失败：
  - **Status errors**：值已变化，但读者仍锚定旧承诺。
  - **Salience errors**：有效值存在，但更频繁或更突出的竞争值获胜。
  - **Sequence errors**：派生值未随输入变化而重新计算。
  - **Compound errors**：多种机制叠加。
  - **Anti-trap**：反向控制，验证系统是否过度更新。

### 2.3 StateMemWrapper

- 将 StateMem 的核心思想压缩成一个 **单次回答调用的提示层包装器**，不增加 LLM 调用次数。
- 回答分两段：
  1. **Trace**：按时间顺序追踪与问题相关的值链，包括初始值、每次修订、当前有效值，并引用轮次编号；字数上限为 250 词。
  2. **Resolve**：基于四条优先级规则作答：
     - 后来的取代先前的；
     - 常设规则优先于一次性实例；
     - 派生值必须按当前输入重新计算；
     - 事实只有在被明确取代或过期时才失效。
- 设计有长度和成本匹配的对照条件 `wrapper-ctrl`，以剥离“额外上下文量”带来的收益，隔离“状态结构”的净贡献。

## 3. 实验设计

### 3.1 主要基准与数据场景

- **StateMemBench**：
  - 234 个多会话场景，共 322 个评分探针。
  - 三个领域：研究（research）、购物（shopping）、个人金融（finance）。
  - 两个长度条件：
    - Set A：190 个短场景，每个 18 个会话，中位数约 165 轮，约 3k token。
