## 摘要
现代智能体在管理工具、上下文和控制流的智能体 harness 内运行，使得 harness 成为智能体系统的关键部分。我们最初的 Agent Lightning 引入了一种解耦架构，通过 LLM 端点代理将任意智能体连接到 RL 训练，这种方法后来被 verl Uni-Agent、AReaL 2.0、slime 和 Polar 等框架采用。我们将这种范式称为受控智能体强化学习（harnessed agentic RL），其中部署时的 harness 直接参与模型后训练。受控智能体强化学习与传统智能体强化学习有根本区别：由 harness（而非训练引擎）拥有环境交互循环，而训练器仅观察 LLM 请求-响应对的序列。这在重新分词、样本合并、优势计算、损失归一化和后端调度方面带来了挑战，这些挑战会显著影响训练的稳定性和有效性。我们提出了 Agent Lightning v1.0，这是一个轻量级框架，用大约 3,500 行代码实现了受控智能体强化学习。它支持任意智能体 harness，并作为研究这些挑战的实用测试平台。我们在指令遵循、搜索和编码智能体上对其进行了评估，并提供了一个完整的可复现的编码智能体 RL 流水线。仅使用 6K 训练示例和适度的计算，RL 将 Qwen3.5-9B 在 SWE-bench Verified 上的表现从 41.8% 提高到 56.4%，绝对提升 14.6 个百分点。我们发布了完整的工作流程和训练脚本，以促进受控智能体强化学习的可复现研究。

## Abstract
Modern agents operate inside agent harnesses that manage tools, context, and control flow, making the harness a critical part of the agent system. Our original Agent Lightning introduced a disaggregated architecture that connects arbitrary agents to RL training through an LLM endpoint proxy, an approach later adopted by frameworks such as verl Uni-Agent, AReaL 2.0, slime, and Polar. We refer to this paradigm as harnessed agentic RL, where the deploy-time harness directly participates in model post-training. Harnessed agentic RL differs fundamentally from traditional agentic RL: the harness, rather than the training engine, owns the environment interaction loop, while the trainer observes only sequences of LLM request-response pairs. This introduces challenges in retokenization, sample merging, advantage calculation, loss normalization, and backend scheduling, which can substantially affect training stability and effectiveness. We present Agent Lightning v1.0, a lightweight framework for harnessed agentic RL implemented in approximately 3,500 lines of code. It supports arbitrary agent harnesses and serves as a practical testbed for studying these challenges. We evaluate it on instruction-following, search, and coding agents, and provide a complete reproducible pipeline for coding-agent RL. Using only 6K training examples and modest compute, RL improves Qwen3.5-9B on SWE-bench Verified from 41.8% to 56.4%, a 14.6-point absolute gain. We release the complete workflow and training scripts to facilitate reproducible research on harnessed agentic RL.

### 1. 论文的核心问题与整体含义

- **研究背景与动机**：现代 LLM 智能体并非独立模型，而是运行在管理工具、上下文、控制流的 **agent harness**（如 mini-SWE-agent、OpenHands、Claude Code 等）中，harness 对智能体能力至关重要。传统 RL 框架（如 verl、AReaL、slime）要求用户在训练框架内部重新实现智能体循环，难以集成已有的复杂 harness。
- **提出的范式**：论文将“部署时 harness 直接参与模型后训练”的范式定义为 **harnessed agentic RL（受控智能体强化学习）**。在该范式下，harness 拥有环境交互循环、上下文构建、工具调用和智能体编排，而训练系统仅观察一组 LLM 请求–响应对 `(p_i, a_i)`，harness 和环境状态成为潜在变量，模型只能看到每次调用时由 harness 构造的 prompt。
- **核心问题**：这种“通过 harness 进行 RL 训练”的方式与传统 agentic RL 有本质区别，带来五个关键挑战：**retokenization（重分词与样本合并）**、**advantage calculation（优势计算）**、**loss normalization（损失归一化）**、**training backend scheduling（训练后端动态调度）**。这些问题若处理不当，会导致训练低效或不稳定，而现有框架对此处理不一致且多未明确定义。

### 2. 论文提出的方法论

- **系统总体设计**：Agent Lightning v1.0 是一个轻量级框架，总共约 **3,500 行代码**，包含三个核心组件：
  - **API Gateway**：存储 rollout、模型和事件，转发来自 harness 的 LLM 调用到注册的推理端点，记录每次调用的 prompt/response token 与 log probs。
  - **Rollout Controller**：在 Kubernetes 集群或本地进程池上通过声明式 rollout 抽象和 reconcile 循环管理智能体执行，支持自托管计算，避免商用沙箱成本。
  - **Customized Trainer**：基于 VERL，注册 rollout，收集轨迹并组装训练样本，实现本文的设计选择。
- **挑战应对策略**：
  - **样本合并**：采用 **best-effort sequence merging**——仅当后续 prompt 在 token 级别是前一次请求+响应的精确前缀时才合并；否则关闭当前序列、开启新序列。保证训练使用的 prompt 与实际采样时的 prompt 一致，避免 off-policy 拼接。
  - **优势计算**：使用 **rollout-level advantage**。同一个 rollout 内的所有训练样本继承该 rollout 的 outcome reward，组均值在 rollout 级别计算，而非在样本级别计算，从而避免样本数量差异影响 baseline。
  - **损失归一化**：采用 **rollout-level token-mean loss**（式 16），先在一个 rollout 内池化所有响应 token 损失，再对 rollout 求平均，使每个 rollout 权重相等，不受样本分裂数量影响。
  - **后端调度**：训练后端将变长的样本集合展平为物理 batch，但保留每个序列的 rollout ID 和 prompt-group ID，确保同一个 rollout 的所有样本在同一 optimizer update 中，避免 policy skew。
- **其他系统特性**：
  - **Collocated Async RL**：推理和权重更新共享同一 GPU 池，通过 API Gateway 在 rollout 阶段和 update 阶段之间无缝切换，避免等待最慢 rollout，同时比传统 async RL 使用更少 GPU（实验显示约 2 倍端到端加速）。
  - **幂等 API 与去重**：所有 Gateway 端点幂等；训练时对相同 prompt 的多个 LLM 调用只保留最后一次，丢弃重试或过期调用。
  - **奖励防护**：在编码智能体训练中禁用 Git 命令、隐藏 `.git` 目录，并通过 Kubernetes 网络策略阻止外网访问，防止智能体通过检索上游源码等方式 reward hack。

### 3. 实验设计

- **搜索智能体（Search Agent）**
  - 实验设置遵循 Search-R1；模型为 Llama-3.2-3B-Instruct，优化算法 GRPO。
  - 训练数据：HotpotQA 训练集；评估数据：HotpotQA、2WikiMultiHopQA、MuSiQue、Bamboogle、TriviaQA、Natural Questions 各随机采样 50 例。
  - 指标：Exact Match (EM)；训练 batch size 512，每 prompt 采样 4 rollouts，每 10 步评估。
  - 结果：训练奖励稳步上升，验证奖励从 25.1% 提升到 41.7%，绝对提升 16.6%。
- **通用指令遵循智能体（General Instruction-Following Agent）**
  - 实验设置遵循 LLM-in-Sandbox；模型为 Qwen3-4B-Instruct-2507，优化算法 RLOO。
  - 数据集：Instruction Pre-Training 数据集，按 80% 训练 / 20% 评估划分；训练 batch size 8，每 prompt 采样 8 rollouts，每 20 步评估。
  - 结果：训练奖励噪声较大，但验证奖励从 51.9% 提升到 70.2%，绝对提升 18.3%。
- **编码智能体（Coding Agent）**
  - 模型：Qwen3.5-9B；harness：mini-SWE-agent；任务来源：SWE-smith 数据集。
  - 数据清洗：移除空问题陈述 18,033 条、缺失分支 1,265 条、测试数量超过 200 的任务；随后用模型自身进行难度过滤（运行 4 次：全对移除、有成功有失败保留约 5,000 例，另采样 1,000 例全失败任务）；最终约 6,000 训练例、400 测试例。
  - 奖励防护：禁用 Git 命令、隐藏 `.git`、Kubernetes 网络策略阻止外网。
  - 训练动态消融：比较三种设置——**Sample-level Advantage + token-mean loss**、**Rollout-level Advantage + token-mean loss**、**Rollout-level Advantage + rollout-level token-mean loss**。
  - 结果：第三种设置在 step 128 达到最高验证奖励 38.2%（对比 35.0% 和 33.1%），且 entropy 增长更慢、更稳定；在 SWE-bench Verified 上，从基线的 41.8% 提升到 56.4%（step 208 checkpoint），绝对提升 14.6 个百分点。

### 6. 论文的主要结论与发现

- harnessed agentic RL 与传统 agentic RL 在潜在状态、模型观察和训练样本结构上有本质差异，导致重分词、样本合并、优势计算、损失归一化和后端调度等新挑战。
- 其中，**token 级前缀连续性**在 harness 场景下经常被破坏（聊天模板非组合性、解码-重分词漂移、推理时输出转换），直接合并会导致 off-policy 训练。
- **rollout-level advantage 和 rollout-level loss normalization** 是更合理的选择，因为动态样本数量通常由重分词等偶发因素驱动，不应影响梯度权重；实验表明该设置能提高验证奖励并控制 entropy 增长。
- Agent Lightning v1.0 作为一个约 3,500 行的轻量级框架，能够有效支持任意 harness，并通过 collocated async 等方式提高效率。
- 在编码智能体上，仅用约 6K 训练样本和适度算力，RL 将 Qwen3.5-9B 在 SWE-bench Verified 上从 41.8% 提升到 56.4%，绝对提升 14.6 个百分点。
