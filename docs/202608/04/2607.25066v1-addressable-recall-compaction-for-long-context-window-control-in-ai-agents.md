## 摘要
长时域LLM智能体会积累推理轨迹、动作和工具观察，这些内容最终可能超出模型固定的上下文窗口。现有压缩方法通过丢弃、摘要或检索先前信息来解决这一限制，但可能会移除任务关键细节或无法可靠地恢复它们。我们提出ARC（可寻址回忆压缩），一种将存档存储与活跃上下文呈现分离的上下文管理框架。ARC将工具观察结果存储在一个仅追加、ID可寻址的日志中，并在需要压缩时用紧凑的引用替换较早的观察结果。智能体随后可以使用这些标识符请求存储的内容，而无需重新执行相应的工具或仅依赖基于相似性的检索。我们使用具有16k上下文窗口的Qwen3-8B和具有32k上下文窗口的Qwen3-32B评估ARC。在“大海捞针”评估中，ARC实现了99.40%的平均精确答案准确率，而我们评估中表现最好的基线为88.12%。在我们的硬件成本模型下，ARC还减少了估计的服务时间和HBM流量。在LongBench-v2 Hard子集上，ARC获得了29.97%的平均准确率，而表现最好的基线为28.25%。这些结果表明，在所测设定下，相对于评估的上下文管理基线，基于地址的显式回忆能够改善信息保留和服务效率。

## Abstract
Long-horizon LLM agents accumulate reasoning traces, actions, and tool observations that can eventually exceed a model's fixed context window. Existing compaction methods address this limitation by discarding, summarizing, or retrieving earlier information, but they may remove task-critical details or fail to recover them reliably. We propose ARC (Addressable Recall Compaction), a context-management framework that separates archival storage from active-context presentation. ARC stores tool observations in an append-only, ID-addressable log and replaces older observations with compact citations when compaction is required. The agent can subsequently use these identifiers to request stored content without re-executing the corresponding tools or depending solely on similarity-based retrieval. We evaluate ARC using Qwen3-8B with a 16k context window and Qwen3-32B with a 32k context window. On the Needle-in-a-Haystack evaluation, ARC achieves an average exact-answer accuracy of 99.40%, compared with 88.12% for the best-performing baseline in our evaluation. ARC also reduces estimated serving time and HBM traffic under our hardware-cost model. On the LongBench-v2 Hard subset, ARC obtains an average accuracy of 29.97%, compared with 28.25% for the best-performing baseline. These results indicate that explicit, address-based recall can improve information retention and serving efficiency relative to the evaluated context-management baselines under the tested settings.

### 1. 论文的核心问题与整体含义
该论文聚焦于**长时域（long-horizon）大型语言模型（LLM）智能体面临的上下文窗口溢出问题**。随着智能体不断与环境交互（思考、调用工具、接收反馈），其历史记录——即输入给模型的唯一“工作记忆”——会无限增长，最终超出模型预定义的上下文长度限制，导致系统崩溃。这一问题是长周期规划、复杂软件工程等任务中“几乎必然”发生的硬件瓶颈。

论文指出，现有的**上下文压缩（compaction）方法（如截断、摘要、状态折叠或RAG检索）本质上是“有损”的**。一旦历史信息被丢弃、改写或向量化，关键的细节（论文中称为“针”，needle）就可能永久丢失，后续无法被精确恢复，从而引发幻觉或任务失败。因此，该研究的核心意图是：**证明上下文压缩可以在保持活跃提示词（active prompt）有界的同时，做到严格无损和可精确回忆**。

### 2. 论文提出的方法论：可寻址回忆压缩（ARC）
ARC的核心思想是**将“存档存储”与“活跃上下文呈现”解耦**。它维护两个独立的组件：
-   **仅追加的可寻址存储（Append-only Addressable Store）**：用于完整、永久地保存每一次工具调用的输出观察。
-   **有界大小的活跃视图（Bounded-Size Active View）**：向LLM展示的、受预算限制的上下文。

**关键技术细节与流程如下：**
*   **存储与标识**：当智能体执行一个动作并产生输出 `O` 时，ARC会为该输出计算一个唯一的哈希标识符 `id`（基于动作签名和输出的SHA1哈希的前8个十六进制字符）。包含完整内容、元数据和创建步骤的记录会在 `ObsStore` 中永久保存。
*   **压缩与引用**：当需要压缩上下文时，ARC的确定性压缩程序不会直接丢弃长的工具输出，而是用**紧凑的引用（citation）`§id`** 来替换它。这个引用包含了该输出的头部和尾部预览、元数据以及一个 `_recall §id` 的使用提示，而完整内容仍安全地保存在 `ObsStore` 中。
*   **精确回忆**：智能体可以在后续任意时刻通过发出 `_recall §id` 命令，直接、精确地从 `ObsStore` 中取回该输出的完整原文。这个回忆机制在执行层面是多层的，可通过 `_recall-start` 和 `_recall-next` 命令以分块（chunks）形式取回超大内容，并有独立的回忆预算（如默认`r=2`次/步）来控制上下文膨胀。
*   **系统级保证**：论文通过理论和证明展示，只要给定有效的 `id`，ARC就能保证精确恢复原始内容，同时维持活跃提示词大小有上界 `K ≤ L`（模型上下文限制）。这使得压缩操作从不可逆变为可逆。

### 8. 不足与局限
*   **模型家族单一**：所有实验均在Qwen3系列模型上进行。虽然论文承认“泛化到其他分词器、推理风格或指令遵循行为仍待研究”，但这是其当前主要局限。在其他模型（如GPT、Claude、Llama等）上的表现尚待验证。
*   **精确回忆的“启动”开销**：ARC的优势依赖于智能体主动发出 `_recall` 命令。虽然它能完美响应“地址条件”，但**无法保证LLM总能选择正确的地址**进行召回。在LongBench-v2上，相比于纯记忆测试优势有所缩小，说明推理错误仍是问题的一部分。
*   **引用本身的Token开销**：ARC的每个引用都包含了头部/尾部预览和元数据，这相比彻底丢弃仍然会引入少量、固定的token开销。虽然论文提到量化分析在附录中，但这仍是潜在的细节成本。
*   **内存线性增长的下界**：论文理论证明并承认，为了实现精确回忆，外部存储必然随历史观察线性增长。虽然这被证明是“最优”的，但对极端长时域的任务，这依然构成一个机械性存储压力。
*   **长对话历史任务的潜在劣势**：论文在讨论中指出，隐式检索（如RAG）在对话历史类任务上仍有竞争力，暗示ARC的机制并非在所有场景下都是绝对最优，显式和隐式回忆可能是互补关系。
