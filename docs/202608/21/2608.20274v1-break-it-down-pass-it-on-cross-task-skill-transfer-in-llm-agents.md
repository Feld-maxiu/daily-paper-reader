## 摘要
大语言模型（LLM）智能体能够从已完成任务中归纳技能，并在日后复用这些技能，从而随着经验积累而不断增强能力。在实践中，归纳出的技能在迁移时可能不可靠，甚至可能损害检索它们的智能体。智能体归纳的技能何时能在任务间可靠迁移，仍是一个悬而未决的问题。我们对技能归纳方式如何影响其跨任务迁移进行了全面且受控的研究。具体而言，我们比较了任务级与子任务级技能归纳，以及文本与代码技能格式，这是现有方法存在差异的两个维度。任务级技能大多使智能体的表现降至其无记忆基线以下，而子任务级技能平均而言将其提升至基线以上；并且文本技能比代码技能迁移得更好。为了进一步理解我们的发现，我们考察了归纳技能的两个互补属性：特异性，衡量技能与实际任务的匹配程度；抽象性，衡量其相关性在任务间分布的均匀程度。任一属性单独都无法预测任务成功，但二者的综合效应可以，我们将其提出为技能效用分数。在技能迁移时，该分数与任务成功始终相关，且子任务级技能和文本技能得分更高。计算技能效用仅需技能和任务描述，无需任何任务执行，因此我们的分数可作为在任何新任务运行之前对技能记忆的实用诊断。

## Abstract
Large language model (LLM) agents can induce skills from completed tasks and reuse them later to grow more capable with experience. In practice, induced skills may transfer unreliably and can even harm the agent that retrieves them. When agent-induced skills transfer reliably across tasks remains an open question. We conduct a comprehensive and controlled study of how the way skills are induced shapes their transfer across tasks. Specifically, we compare task-level with subtask-level skill induction and text with code skill formats, the two axes along which existing methods differ. Task-level skills mostly reduce the agent's performance below its no-memory baseline while subtask-level skills raise it above on average, and text skills transfer better than code skills. To further understand our findings, we examine two complementary properties of the induced skills: specificity, which measures how closely a skill matches real tasks, and abstractness, which measures how evenly its relevance spreads across tasks. Neither property alone predicts task success, but their combined effect does, which we propose as a skill utility score. The score correlates consistently with task success when skills are transferred, and subtask-level and text skills score higher. Computing skill utility only needs the skills and task descriptions but not any task execution, so our score serves as a practical diagnostic of a skill memory before any new task runs.

- **研究背景与动机**：现有技能归纳方法在“归纳层级”和“技能格式”两个维度上做法不一：有的从整条任务轨迹归纳，有的从子任务归纳；有的将技能存为文本，有的存为代码。已有研究对子任务级归纳的支持证据较窄，且缺乏对这两大维度进行同等条件下的系统对比。

## 2. 方法论

### 2.1 两种智能体架构

- **任务级智能体（Task-level agent）**：采用扁平的 ReAct 循环，将全部动作与观察 append 到同一个上下文，生成整条任务轨迹。
- **子任务级智能体（Subtask-level agent）**：在相同环境与策略下，通过三步循环分解任务：
  - **Planner**：根据目标和当前进度总结，提出下一个子任务或宣布任务完成。
  - **Executor**：对当前子任务运行 ReAct 循环，产生子轨迹。
  - **Summarizer**：将子轨迹压缩为运行进度总结，供下一轮 planner 使用。
- 任务级智能体可视为子任务级智能体的特例：整个任务只有一个子任务，且仅执行 executor。

### 2.2 技能记忆与技能格式

- **技能记忆**包含归纳算子（从轨迹生成技能）和检索算子（相关技能注入上下文）。
- **文本技能**：主体为工作流笔记，包含“Procedure: step1 → step2 → …”以及环境相关的注意事项。
- **代码技能**：主体为 Python 函数，将实例相关值参数化，环境注意事项作为代码注释。
- **技能归纳层级**：
  - 任务级归纳：每条完整任务轨迹生成一个技能。
  - 子任务级归纳：每条子轨迹生成一个技能。
- 两个层级共享同一归纳提示词，以隔离“归纳层级”这一变量。
- **技能检索**：使用 all-MiniLM-L6-v2 对技能描述和查询进行嵌入，注入 top 匹配技能；代码技能还会加载到执行命名空间。记忆会修剪加载失败的代码技能，并合并或丢弃近重复项。

### 2.3 技能效用分数（Skill Utility Score）

- 定义两个互补属性：
  - **特异性（Specificity）**：衡量技能与真实任务的匹配程度。形式化为技能与其最近任务的相似度超过两个随机任务之间相似度的概率：
    \[
    \text{specificity}(s) = \Pr\left[\max_j c_j \ge \cos(t_i, t_k)\right]
    \]
    其中 \(c_j\) 是技能 \(s\) 与第 \(j\) 个任务指令的余弦相似度。
  - **抽象性（Abstractness）**：衡量技能相关性在多个任务上的分布均匀程度。将相似度分布经 softmax 后计算困惑度，再除以任务数：
    \[
    \text{abstractness}(s) = \frac{\exp\left(H[\text{softmax}(c/\tau)]\right)}{N}
    \]
    其中 \(H\) 为熵，\(\tau=0.1\) 为温度，\(N\) 为任务数。
  - **技能效用**定义为两者乘积：
    \[
    \text{utility}(s) = \text{specificity}(s) \cdot \text{abstractness}(s)
    \]
- 该分数仅依赖技能描述和任务描述，无需任务执行，可作为运行前诊断。

## 6. 主要结论与发现

- **归纳层级决定技能是否有帮助**：
  - 任务级技能平均将任务成功率降低（Text 约 -1.2 个百分点，Code 约 -4.1 个百分点）。
  - 子任务级技能平均提升成功率（Text 约 +1.9 个百分点，Code 约 +0.5 个百分点）。
  - 该趋势在几乎所有 benchmark 和难度层级上成立。
- **格式决定帮助或损害程度**：
  - 文本技能迁移优于代码技能，在子任务级平均领先约 2.9 个百分点，在任务级领先约 1.4 个百分点。
  - 文本技能相对于各自无记忆基线的优势也优于代码技能。
- **技能效用分数可预测任务成功**：
  - 仅用特异性或抽象性都无法预测成功，二者存在折中；只有乘积（效用分数）与成功率单调正相关。
  - 子任务级和文本技能具有更高的效用分数。
  - 效用分数与实际跨任务复用密度一致：子任务级智能体在三个 benchmark 上均复用更密集。
- **成本效率**：小预算下任务级智能体表现更好，但从中等预算起，子任务级智能体在同等成本下解决更多任务。
