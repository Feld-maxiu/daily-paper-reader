## 摘要
大型语言模型（LLM）智能体在复杂的长期任务上通常表现不佳，因为其上下文会随时间推移变得越来越杂乱。随着交互不断累积，详细的执行轨迹和中间输出占据了上下文的主导地位，使模型难以保留和使用高层规划信息。大多数现有方法通过对单一扁平上下文进行压缩或检索来解决这一问题，但并未清晰区分不同类型的上下文信息，且往往导致推理能力下降。为应对这一挑战，我们提出了 HyMem，一个将智能体上下文显式划分为不同功能层的分层框架。HyMem 按功能组织上下文，将高层规划与执行及复杂分析分离开来。其隔离推理模块处理复杂子任务，而不会将中间推理轨迹添加到持久规划上下文中；其记忆管理模块则通过结构化摘要，在上下文刷新时保留任务进展。这些组件减少了冗余上下文的累积，保留了任务关键信息，并在有限的上下文窗口内支持连贯的长期推理。在 GAIA 和 Browsecomp-plus 上的实验表明，使用 DeepSeek-V4 时，HyMem 的平均 Pass@1 得分分别为 66.7% 和 61.3%，比最强基线分别高出 6.1 和 4.7 个百分点。进一步分析表明，HyMem 有效控制了推理上下文的增长，使模型能够在复杂的长期任务中保持专注度和准确性。

## Abstract
Large language model (LLM) agents often perform poorly on complex, long-horizon tasks because their context becomes increasingly cluttered over time. As interactions accumulate, detailed execution traces and intermediate outputs dominate the context, making it difficult for the model to retain and use high-level planning information. Most existing methods address this issue through compression or retrieval applied to a single, flat context, which does not clearly separate different types of context information and often leads to degraded reasoning. To address this challenge, we propose HyMem, a hierarchical framework that explicitly separates the agent's context into distinct functional layers. HyMem organizes context by function to separate high-level planning from execution and complex analysis. Its isolated reasoning module handles complex subtasks without adding intermediate reasoning traces to the persistent planning context, while its memory management module preserves task progress across context refreshes through structured summaries. These components reduce redundant context accumulation, retain task-critical information, and support coherent long-horizon reasoning within a limited context window. Experiments on GAIA and Browsecomp-plus show that, with DeepSeek-V4, HyMem achieves average Pass@1 scores of 66.7% and 61.3%, outperforming the strongest baseline by 6.1 and 4.7 percentage points, respectively. Further analysis indicates that HyMem effectively controls the growth of the reasoning context, allowing the model to maintain focus and accuracy across complex, long-horizon tasks.

# HyMem 论文详细总结

## 1. 论文的核心问题与整体含义

- **核心问题**：大语言模型（LLM）智能体在长期、复杂任务中表现下降，主要原因是上下文随着执行过程不断累积，导致“上下文稀释”（context dilution）。
- **具体表现**：高层规划信号（目标、已验证事实、约束、未解决子目标）是稀疏且关键的；低层执行轨迹（原始工具输出、浏览日志、重试、格式噪声、失败尝试）是密集且冗余的。在传统扁平上下文（如 ReAct）中，两者被交错混合，执行噪声逐渐淹没规划信号，使智能体迷失在工具使用细节中。
- **整体含义**：现有压缩或检索方法通常在信息已经混合后进行处理，只是缓解上下文长度压力，未解决信息混合这一根源。HyMem 提出从架构上对不同类型信息进行隔离管理，使决策上下文始终保持聚焦于高价值规划信号。

## 2. 论文提出的方法论

- **核心思想：类型化上下文隔离（typed context isolation）**
  - 将规划、工具执行、隔离子任务推理、记忆固化分别置于独立的上下文空间。
  - 只允许符合模式约束（schema-constrained）的消息跨边界进入规划上下文，从源头阻止原始执行轨迹和中间推理 token 污染决策上下文。

- **两个上下文空间**
  - **Planner Layer（规划层）**：持久维护主决策上下文，包含系统提示、查询、三类结构化记忆、以及历史中仅有的类型化返回结果。规划器一次只发出一种动作：`⟨TASK⟩`（指派执行）、`⟨ISO REASON⟩`（发起隔离推理）、`⟨FOLD⟩`（触发记忆折叠）、`⟨ANSWER⟩`（给出最终答案）。
  - **Executor Layer（执行层）**：按需创建，接受工具调用指令，进行有界工具调用循环。原始观察不会直接返回，而是先经过相关性蒸馏（`ϕ`），去除导航文本、重复段落、格式噪声和不相关片段，保留命名实体、日期、数值、来源标识和证据片段；随后合成为结构化 `⟨RESULTS⟩` 消息，返回后即丢弃执行层私有上下文。

- **隔离推理模块（Isolated Reasoning）**
  - 对需要多跳分析、假设检验或冲突证据协调的子任务，规划层发起 `⟨ISO REASON⟩`。
  - 隔离会话可以调用执行器获取额外证据，但中间推理轨迹完全私有，只返回结构化 `⟨RETURN⟩`：结论、支撑事实、来源、置信度 `κ` 和假设。返回后该上下文被丢弃。

- **结构化记忆管理模块**
  - 维护三种可重写记忆：
    - **episode memory**：已完成里程碑、已验证事实和重要决策；
    - **working memory**：当前目标、未解决缺口和下一步计划；
    - **tool memory**：有效工具使用模式、失败查询和工具特定注意事项。
  - 当规划器发出 `⟨FOLD⟩` 或触发条件满足时，通过 `Φ` 对历史进行联合压缩，重写所有记忆。
  - 采用**非对称记忆注入**：规划层和隔离推理层注入三种记忆；执行层只注入工具记忆，以保留可复用工具经验，同时将原始工具日志隔离在外。

- **关键公式与机制**
  - 上下文稀释密度：`ρ_t = |Z_t| / |C_t|`，其中 `Z_t` 为规划相关信息，`C_t` 为完整上下文；长期任务中 `|X_t|`（执行层信息）增长快于 `|Z_t|`，导致 `ρ_t` 下降。
  - 信息边界约束：`I(C^{(p)}_{t+1}; X_t | R_t) ≈ 0`，即给定结构化返回 `R_t` 后，规划层与被隔离的原始执行轨迹条件互信息接近零。这不是可微优化目标，而是通过接口设计强制实现。
  - 折叠触发条件：上下文利用率 > 0.99、执行器调用 ≥ 5、连续执行失败 ≥ 3、规划轮数 ≥ 8、工具调用 ≥ 10，任一满足即触发记忆折叠。

- **训练无关性**：HyMem 是推理时控制器，包裹冻结的基础 LLM，无需训练。

## 6. 论文的主要结论与发现

- HyMem 在 DeepSeek-V4 上取得最佳平均 Pass@1：GAIA 66.7%，Browsecomp-plus 61.3%，分别比最强基线（ReSum 60.6%、ReAct 56.6%）高 6.1 和 4.7 个百分点。
- 增益在难题上更显著：Browsecomp-plus 困难题 Pass@1 从 ReAct 的 14.0% 提升到 HyMem 的 30.0%；GAIA Level 3 上也有明显提升。
- HyMem 的优势来自**上下文分配方式**而非单纯减少总上下文长度：Planner 上下文增长缓慢，Executor 和隔离推理上下文可扩展，但执行细节不进入持久规划空间。
- 消融实验表明：隔离推理和记忆管理都必要；移除任一项均导致显著性能下降（如 GAIA 上移除任一项均下降 18.6 个百分点）。
- 性能提升不是通过无节制增加 token 或工具调用实现，HyMem 在资源-性能权衡曲线上处于有利位置。

## 7. 优点

- **问题定位准确**：明确将长期智能体性能瓶颈归因于信息类型混合导致的上下文稀释，而非仅上下文长度。
