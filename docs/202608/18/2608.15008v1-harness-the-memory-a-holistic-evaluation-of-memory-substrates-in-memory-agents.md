## 摘要
记忆正在成为长时程 LLM 智能体的核心基础设施，但现有评测对于在不同运行机制下应使用哪种记忆基底（即记忆被表示和存储的底层介质）提供的指导有限。我们提出了一个受控的测试框架，对记忆增强型智能体的记忆基底进行评估，涵盖稠密与稀疏索引、文本记录、结构化存储、层次化存储、基于精炼的记忆、参数化更新以及激活兼容的上下文机制。在三个骨干模型和四个基准套件上（涵盖以用户为中心的问答和以智能体为中心的决策制定），我们在统一测试框架下测量了 26 项性能与效率指标。结果表明，没有单一基底能始终占优：广泛检索有利于长上下文事实问答，而过度检索可能将注意力从行动关键上下文转移开，从而损害顺序决策。可扩展性引入了进一步的路由维度，因为在中等历史长度下表现良好的基底在更长时程下可能变得昂贵或脆弱。这些发现促使将基底路由作为自适应智能体记忆系统的必要组成部分，并为设计高效、可靠且具有机制感知能力的 LLM 智能体长期记忆提供了实证指导。代码将在录用后公开。

## Abstract
Memory is becoming core infrastructure for long-horizon LLM agents, yet existing evaluations offer limited guidance on which memory substrate, namely the underlying medium in which memory is represented and stored, should be used under different operating regimes. We present a controlled harness evaluation of memory substrates for memory-augmented agents, covering dense and sparse indices, text records, structural stores, hierarchical stores, refinement-based memories, parametric updates, and activation-compatible context mechanisms. Across three backbone models and four benchmark suites spanning user-centric question answering and agent-centric decision-making, we instrument 26 performance and efficiency metrics under a unified harness. Our results show that no single substrate consistently dominates: broad retrieval benefits long-context factual QA, while excessive retrieval can harm sequential decision-making by shifting attention away from action-critical context. Scalability introduces a further routing axis, as substrates that perform well at moderate history lengths can become costly or brittle at longer horizons. These findings motivate substrate routing as a necessary component of adaptive agent memory systems and provide empirical guidance for designing efficient, reliable, and regime-aware long-term memory for LLM agents. - **核心问题**：长时程大语言模型（LLM）智能体日益依赖持久记忆，但“应该使用哪种记忆基底（memory substrate）——记忆表示与存储的底层介质——在不同运行机制下表现最好”缺乏实证指导。
- **研究动机**：
  - 不同记忆基底在精度、效率、成本之间存在不同权衡，没有单一设计能在所有方面占优。
  - 现有评测存在三个主要局限：
    1. **基准集中**：52 个记忆增强系统中 62% 的基准使用集中在 LoCoMo 和 LongMemEval 两个对话数据集，智能体任务几乎未被评估。

- **整体含义**：任何通用记忆系统必须能够根据查询、任务和部署约束在多种基底之间动态路由（substrate routing），而不是在设计中固定使用单一基底。本文通过受控 harness 评估为这种路由决策提供实证信号。

## 2. 论文提出的方法论

- **核心思想**：将“记忆基底”作为唯一实验变量，在统一测试框架（harness）下，固定骨干、提示模板和辅助 LLM 设置，隔离基底对性能和效率的影响。
- **基底分类与实现（11 种方法，7 个家族）**：
  - **外部记忆**（存储在模型外部的数据结构中，通过显式操作写入和读取）：
    - `Flat Index`：M1 稠密向量（dense embedding + cosine top-k），M2 稀疏向量（BM25 倒排索引）。
    - `Text Record`：M3 Gist Index（ReadAgent 风格，写时 LLM 生成摘要，读时页面选择与扩展）。
    - `Structural`：M4 Evolving Notes（A-Mem 风格，互连笔记+演化触发重写），M5 Dual-Level Graph（LightRAG 风格，实体-关系图+向量混合检索）。
    - `Hierarchical`：M6 Hierarchical Tree（RAPTOR 风格，递归聚类+摘要，崩塌树检索）。
    - `Refinement`：M7 Distilled Strategies（ReasoningBank 风格，判断轨迹并蒸馏策略），M8 Skill Bundles（MemSkill 风格，聚类经验为技能束，但用零样本 LLM 替代 PPO 控制器）。
  - **内部记忆**（编码在模型权重或激活中，隐式访问）：
    - `Weight`：M9 Adapter Tuning（LoRA-FA，对合成的问答对做适配器微调）。
    - `Activation`：M10 Full Context（全历史拼接+截断），M11 Episode-Clustered Re-prefill（EpiCache 风格，按情节聚类并重填充，保留 25% token 预算）。
- **统一 harness 设计**：
  - 辅助 LLM 固定为 GPT-4o-mini（用于记忆写入、管理和 LLM-as-a-judge 评分）。
  - 三种骨干模型：Qwen3-8B、Qwen3-32B-AWQ、Gemma-4-26B-A4B-IT。
  - 26 项指标：性能指标（EM、F1、BLEU-1、LLM Judge、压缩率、Recall@k、任务成功率、GC成功率、步数、Pass@1、SubEM 等），效率指标（内存大小、推理时间、写/读/管理延迟、写/读/管理 token 与调用、总 token、总调用、总墙钟时间、每查询延迟等）。
- **关键实验手段**：
  - **Top-k 检索广度扫描**：在 LoCoMo 和 ALFWorld 上分别扫描 k∈{1,2,5,10,20} 和 k∈{1,2,3,4,5}，并与无记忆基线比较。
  - **注意力探针**：探测响应 token 的注意力质量在 System、Retrieved、Context、Cue 四个区域间的分配，解释检索广度反转现象。
  - **上下文长度压力测试**：在 MAB-CR 下扫描 6K/32K/262K token 三种历史长度，考察可扩展性。

## 6. 论文的主要结论与发现

- **没有单一基底在所有场景占优**：
  - 结构性图（M5）在对话 QA 中领先，但在智能体任务上帕累托被占优。
  - 精炼记忆（M7）在具身规划中领先，但在 QA 中表现一般。
  - 性能-延迟帕累托前沿在 QA 与智能体任务之间完全不相交。
- **检索广度的反转效应**：
  - 在 LoCoMo QA 中，P4 随 k 单调上升（更多检索→更高机会覆盖证据）。
  - 在 ALFWorld 中，任务成功率随 k 下降（M7 从 k=1 的 32.1% 降至 k=5 的约 25%），步数增加，智能体“迷路”。
  - 注意力探针解释：k 增大使注意力从任务 Context 转移到 Retrieved；QA 的答案在检索块中，智能体任务的决策关键在于当前观察和可行动作列表，因此检索稀释了关键注意力。
- **可扩展性是第三路由轴**：
  - 精炼类基底（M8）在历史从 6K 到 262K token 时质量上升且延迟增长温和（约 1s→10s）。
  - 结构化基底（M4/M5）在长历史下延迟陡增，质量优势被侵蚀。
  - 内部基底分化：全上下文（M10）质量随规模上升但线性读成本；适配器微调（M9）缺乏选择性时态更新，在冲突解决上停滞。
- **设计规则**：用读取广度换写入深度（write depth over read breadth）——每次查询检索更少条目，在写入时更多投资于提炼和结构化记忆。
- **总体启示**：通用智能体记忆必须为多基底/多智能体系统，由 harness 按情景路由到与其提示负载核心区域对齐的基底。
