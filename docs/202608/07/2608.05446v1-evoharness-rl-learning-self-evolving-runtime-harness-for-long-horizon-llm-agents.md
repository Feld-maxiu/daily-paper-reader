## Abstract
Long-horizon LLM agents increasingly rely on external execution support to maintain state, track progress, invoke tools, verify outcomes, and reuse experience across interactions. However, effective harness use raises two coupled challenges: state formation from noisy interaction traces and runtime control over external-state access. Existing agents usually handle both through prompts, heuristics, or domain-specific conventions, leaving the external workspace and its usage policy manually engineered. To address this, we study the problem of harness policy learning, where agents learn harness policies offline and deploy them to construct and update external harness state online during runtime task execution. We introduce EvoHarness-RL, which exposes Belief, Progress, and Experience (BPE) as policy-facing harness state. Supervised harness fine-tuning teaches the base agent the harness action space and how to construct useful external state, while cost-aware GRPO explores coordination policies to selectively read, update, and consolidate that state during long-horizon interaction. Instantiated on ALFWorld with a Qwen3-8B LLM, EvoHarness-RL reaches 96.9% success and reveals two key dynamics: harness annealing, where training internalizes recurring harness-use patterns into the model policy and shifts the agent from frequent harness calls toward selective external-state access, and harness evolution, where progress updates and experience consolidation refine the harness into a compact, task-adaptive state substrate. These results suggest that long-horizon agents benefit from trainable policies for constructing and coordinating with external harness workspaces, beyond simply adding stronger tools or larger memories.

*   **核心问题**：长时域（Long-Horizon）LLM代理在执行复杂任务（如具身交互、网页导航）时，严重依赖外部运行时环境（称为Harness）来维持状态、追踪进度、调用工具和复用经验。然而，**如何从嘈杂的交互轨迹中有效地形成外部状态，以及如何在运行时控制对这些状态的访问**，是两个紧密耦合的挑战。

*   **研究动机与整体含义**：论文提出研究**Harness策略学习**问题，旨在让代理能够离线学习Harness的使用策略，并在在线任务执行时自主地构建和更新外部Harness状态。其核心意义在于，将Harness从一个静态的、硬编码的支撑工具转变为代理**可学习的决策过程**的一部分。

### 2. 论文提出的方法论：核心思想、关键技术细节

本方法的核心是提出 **EvoHarness-RL**，一个可训练的代理-Harness协调层。

*   **核心思想**：
    *   将异构的Harness组件抽象为一个统一的、面向策略的 **BPE（Belief, Progress, Experience）工作区**，以应对长时域交互中的三个核心需求：
        *   **Belief（信念）**：维护当前环境状态的持久化估计。
        *   **Progress（进度）**：记录任务的分解和执行状态（已完成/待办子目标）。
        *   **Experience（经验）**：维护跨集（Cross-Episode）的可复用知识，如技能、失败模式。
    *   代理通过与BPE工作区交互的**紧凑的Harness元动作（Meta-Actions）** 来使用外部状态。通过两阶段训练，让代理学会“何时”以及“如何”使用这些外部支持。

*   **关键技术细节与流程**：
    1.  **统一Harness抽象与交互协议**：
        *   **BPE状态**：形式化地定义了Harness在工作区中呈现的状态：\( H_t = (B_t, P_t, E_t) \)。
        *   **Harness动作集（\( \mathcal{A}_{bpe} \)）**：定义了一组小型的元动作来覆盖主要的信息流：
            *   `track`: 从\( B_t \)读取任务相关的信念。
            *   `commit`: 向\( P_t \)写入子目标或执行更新。
            *   `recall`: 从\( E_t \)检索可复用知识。
            *   `note`: 记录新的洞察，供后续整合到\( E_t \)。
        *   **动作混合**：代理的策略在环境动作和Harness动作的联合空间（\( \mathcal{A} = \mathcal{A}_{env} \cup \mathcal{A}_{bpe} \)）中进行选择。由于两者消耗相同的交互步数预算，代理必须学习成本效益权衡。

    2.  **环境适配器（Environment Adapter）**：
        *   作为桥梁，连接特定领域的信号与通用的BPE接口。它处理环境观测，维护内部Harness存储，并将选定的视图渲染为\( (B_t, P_t, E_t) \)供策略使用。这使得内部实现是领域相关的，但代理-Harness协调层是共享且可训练的。

    3.  **两阶段成本感知训练**：
        *   **第一阶段：监督Harness微调（Supervised Harness Fine-Tuning, SFT）**：
            *   使用成功教师轨迹（Teacher Trajectories，由强模型生成）对基础LLM进行监督微调。
            *   **目的**：教会模型Harness动作空间（何时用`track`, `commit`, `recall`, `note`）的语义，以及如何从交互轨迹中构建有用的外部状态。
        *   **第二阶段：成本感知的GRPO优化**：
            *   使用**组相对策略优化（GRPO）** 算法，从SFT检查点开始进一步优化策略。
            *   **奖励函数（Reward Function）** 设计为综合性的：
                \( R(\tau) = R_{\text{succ}}(\tau) + \lambda_{\text{eff}} R_{\text{eff}}(\tau) + \lambda_{\text{div}}(u) R_{\text{div}}(\tau) - \lambda_{\text{spam}} R_{\text{spam}}(\tau) - \lambda_{\text{inv}} R_{\text{inv}}(\tau) \)
                *   \( R_{\text{succ}}(\tau) \): 任务成功奖励（主导信号）。
                *   \( R_{\text{eff}}(\tau) \): 效率奖励（成功基础上惩罚多余步数）。
                *   \( R_{\text{div}}(\tau) = \frac{|\{\text{verb}(a_t): a_t \in \tau\}|}{|\tau|} \): **动作多样性奖励**。其权重\( \lambda_{\text{div}}(u) \)采用余弦退火课程（Curriculum），鼓励早期探索Harness动作，后期则迫使策略精炼和专业化。
                *   \( R_{\text{spam}}, R_{\text{inv}} \): 惩罚无意义重复或格式错误的动作。
            *   **目的**：学习“何时”读、写、整合外部状态是有价值的，将Harness使用从提示时的脚手架转变为学习到的运行时策略。

### 7. 优点：方法或实验设计上的亮点

*   **统一抽象与可学习性**：将复杂的Harness工程问题统一为BPE抽象和四个简单的元动作，使其成为可优化策略的一部分，这是方法论上的核心亮点。
*   **成本感知的协调学习**：通过将Harness动作与环境动作置于同一奖励框架下，让模型自己学会成本效益权衡，而非依赖硬编码的调用规则，设计精巧。
*   **两阶段训练管线的设计**：SFT提供基础能力，GRPO进行效率与策略优化，分工明确，有效避免了RL训练的冷启动问题。
*   **深入的分析揭示新动态**：不仅报告了性能提升，还通过实验分析发现了“Harness退火”和“Harness进化”这两个新颖且有价值的训练动态，为理解代理-Harness协同优化提供了深刻的洞见。
*   **紧凑的动作空间**：仅需4个通用元动作，使得学习到的行为具备更好的可解释性和潜在的跨场景迁移能力。

### 8. 不足与局限：包括实验覆盖、偏差风险、应用限制等

*   **单一环境验证**：主要实验仅在ALFWorld这一个文本形式的具身环境上进行。虽然该环境具有代表性，但不足以证明方法在更复杂的环境（如需要视觉输入、更自由的世界模型）中的普适性。
*   **依赖强教师模型**：SFT阶段和外部经验库的整合（consolidation）都依赖Claude Opus等强模型，这会引入强模型自身的知识与偏见，并增加了系统的复杂性和成本。
*   **环境适配器仍需人工设计**：尽管Harness抽象是通用的，但将其具体落地（即实现环境适配器）到新环境仍需要大量领域专家知识，离完全自动化还有距离。BPE内部状态的格式和提取规则（如规则库的Belief Tracker）仍是手工定义的。
*   **动作空间特殊化的局限**：元动作`track[object]`、`commit[subgoal]`等依然预设了任务是具有子目标和对象搜索的结构。对于开放域对话或更自由形态的交互，该动作集的适用性有待探究。
*   **长期记忆的维护复杂度**：虽然论文展示了经验库的进化，但其整合、移除、遗忘机制依赖于额外的LLM调用和预设的容量限制，在高吞吐量、持续学习的实际部署中，其鲁棒性和扩展性可能需要更严格的验证。
