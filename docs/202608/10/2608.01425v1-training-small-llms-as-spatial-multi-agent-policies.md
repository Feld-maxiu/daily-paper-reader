## 摘要
基于多智能体强化学习训练基于LLM的多智能体系统正迅速获得关注，同时一系列并行研究认为这类系统应通过其行为而不仅仅是奖励来评判。我们在空间合作游戏中同时探讨这两个线索，其中被提示低级动作的小型冻结LLM完全失败，获得零奖励。在选项/半MDP框架的指导下——并且由于选项执行在智能体间是异步的，我们采用其在宏动作Dec-POMDPs中的多智能体扩展——我们为每个游戏配备一个符号化选项库：由符号规划器执行的带类型、状态可行、短时域行为。每个库由前沿编码模型根据游戏源代码起草；然后通过廉价的随机策略预热rollout机械地合成过滤每个菜单的可行性守卫——只有当守卫能解释重复的执行失败且不掩盖任何记录的成功时才被采用——因此没有守卫是手工编写、选择或基于奖励调整的。每个智能体的LLM充当其在选项上的策略，使用每个智能体私有的LoRA适配器，通过每个智能体变体的多智能体GRPO（PA-MAGRPO）训练；这使冻结的基础模型在三个游戏和四个小型骨干上从零奖励提升为胜任游戏。行为审计随后揭示奖励和合作分离：上升的奖励曲线可能仅仅意味着一个智能体学会了独自运行整个任务而其伙伴闲置——只有当任务需要时合作才会出现。因此仅凭奖励是合作的不可靠读数；行为评估必须与之并行。

## Abstract
Training LLM-based multi-agent systems with multi-agent reinforcement learning is rapidly gaining traction, and a parallel line of work argues that such systems should be judged by their behavior, not only their reward. We take up both threads in spatial cooperative games, where small frozen LLMs prompted with low-level actions fail outright, earning zero reward. Guided by the options/semi-MDP framework---and, because option execution is asynchronous across agents, its multi-agent extension in macro-action Dec-POMDPs---we equip each game with a library of symbolic \emph{options}: typed, state-feasible, short-horizon behaviors executed by a symbolic planner. Each library is drafted by a frontier coding model from the game's source code; the feasibility guards that filter each menu are then synthesized mechanically from cheap random-policy burn-in rollouts---a guard is adopted only if it explains repeated execution failures while hiding no logged success---so no guard is authored, selected, or reward-tuned by hand. Each agent's LLM acts as its policy over options, with a private per-agent LoRA adapter trained by a per-agent variant of multi-agent GRPO (PA-MAGRPO); this lifts frozen bases from zero reward to competent play across three games and four small backbones. Behavioral audits then reveal that reward and cooperation decouple: a rising reward curve may simply mean that one agent has learned to run the entire task alone while its partner idles---cooperation emerges only when the task makes it necessary. Reward alone is thus an unreliable readout of cooperation; behavioral evaluation must sit alongside it.

### 2. 论文提出的方法论

核心思想可以分解为三个组成部分：**符号化选项库与菜单接口**、**可行性守卫的自动合成**，以及**Per‑Agent LoRA + PA‑MAGRPO 训练**。

#### 2.1 符号化选项库与菜单接口
- 将智能体的动作空间从基础动作（例如 `move`, `fire_clean`）提升为**选项（options）**。每个选项具有：启动条件（`Iz`）、执行器（符号规划器）、终止条件。
- 选项由 Claude Opus 4.8 根据游戏源代码起草（唯一一次使用前沿模型），包含 **效应谓词**（delta 形式）来定义执行成功与否。
- 在每个决策时刻，系统根据当前状态和观察计算可行选项，并以菜单形式（打乱字母顺序）呈现给 LLM。LLM 只需输出选项字母，由符号规划器负责将选项展开为基础动作序列（如寻路、交互）。

这种设计使每个智能体面临的是**半马尔可夫决策过程（semi‑MDP）**，而团队层面则构成**宏动作 Dec‑POMDP**，因为选项在智能体间异步开始和结束。整个系统做到“LLM 决定做什么，符号规划器决定怎么做”。

#### 2.2 可行性守卫的自动合成
- 选项库的可行性检查代码（守卫）**完全通过算法合成**，无人为参与：
  1. **烧入阶段**：使用随机均匀策略执行大量 episode，记录每个选项执行的成功/失败（基于效应谓词或执行器错误，不基于奖励）。
  2. **守卫合成**：对于执行失败，提取出可解释失败的 conjunctions（基于可读的确定性特征，如“held=onion”，“pot state=full”）。一个守卫仅当其覆盖至少5次失败且**零次成功**时才被采用（纯度要求）。这是为了防止将合法执行也过滤掉，从而避免战略信息混入守卫集。
  3. 守卫数据存档，在菜单构建时自动应用；显式失败（如 `NoPath`）通过实时路径规划重新检查。
- 此外，通过**契约修复环**处理效应谓词的缺陷（如绝对量级 vs. delta 形式），确保守卫数据纯净。

#### 2.3 Per‑Agent LoRA 与 PA‑MAGRPO 训练
- **参数化**：使用一个共享的冻结 LLM 基础模型，每个智能体拥有**私有的 LoRA 适配器**。这允许不同智能体在训练中形成差异化策略，避免共享适配器因梯度平均而导致的模式坍缩。
- **训练算法**：PA‑MAGRPO（Per‑Agent Multi‑Agent Group Relative Policy Optimization）。
  - 每一轮收集 K 条联合 rollout，每条 rollout 得到团队总回报 R_k。
  - 在队列内标准化回报获得共享优势 ˆA_k,t。
  - 每个智能体使用该共享优势，在**自己的期权决策**上进行 PPO 风格的裁剪更新，并加入 KL 惩罚向参考策略。更新仅在选项边界处进行。
- 这种方法无需集中式 Critic，也无需为不同角色手工设计奖励，角色分化从相同的团队奖励中自然涌现。

整个方法的核心流程可概括为：
```
游戏代码 → 前沿模型起草选项模式 → 随机策略烧入 → 守卫合成 → 菜单接口 → PA‑MAGRPO 训练私有 LoRA
```

### 6. 论文的主要结论与发现

1. **方法有效性**：小型 LLM 可以通过选项抽象+私有适配器+PA‑MAGRPO 成功训练为空间合作策略。在三个游戏中，零奖励的冻结模型被提升到胜任的游戏水平（如 Cleanup 苹果 0→92.85，Overcooked AA 交付 0→6.21）。

2. **组件必要性**：
   - 移除选项菜单（原生动作 RL）导致零奖励，模型无法摆脱原始动作的先验坍缩。
   - 共享 LoRA 不能维持角色分化，仅限于对称任务（Harvest）可行，在需要角色分工的任务中表现差。
   - 复合 JSON 生成（无菜单过滤）不稳定，在困难游戏中难以训练。

3. **奖励与合作的分离现象**（三个方向）：
   - Cleanup：高奖励伴随着真正的角色分化（清洁者 vs. 食者），即合作涌现。
   - Overcooked AA：高奖励却由一人工作、另一人闲置产生，合作并未发生；而强制协调版本中交付才能证明合作。
   - Commons Harvest：树木存活率大幅提升（约束行为）而团队回报改善甚微——奖励几乎平坦却隐藏了有效的资源节制。

**结论**：团队奖励不能单独证明合作；行为评估（角色分化、协调行为、可持续性）必须与之并行。

### 8. 不足与局限

- **任务范围有限**：仅在三个特定的空间游戏上评估，且都源自 Melting Pot 或 Overcooked，未涉及更复杂的3D环境或非空间合作任务。

- **选项库需针对游戏设计**：流程虽然自动化，但每个游戏需要单独起草库，缺乏跨游戏或任务无关的选项发现机制。

- **只考虑合作设定**：未涉及竞争或混合动机场景；私人适配器设计可能不适用于对手建模。
- **训练超参数敏感**：虽然消融实验固定超参数，但文中承认超参数从小规模试运行得到，迁移到新任务可能需要重新调整。
